# ID задач Blueprint LLM

**Редакция:** 1, 03.11.2026. **План:** `43_План работ по Blueprint LLM.md`. **Полные записи:** [[43.2_Реестр задач Blueprint LLM]].

Это короткий индекс: его можно читать целиком для понимания сделанного и выбора следующего шага. Полный реестр по умолчанию целиком не читать. Описание задачи — примерно 15–20 слов; подробности, уточнения и доказательства находятся в записи по ID.

## Индекс

**Следующий свободный номер:** `BP-0003`. Это номер будущей записи, не назначенная задача. Технические TASK ID не переименовываются: например, запись `BP-0001` соответствует пакету `CODEX-WUA-BLUEPRINT-MVP-001`.

## Как раскрыть одну задачу

1. Найти ID в таблице и определить, нужны ли подробности для текущей работы.
2. Получить только запись между её точными маркерами. Номера строк — подсказка; устойчивый адрес — файл и ID.
3. Если нужен предыдущий связанный результат, сначала выбрать его ID из индекса; не загружать соседние записи автоматически.

Из корня проекта:

```powershell
python -B -X utf8 tools/read_task_record.py --registry "Документация/43.2_Реестр задач Blueprint LLM.md" --id BP-0001
```

Команда выводит путь, границы строк и только выбранную запись. При повторном ID, повреждённых маркерах или превышении ограничения вывода она отказывает, а не печатает весь файл. Если инструмент недоступен, найти точные маркеры и прочитать только соответствующий диапазон строк. Наличие адреса не расширяет права на чужие архивы.

Для восстановления контекста обычно достаточно индекса. Полные последние пять задач можно читать только по явной необходимости текущего поручения, выбрав до пяти ID и раскрывая каждую отдельно. Это исключение, а не обязательная загрузка при каждом входе.

## Как обновлять

Планировщик сохраняет поручение и фактический результат в №43.2, проверяет чтение записи по ID, затем добавляет или уточняет строку здесь и отметку в плане. ID выдаётся один раз по порядку. Новая самостоятельная задача получает следующий ID; уточнение прежней сохраняется в той же записи с датой и новой редакцией снимка.

До назначения будущая задача может присутствовать в рабочем плане без строки «выполнено». После назначения в индексе допускаются состояния «назначено» и «в работе». После сдачи — «сдано автором»; «принято» появляется только с предусмотренным вердиктом и адресом доказательства. Невыполненная часть остаётся явно открытой.

Правило и ответственность: №18 → `DOC-PLAN-TASK-INDEX-01@1`; памятка — общий №000; форма записи — №07. Большие отчёты остаются в `reports/<TASK-ID>/`. Этот индекс не заменяет общий №05/FOLLOWUP, независимые вердикты №06 или личные карточки исполнителей.

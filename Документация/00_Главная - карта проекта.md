# GigaChat Ultra Local Agent

GigaChat Ultra Local Agent — это локальная система, построенная вокруг GigaChat API, которая обеспечивает управляемую работу с контекстом, проектами (workspace) и историей чатов. Проект реализует подход, при котором пользователь сохраняет полный контроль над тем, что именно находится в активном контексте модели, а история и артефакты надёжно хранятся на диске.

## Текущий этап

Ближайшая крупная работа связана с построением полноценной системы проектов и чатов:

- разделение workspace и чатов;
- хранение истории чатов на диске;
- настоящий multi-turn контекст;
- управляемое сжатие контекста с сохранением оригиналов;
- переносимость запуска между машинами (относительные пути, авторазвёртка окружения);
- последующий переход на web UI без переписывания ядра.

Этот документ является центральной точкой навигации по всей проектной документации. Рекомендуется открывать папку «Документация» как отдельный Obsidian Vault для удобной работы со связями между документами.

## Актуальный статус реализации (по результатам TASK DOC-SYNC-01)

- **Workspace / Chat / RAW HISTORY**: реализованы переносимый `.ultra/`, постоянные `workspace_id` / `chat_id` / `message_id`, хранение RAW MESSAGE отдельными JSON, сохранение user RAW до API request и assistant RAW до UI success, persistent history, восстановление после restart.
- **Project Context**: общий для всех чатов WORKSPACE, загружается перед каждым RUN, редактор и история ревизий доступны из UI.
- **Active Chat Context**: выбранный chat_id реально передаётся модели вместе с PROJECT CONTEXT.
- **UI**: трёхколоночная компоновка (trace / chat+input / WORKSPACES-ЧАТЫ), создание/переименование Workspace и Chat, редактор PROJECT CONTEXT, предупреждение о необходимости restart при изменении runtime-файлов.
- **Safety / Verification**: READ/WRITE/DELETE scopes, VERIFY, server-side Verification Gate (python_compile, git_diff, git_status, ui_smoke_test), обязательный pre-RUN backup, namespace backup по workspace_id, lazy backup изменяемых/уделяемых файлов, отдельные RUN logs по workspace_id, настраиваемые backup/log paths вне Workspace.
- **Следующий функциональный рубеж**: 06.4 (RAW HISTORY vs WORKING/ACTIVE CONTEXT) → 06.5 (управляемое сжатие).

# GigaChat Ultra Local Agent

GigaChat Ultra Local Agent — локальная рабочая среда для работы с проектами, файлами, Workspace, Chat и долговременным контекстом.

**Текущий runtime:** `server.py` использует Model Registry и отдельные назначения моделей MAIN CHAT, COMPRESSOR и VERIFIER через GigaChat transport.

**Принятое архитектурное направление:** универсальный Agent Runtime, в котором LLM выбирается через MODEL ASSIGNMENT и MODEL REGISTRY. Мультимодельный фундамент реализован; универсальный Provider Adapter и Local Provider остаются будущими этапами.

Система развивается в сторону локального клиента уровня ChatGPT / Codex, где:

- проект и его данные остаются на диске пользователя;
- история Chat сохраняется между запусками;
- Project Context является общей памятью Workspace;
- сервер физически контролирует файловые действия модели;
- backup, trace и verification используются как независимые уровни защиты;
- RAW HISTORY сохраняется независимо от активной Working Representation и сжатия.

## Текущее состояние проекта

Работают несколько Workspace и Chat, persistent RAW HISTORY, общий Project Context и multi-turn Main Chat Context с активными RAW / SUMMARY представлениями. Удаление Chat как завершённая функция ещё отсутствует. Подробности идентичностей, хранения и сборки контекста — в `03_Чаты, проекты и контекст.md`; краткий статус runtime — в `01_Архитектура и текущее состояние.md`.

## Мультимодельная архитектура

Model Registry и назначения Main Chat, Compressor и Verifier реализованы для GigaChat. Универсальный Provider Adapter и Local Provider остаются будущими. Канонические роли, модельная изоляция и будущие расширения описаны в `11_Мультимодельная архитектура и назначение LLM.md`.

## Safety / Verification

Server проверяет permissions и scopes, создаёт обязательный backup и применяет deterministic Verification Gate. Для изменённого существующего Python-файла требуется `python_compile`, для `server.py` / `ultra_ui.py` дополнительно `ui_smoke_test`; `git_diff` / `git_status` — диагностика. Подробности и edge cases принадлежат `13_Архитектура оперативной верификации и контроля выполнения задач.md`.

---

## GUARD P1

Guard может остановить подозрительный tool action до исполнения; он дополняет permission и verification. Исторические тестовые сценарии и известное ограничение near-duplicate CREATE зафиксированы в `06_Журнал выполнения и отчёты.md`, текущая safety-архитектура — в `13_Архитектура оперативной верификации и контроля выполнения задач.md`.

---

## No-tool completion

Final Audit проверяет claim Executor по server-observed evidence и может отклонить ложное сообщение о выполненной mutation. `TOOLS = 0` само по себе не означает FAIL. Автоматический mutation-intent / Execution Consistency gate отключён; classifier остаётся диагностическим. Возможный отдельный TASK EXECUTION GATE / NO-TOOL STOP GUARD пока не реализован. Владелец подробного execution lifecycle — `13_Архитектура оперативной верификации и контроля выполнения задач.md`.

```text

```

- backup paths;
- log paths;

## Главный принцип проекта

```text
Пользователь ставит TASK.
        ↓
Модель предлагает действия.
        ↓
Permission Gate решает, разрешены ли они.
        ↓
GUARD может вмешаться в подозрительное поведение.
        ↓
Tool выполняет разрешённое действие.
        ↓
Backup страхует изменение.
        ↓
Verification Gate требует подтверждения результата.
        ↓
Trace показывает, что реально произошло.
        ↓
Git сохраняет проверенные контрольные точки.
```

Финальный текстовый отчёт модели никогда не должен считаться более надёжным источником, чем фактический trace и состояние файлов.

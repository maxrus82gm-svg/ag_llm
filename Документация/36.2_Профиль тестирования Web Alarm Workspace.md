## Открытые находки: НЕ растворять в PASS пилота

- **F1 / RC-5 Closeout:** доказан один pre-move `WinError 5` с сохранённой активной TASK. Но status write после move и `MOVED_STATUS_PENDING` требуют *отдельного* fresh-process recovery proof с independent raw oracle; простой FAIL/CloseoutError не равен REJECTED.
- **F2 / direct TaskStore.complete_task vs MutationExecutor:** зафиксирован raw `FileNotFoundError` при checkpoint/manifest snapshot после перемещения TASK. Отсутствие доказанного незаконного write ещё не гарантирует безопасный итог.
- **F3 / completion crash-race:** marker достижения crash phase, независимая диагностика перехвата отказов, fail-closed и restart recovery. Повторные 80-round PASS не устраняют исторический non-reproduced failure.

## Raw oracle для всех критичных гонок

```text
1. Брать PRE на quiescent fixture; отдельно actual bytes + expected model.
2. Явно отмечать reached phase/worker exit/lock ownership; no wall-clock proof.
3. После остановки собственных workers считывать:
   active/<task>, completed/<task>, task.json, operations/*.json,
   manifest/snapshot, events prefix, plan, receipt, workspace target bytes.
4. Уникальная TASK location, valid JSON/task identity/immutable hashes — MUST.
5. При completed + PLANNED (status-pending) отмечать состояние, НЕ PASS.
6. Затем — отдельный явно разрешённый recovery и fresh-process re-open,
   без второго physical apply / active resurrection.
7. FAIL: испорченные bytes, orphan/lost snapshot, illegal write либо
   receipt без требуемой authority, с неверной identity/POST или revision.
8. Receipt oracle задаётся ДО запуска по конкретному сценарию и PRE:
   - Read-only historical replay / запрет нового эффекта: ранее сохранённый
     receipt неизменен, нового receipt и нового physical apply не возникает.
   - Явно разрешённый RC-6 ADOPT: допустим НОВЫЙ receipt для уже совершённого
     physical effect, если есть принятый resolution (identity/action),
     актуальная revision/freshness, подтверждённые target POST bytes,
     правильные task/operation identity и нет второго physical apply.
     Проверять независимой expected model и raw evidence после recovery/re-open.
   - Нельзя принимать любой новый receipt без доказательств или превращать
     нарушение historical replay в законный ADOPT задним числом.
```

Production `ProjectionService` можно использовать как вторичное наблюдение, но **не** как единственное expected для проверки самого projection. Injection vs natural incident всегда подписывать отдельно.

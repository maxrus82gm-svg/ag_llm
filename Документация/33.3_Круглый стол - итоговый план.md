# 🔴 Круглый стол — итоговый план (33.3)

**Назначение:** универсальная постоянная оболочка для **одного итогового согласованного плана** после фактического участия хотя бы одного альтернативного планировщика или рецензента в 33.1/33.2. Не новая стадия вердикта и не разрешение выполнять код. **CURRENT: NOT_REQUIRED / EMPTY** — по RT-002 альтернативные слоты пока NOT_REQUESTED, поэтому документ **не заполнен**.

**Навигация Obsidian:** [[33_Круглый стол - план исполнения|33 — исходный план]]. Правила, источники альтернатив 33.1/33.2 и архивные locators здесь указаны текстом (без дополнительных Graph-связей).

## Постоянная инструкция — выбрать один-единственный источник финального плана

1. **Нет фактического альтернативного участия.** Если обе оболочки 33.1 и 33.2 `NOT_REQUESTED` либо их назначения закончились `CANCELLED` без сданных результатов (при этом пользователь явно закрыл группу), **33 остаётся единственным итоговым планом**. 33.3 остаётся `NOT_REQUIRED / EMPTY`; не копировать сюда 33, не заполнять таблицы «для порядка» и не утверждать 33.3.
2. **Альтернатива назначена, ещё не сдана.** Пока хотя бы один включённый участник находится в `ASSIGNED`/`DRAFT`/`BLOCKED`, выбор итогового плана ожидает его `SUBMITTED` либо отдельного решения пользователя об отмене/изменении группы. 33.3 остаётся `WAITING_INPUT`, **без содержательного итогового плана**.
3. **Альтернативное участие подтверждено.** Как только хотя бы один назначенный вариант/REVIEW в 33.1 или 33.2 **сдан и запечатан** (`SUBMITTED`) и пользователь/координатор по установленным правилам разрешил раскрытие и сравнение, **итог оформляется исключительно в 33.3**, даже если альтернатива только одна, даже если её предложения все отклонены и итог совпал с базовым 33. В этом случае 33 **не** превращается в финальный и сохраняет первоначальную независимую редакцию.
4. Результат `COMPARED` и решение об учёте альтернатив не означают автоматического USER PLAN APPROVAL. При наличии альтернатив запрещено утверждать/передавать 33 как финальный вместо 33.3. Если gate отсутствует, файл не заполнять содержательной финальной редакцией: показать `BLOCKED` и точное условие возобновления.
5. **План только по отдельному поручению редактору итогового документа.** Наличие файла, альтернативы или submission само по себе не назначает редактора и не даёт ему write permissions. Координатор фиксирует состав источников и разрешённую стадию; редактор заполняет только оперативную часть ниже.
6. По `rule-ref:RT-FINAL-01@1` из 28 и `rule-ref:PLAN-RECONCILE-01@2`, `PLAN-APPROVAL-01@2` из 33 извлечь действующие нормативные определения с зависимостями; применить `DOC-GIT-01@1`, `DOC-VERSION-01@1`, `DOC-CHANGE-01@1` из 18. Точный `rule_set_ref` и допустимый доказательный input сохраняются в записи подготовки.
7. **Печать и внешние approvals:** до пользовательского PLAN APPROVAL сохранить точные bytes итогового 33.3, SHA-256 и immutable locator вне запечатанного текста (в оперативном реестре 28; затем locator в архиве 35). Любая новая редакция требует нового подтверждения. Только после личного PLAN APPROVAL и verified handoff в профильный план можно создавать отдельные implementation TASK. Архивирование и очистка только по `RT-CLEANUP-01@2` и отдельному разрешению пользователя.

### Обязательная структура при активации 33.3

- **RT / assignment:** RT-ID, назначенный составитель, решение о ветке (альтернативы включены), статус, scope и дата.
- **Frozen inputs:** approved Decision Record 32, SHA-256 синтеза 31, версия общего Planning Input Manifest 28, версия исходного 33 (с original seal), exact `SUBMITTED` refs альтернатив/REVIEW 33.1/33.2, known exposure и применимые версии правил.
- **Таблица сверки:** `source + exact revision → предложение/findings → принято/модифицировано/отклонено/отложено → evidence/rationale → пункт итогового плана`. Существенное отклонение имеет объяснение. Согласие моделей не подменяет проверку.
- **Один итоговый план:** TASK graph, verdict V→TASK, зависимости, boundaries, исполнители как предложения, scope и exclusions, offline/visual/user acceptance, порядок согласованного handoff. Все неразрешённые противоречия, изменившиеся предпосылки и риск неправильного утверждения отмечаются как BLOCKED/OPEN.
- **Gate:** завершённый reveal всей выбранной группы, архивируемые исходные редакции, consistency check с вердиктом, внешняя печать итогового файла, затем **отдельный USER PLAN APPROVAL конкретной версии**. Нельзя молча «улучшить» verdict.
- **Проверка перед очисткой:** 33/33.1/33.2/33.3, reasons, approvals, существенное raw evidence и архивные locators должны быть восстановимы до разрешённого сброса.

*(ULTRA FUTURE NOTE: при создании серверного Круглого стола Ultra этот документ соответствует **условной финальной сущности**, создаваемой только после действительного альтернативного SUBMITTED и разрешённого сравнения; Server должен проверять источники и полномочия, а не доверять одному лишь факту существования шаблона.)*

# Задачи для агента

**Назначение:** оперативный handoff-документ проекта. Это краеугольная точка непрерывности между Chat / Agent / Remote-сессиями: здесь должно быть видно, что уже доказано, что нельзя повторять вслепую и что агент делает следующим.

**Канонический вход:** сначала открыть `08_Старт.md`; уже внутри Start-маршрута этот `000` обязателен до начала любой значимой TASK. Затем читать `18_Регламент сопровождения документации.md`, `01_Архитектура и текущее состояние.md` и только нужный профиль активной ветки.

**Обязательное правило:** если в блоке «Текущая задача» есть запись, сначала сверить её с фактическим состоянием проекта, recovery-журналом и live evidence. Не повторять незавершённое действие только потому, что Chat потерял контекст.

**Правило инженерной самостоятельности:** границы TASK ограничивают самовольные изменения, а не мышление. Для значимой технической работы обязательный чек-лист является минимумом: перед `RESULT READY` исполнитель должен самостоятельно выполнить adversarial pass, проверить релевантные неперечисленные edge cases и не скрывать находки. Внутри scope найденное можно исправлять с regression test; вне scope — только evidence + `FINDING / PROPOSAL / BLOCKER`, без самовольной смены этапа. Полное правило — в `18_Регламент сопровождения документации.md`.

1. Этот файл — **глобальный project-level router**, а не персональная карточка конкретного исполнителя. БЛОК 1 показывает текущий проектный NEXT, назначенного исполнителя и route на его персональную task-card.

После фактического выполнения исполнитель сам делает безопасную ротацию персональной карточки: **сначала** полная постановка → БЛОК 2, **затем** factual closeout → БЛОК 3 (`RESULT READY / AWAITING INDEPENDENT VERIFICATION`), **только потом** персональный БЛОК 1 → `ОЖИДАНИЕ НОВОЙ ЗАДАЧИ`.
3. Если сохранность БЛОКОВ 2–3 не доказана из-за сбоя/обрыва, персональный БЛОК 1 не очищать и не повторять ротацию вслепую; сначала reconciliation фактического файла. Незавершённую/приостановленную TASK не выдавать за выполненную.

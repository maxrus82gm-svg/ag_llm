**Ближайшая цель: работающая пользовательская переписка в STANDARD и проверка GigaChat через EVM, затем согласованный UX окон.** STANDARD — производственный обычный режим, а не временная демоверсия. ## Наблюдения владельца 17.11 — не выдавать за инженерную независимую приёмку

- В штатном STANDARD пользователь видит **запрет отправки**: «Отправка GigaChat закрыта до проверки параметров модели и защит. История и настройки доступны»; физической новой переписки не получилось. В `web_alarm/ui.py` это строка при `turn_test.available=false`; в `ordinary_provider.py` REAL требует отдельной действующей `ProviderSession`. **Точный runtime-код причины сегодняшнего отказа не установлен**, не объявлять истечение 24 часов доказанным без readback активного сервера.
- EVM «Проверить чат» в пользовательской попытке не отправил сообщение; UI содержит «в этой версии оно не отправляется». Checker требует заранее подтверждённую REAL session. Сообщение checker «Сначала явно подключите GigaChat в Ultra Chat» уже противоречит управлению из EVM. На реальном API проверить, что успешный/ошибочный Ordinary Turn действительно меняет индикатор, пока НЕ ПРОВЕРЕНО.
- Внутренние копии карточек EVM пользователь свободно двигает **только внутри браузерной страницы**, не на второй монитор; отдельное «↗ Внешнее окно» создаёт другой browser popup и может перемещаться на другой монитор. Текущие **два режима пользователь считает лишними**; желает один вид карточки, допускающий перенос на другой экран, изменение размеров, необязательный topmost. Важно: DOM-панель принципиально не может выходить за границы окна браузера; дизайнерское объединение должно переиспользовать системное окно/браузерный API без ложных обещаний и без скрытого нового менеджера. Конкретный образец интерфейса пользователь ещё готовит — не выдавать UX решение за утверждённое.
- Работа «Ножниц» и охват двух мониторов в Windows вызвали подозрения; после закрытия Web Alarm пользователь также сообщил проблему с обнаружением второго экрана. **Связь с PiP/Web Alarm не доказана**.

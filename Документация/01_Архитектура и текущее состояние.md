# Архитектура и текущее состояние GigaChat Ultra Local Agent

## Общая схема

На данный момент GigaChat Ultra Local Agent представляет собой локальное Python-приложение, состоящее из нескольких основных компонентов:

- **server.py** — backend-сервер, отвечающий за взаимодействие с GigaChat API, обработку запросов и работу с файловой системой через file-agent tools. Реализует Workspace storage, Project Context, Active Chat Context, обязательный pre-RUN backup, Verification Gate и server-side ограничения.
- **ultra_ui.py** — графический интерфейс на Tkinter, обеспечивающий взаимодействие пользователя с системой. Трёхколоночная компоновка (trace / chat+input / WORKSPACES-ЧАТЫ), создание/переименование Workspace и Chat, редактор PROJECT CONTEXT, предупреждение о необходимости restart при изменении runtime-файлов.
- **context_storage.py** — единый API хранения: рабочие пространства (.ultra/workspace.json), проектный контекст (.ultra/project_context.md), история версий контекста, каталоги чатов/мессаджей со строгими ID-правилами, атомарная запись JSON/text, лимиты размеров, миграции схемы. Используется UI и сервером для консистентного доступа к данным.
- **workspace_runtime_settings.py** — настройки runtime Workspace (пути backup/log, изоляция вне Workspace).
- **ui_state.py** — persistent UI state (геометрия, тема, цвета, layout, registry Workspace).
- **Start_Ultra.cmd** — Windows-скрипт для удобного старта системы.
- **GigaChat API** — внешний API, используемый для генерации ответов.
- **file-agent tools** — набор инструментов для работы с файловой системой (чтение, запись, листинг).
- **workspace** — текущая рабочая директория проекта, с которой работает агент.
- **trace/event subsystem** — подсистема логирования и трассировки действий.
- **logs/runs** — директории для хранения журналов и результатов запусков.
- **runtime change warning** — механизм предупреждения об изменениях в runtime-файлах.

## Что уже работает

- Запуск локального сервера и UI.
- Взаимодействие с GigaChat API.
- Базовые file-agent операции (чтение, запись, листинг).
- Система логирования и трассировки (trace).
- Механизм предупреждения об изменениях в runtime-файлах.
- Sidebar лога в UI.
- Успешные диагностические запуски.
- Автономный режим работы (standalone Ultra).
- Автоматическая загрузка обязательного регламента Ultra в system prompt каждого run.
- **Workspace storage**: переносимый `.ultra/`, постоянные `workspace_id`, `chat_id`, `message_id`.
- **Persistent RAW HISTORY**: отдельные JSON-файлы, сохранение user RAW до API request и assistant RAW до UI success, восстановление после restart.
- **Project Context**: общий для всех чатов WORKSPACE, загружается перед каждым RUN, редактор и история ревизий.
- **Active Chat Context**: выбранный chat_id реально передаётся модели вместе с PROJECT CONTEXT.
- **Workspace / Chat UI**: создание, переключение, переименование Workspace и Chat, изоляция выбранного Chat.
- **SAFE scopes**: READ/WRITE/DELETE области, VERIFY, server-side Verification Gate.
- **Backup**: обязательный pre-RUN snapshot `.ultra`, namespace по workspace_id, lazy backup изменяемых/уделяемых файлов.
- **RUN logs**: отдельные логи по workspace_id, настраиваемые backup/log пути вне Workspace.

## Что пока НЕ реализовано

- **MESSAGE SUMMARY**: отсутствует интерфейс и логика для управляемого пользователем сжатия фрагментов чата.
- **WORKING REPRESENTATION**: нет отдельной сущности состояния RAW/SUMMARY и token accounting.
- **Управляемое сжатие контекста**: отсутствует интерфейс и логика сжатия с сохранением оригиналов.
- **Переносимость между машинами**: Start_Ultra.cmd и окружение работают относительно директории, но автоматическая развёртка .venv/dependencies не реализована.
- **Web UI**: интерфейс реализован на Tkinter, браузерного интерфейса нет.

## Архитектурные принципы

- Ядро (server.py) и UI (ultra_ui.py) разделены.
- Все операции с файловой системой проходят через контролируемые инструменты.
- История действий фиксируется в trace.
- Изменения runtime-файлов требуют перезапуска и сопровождаются предупреждением.
- Документация и реестр задач ведутся отдельно от кода.
- Обязательный регламент Ultra хранится как Markdown и автоматически загружается в system prompt при каждом запуске run_agent_task; отсутствие регламента блокирует запуск.
- **.ultra защищена**: обычные file tools не могут напрямую изменять служебное хранилище; доступ только через Context Storage API.
- **Verification Gate**: после последней записи/удаления сервер физически блокирует SUCCESS до выполнения git_diff, git_status и, при необходимости, python_compile/ui_smoke_test.

## Текущие ограничения

- Контекст модели соответствует полной истории чата и PROJECT CONTEXT, но WORKING REPRESENTATION и SUMMARY ещё не реализованы.
- Нет надёжного автоматического сжатия контекста при приближении к лимиту.
- Запуск не полностью автоматизирован для переносимости (отсутствует авто-.venv/requirements).
- Web UI не реализован.

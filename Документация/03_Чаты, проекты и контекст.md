# Чаты, проекты и контекст в GigaChat Ultra Local Agent

Этот документ описывает фактическую модель организации работы с проектами, чатами и контекстом.

## Иерархия: WORKSPACE → CHAT → CONTEXT

```
WORKSPACE
    ├── PROJECT CONTEXT (общий для всех чатов)
    └── CHAT
        ├── RAW HISTORY (msg_*.json)
        └── (в будущем) MESSAGE SUMMARY
```

## Workspace (Проект)

- Workspace — это корневая директория, с которой работает агент.
- Один workspace может содержать множество независимых чатов.
- Workspace определяет область видимости файлов и артефактов.
- Внутри workspace создаётся служебная директория `.ultra/` с переносимым состоянием.
- Переключение workspace поддерживается через UI (список, создание, подключение, переименование, удаление из registry).

## Chat (Сеанс)

Каждый чат имеет:
- **chat_id**: постоянный уникальный ID (chat_<uuid>).
- **title**: пользовательское или сгенерированное имя.
- **created_at / updated_at**: даты.
- **RAW HISTORY**: полная persistent history на диске в `.ultra/chats/chat_<id>/messages/msg_<id>.json`.
- **ACTIVE CONTEXT**: управляемый набор фрагментов, передаваемых в модель.
- **метаданные**: хранятся в `.ultra/chats/chat_<id>/metadata.json`.

### Ключевые правила чатов

1. **Независимость контекстов**
   Переключение между чатами не смешивает активный контекст модели. Каждый чат имеет свою изолированную историю и контекст.

2. **Новый чат**
   Создание нового чата:
   - создаёт новую директорию и metadata.json;
   - НЕ меняет текущий workspace;
   - очищает активный контекст разговора.

3. **Разделение истории и контекста**
   - **История для UI** — полная хронология всех сообщений, сохраняется на диске целиком.
   - **Active model context** — то, что реально передаётся в GigaChat API. Это управляемый набор фрагментов.
   - Эти понятия НЕ тождественны.

## Persistent History (Постоянная история)

- Полная история каждого чата хранится на диске в структурированном виде:
  ```
  .ultra/
      chats/
          chat_<id>/
              metadata.json
              messages/
                  msg_<uuid>.json
              summaries/ (зарезервировано)
  ```
- Каждое сообщение имеет уникальный ID и сохраняется в исходном виде.
- История не теряется между сессиями.
- UI отображает сохранённые чаты после перезапуска.

## Active Model Context (Активный контекст модели)

Активный контекст — это не вся история чата, а управляемая комбинация:
- свежих несжатых сообщений;
- (в будущем) сжатых старых фрагментов (summaries);
- PROJECT CONTEXT текущего workspace;
- текущего пользовательского запроса.

### Механизм сжатия контекста

Детальная архитектура описана в документе «Архитектурное решение - управляемое сжатие контекста».

Кратко (статус: НЕ РЕАЛИЗОВАНО):
1. Пользователь выбирает объёмный фрагмент истории.
2. Создаётся сжатая версия (summary) с сохранением критически важной информации.
3. В активный контекст вместо оригинала помещается summary.
4. Оригинал остаётся на диске и доступен для восстановления.
5. Пользователь может редактировать summary вручную.

### Доступные действия с фрагментами (план)

Для каждого фрагмента (сообщения или группы сообщений):
- **Сжать** — создать summary.
- **Показать оригинал** — просмотреть исходный текст.
- **Развернуть** — вернуть оригинал в активный контекст вместо summary.
- **Пересжать подробнее/короче** — создать новую выжимку.
- **Редактировать summary** — ручное изменение сжатой версии.

## Требования к реализации

### TASK 06.1 — Модель данных чатов и хранение
- Определена структура директорий.
- Реализовано сохранение истории на диск.
- Создан API для работы с чатами (context_storage.py).
- **Статус: ГОТОВО**

### TASK 06.2 — Навигация по чатам
- UI для списка чатов.
- Переключение между чатами.
- Создание/переименование.
- **Удаление Chat: НЕ РЕАЛИЗОВАНО** (требуется отдельная реализация).
- **Статус: В РАБОТЕ**

### TASK 06.3 — Настоящий multi-turn context
- Контекст модели соответствует истории чата.
- Устранено расхождение между UI и API контекстом.
- **Статус: ГОТОВО**

### TASK 06.4 — Разделение raw history и active context
- Явное разделение полной истории и передаваемого контекста.
- Механизм учёта размера контекста.
- **Статус: В РАБОТЕ** (RAW HISTORY есть, WORKING REPRESENTATION/SUMMARY отсутствуют).

### TASK 06.5 — Управляемое сжатие
- Реализация интерфейса сжатия.
- Сохранение оригиналов.
- Редактирование summary.
- **Статус: ЗАПЛАНИРОВАНО**

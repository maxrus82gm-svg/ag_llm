# Круглый стол — вердикт и реестр решений

**Назначение:** короткий decision-ready вердикт по текущему вопросу Круглого стола для человека, фиксация USER APPROVAL и реестр текущего RT; краткая постоянная история находится в 35. Протокол и карточка вопроса — `28_Круглый стол - протокол и текущий вопрос`.

## Постоянная инструкция

[[35_Круглый стол - краткая история]]

**Входы:** [[31_Круглый стол - синтез и разногласия]] с пройденным representation check; карточка вопроса в `28`.

**Выход:** вердикт по пунктам → USER APPROVAL → Decision Record в реестре ниже.

**Состояния пункта решения:**
- **ВНЕСТИ** — решение утверждено для переноса в соответствующие документы и/или код;
- **НЕ ВНОСИТЬ** — решение отклонено;
- **ОТЛОЖИТЬ** — решение пока не готово к переносу;
- **ПЕРЕРАБОТАТЬ** — требуется новый цикл анализа: новый `RT-xxx` со ссылкой на родительский.

**Критическое правило:** если для пункта нет утверждённого пользователем состояния ВНЕСТИ, **никакие изменения канонической документации или runtime на его основании не выполняются**. Сам факт появления аналитики, синтеза или проекта вердикта не меняет `01` и профильные документы.

**После утверждения:** approved verdict передаётся в [[33_Круглый стол - план исполнения]]. Там формируется post-round execution plan с TASK graph, зависимостями, scope и acceptance. До отдельного USER PLAN REVIEW / PLAN APPROVAL этот план не переносится в профильные документы и execution не начинается. После PLAN APPROVAL план передаётся в канонический профильный implementation plan, и только затем создаются отдельные исполнительные TASK.

**Закрытие:** Круглый стол закрыт после USER APPROVAL и записи Decision Record. Planning в `33` и последующие исполнительные TASK живут дальше независимо и не переоткрывают Круглый стол.

**Разрешено:**
- формулировать вердикт строго на основе `31`;
- держать оперативный вердикт коротким — на одну-две страницы.

**Запрещено:**
- добавлять пункты, которых нет в `31`, без явной пометки;
- объединять разные решения в один пункт;
- фиксировать USER APPROVAL от имени пользователя;
- удалять записи постоянного архива 35 и очищать текущий RT до handoff.

**Шаблон вердикта:**

```text
### RT-xxx — вердикт
Основание: 31 (дата / commit)

Пункты решения:
№ | Что предлагается | Куда внести | Критерий приёмки | Предлагаемое состояние

Не принято:
Не определено (unresolved):
Предпосылки для проверки дрейфа исполнительной TASK:

USER APPROVAL
Дата:
Утверждённые пункты и итоговые состояния:
Версия / hash вердикта:
Execution plan / package:
```

**Правила очистки:** оперативная часть между `RT:BEGIN` и `RT:END` очищается только после записи Decision Record. Реестр текущего RT можно очистить после USER APPROVAL, проверенного handoff и записи краткого итога в постоянный архив 35.

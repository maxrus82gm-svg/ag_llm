1. **Постоянный канал.** ChatGPT самостоятельно читает реальный GitHub HEAD/branch/diff, код, отчёты и Actions. Адресные утверждённые пользователем изменения в своей зоне ответственности публикует **в `GPT`**, не в `main`. Это постоянное разрешение на использование ветки, а не право расширять TASK или произвольно менять runtime/production: инженерные правки кода, постоянных тестов и CI требуют разрешённого предметного scope; общая документация остаётся ответственностью ChatGPT.
2. **Безопасность ветки.** Перед записью проверить `main` и `GPT` HEAD, compare и пересечения с чужими TASK. Если GPT отстаёт, безопасная синхронизация возможна после доказательства отсутствия несогласованных собственных коммитов/конфликтов; в ином случае необходим reconciliation. Атомарно публиковать только целевые файлы, соблюдать DOC-COMMIT-01. Без отдельного нового USER GO не делать прямых записей в `main`, merge, force-push, rebase, reset, удаление веток или переписывание истории.

Для каждого прогона сверять точные HEAD SHA, набор тестов, PASS/FAIL/ERROR/SKIP, isolation, evidence и настоящий run ID. Нельзя выдавать старый/чужой run за новый, считать CI запущенным без факта или заменять отсутствующий инструмент фиктивной командой.

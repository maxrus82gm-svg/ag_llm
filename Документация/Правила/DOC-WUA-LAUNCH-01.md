## DOC-WUA-LAUNCH-01 — Два постоянных запуска Web Alarm Ultra


**Обязательно для координатора, Codex/Claude и каждого нового обычного WEB-чата.** В корне проекта для пользовательского **Web Alarm Ultra** есть **ровно две постоянные точки входа**:

1. **`Start_WebAlarm_Standard.cmd` — STANDARD:** существующий `web_alarm.launcher --standard`, обычное постоянное хранилище, штатный зелёный статус. Не читает тестовый профиль ради выбора режима и не должен молча открывать пустой/другой root; один цвет не доказывает независимую приёмку.
2. **`Start_WebAlarm_Test.cmd` — TEST:** тот же launcher с `web_alarm/launch_test_config.json` и `--require-test`. Текущий профиль — Stage 5 OFFLINE, браузер и fake LLM, одноразовое хранилище. Красное предупреждение TEST с целью и конфигурацией обязательно. Отсутствующая/повреждённая/standard-конфигурация должна завершаться отказом **fail-closed**, без перехода на STANDARD.
3. **Постоянство:** последующие этапы меняют только внутреннюю конфигурацию/реализацию, а не имена двух CMD и Windows-ярлыки. Ярлыки можно копировать в любое место. Не создавать дополнительный пользовательский BAT/CMD или серверную копию для нового этапа. STANDARD и TEST могут работать одновременно; конкретные localhost-порты не являются константами.
4. **Изоляция:** разные HTTP-адреса и пустой TEST-экран не доказывают изоляции storage. TEST не должен читать/изменять рабочие Workspace, TASK, историю, секреты, живые/оплачиваемые API и root без отдельного USER GO. Не менять Windows rights, Host/Origin/token, backup/rollback или переносить реальные данные ради теста. Для каждого этапа проверять target/root, отказ на плохом профиле, cleanup и отсутствие влияния на STANDARD; при сбое — блокировка, не автоматический fallback.
5. **Завершение:** TEST останавливается и очищает свои временные данные в соответствии с конкретным профилем; закрытие браузерной вкладки само по себе сервер не останавливает. Возвращать единый BAT в STANDARD **больше не требуется**, поскольку два CMD независимы по режиму. Если STANDARD перестал попадать в штатный root — `LAUNCHER_STANDARD_BLOCKED`, самостоятельное восстановление данных запрещено до проверки.
6. **Старые/отдельные:** `Start_WebAlarm.bat` стал пустым до создания двух CMD, впервые появился пустым в опубликованном №531; происхождение UNKNOWN. Два CMD его не вызывают, **автоматически не восстанавливать**. `Start_WebAlarm_Demo.cmd` запускает `wa4o_ui_launcher.py`/`wa4o_ui_demo.py` — отдельный старый WA4-O стенд с синтетическими временными задачами; это **не** актуальный TEST. Не рекомендовать как пользовательскую точку; удалить после dependency review и отдельного разрешённого изменения, без побочного удаления используемых тестов. `Start_Ultra.cmd` запускает `ultra_ui.py` (Tkinter), сохранить как отдельный замороженный интерфейс, не считать третьим пользовательским Web Alarm.
7. **Учёт:** перед технической TASK сверять `STANDARD target/root`, `TEST profile/root`, красную/зелёную маркировку, fail-closed, cleanup, отсутствие пересечения с production; отмечать честные `NOT RUN` и OPEN. USER GUI smoke 07.11 подтвердил параллельное открытие STANDARD с историей и пустого Stage5 TEST, но не полную независимую storage/Chromium регрессию.

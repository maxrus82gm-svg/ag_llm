**Обязательно для координатора, Codex/Claude и каждого нового обычного WEB-чата.** В корне проекта для пользовательского **Web Alarm Ultra** есть **ровно две постоянные точки входа**:

1. **`Start_WebAlarm_Standard.cmd` — STANDARD:** существующий `web_alarm.launcher --standard`, обычное постоянное хранилище, штатный зелёный статус. Не читает тестовый профиль ради выбора режима и не должен молча открывать пустой/другой root; один цвет не доказывает независимую приёмку.
2. **`Start_WebAlarm_Test.cmd` — TEST:** тот же launcher с `web_alarm/launch_test_config.json` и `--require-test`. Текущий профиль — Stage 5 OFFLINE, браузер и fake LLM, одноразовое хранилище. Красное предупреждение TEST с целью и конфигурацией обязательно. Отсутствующая/повреждённая/standard-конфигурация должна завершаться отказом **fail-closed**, без перехода на STANDARD.
3. **Постоянство:** последующие этапы меняют только внутреннюю конфигурацию/реализацию, а не имена двух CMD и Windows-ярлыки. Ярлыки можно копировать в любое место. Не создавать дополнительный пользовательский BAT/CMD или серверную копию для нового этапа. STANDARD и TEST могут работать одновременно; конкретные localhost-порты не являются константами.
4. **Изоляция:** разные HTTP-адреса и пустой TEST-экран не доказывают изоляции storage. TEST не должен читать/изменять рабочие Workspace, TASK, историю, секреты, живые/оплачиваемые API и root без отдельного USER GO. Не менять Windows rights, Host/Origin/token, backup/rollback или переносить реальные данные ради теста. Для каждого этапа проверять target/root, отказ на плохом профиле, cleanup и отсутствие влияния на STANDARD; при сбое — блокировка, не автоматический fallback.
5. **Завершение:** TEST останавливается и очищает свои временные данные в соответствии с конкретным профилем; закрытие браузерной вкладки само по себе сервер не останавливает. Возвращать единый BAT в STANDARD **больше не требуется**, поскольку два CMD независимы по режиму. Если STANDARD перестал попадать в штатный root — `LAUNCHER_STANDARD_BLOCKED`, самостоятельное восстановление данных запрещено до проверки.
6. **Старые/отдельные:** `Start_WebAlarm.bat` стал пустым до создания двух CMD, впервые появился пустым в опубликованном №531; происхождение UNKNOWN. Два CMD его не вызывают, **автоматически не восстанавливать**. `Start_WebAlarm_Demo.cmd` запускает `wa4o_ui_launcher.py`/`wa4o_ui_demo.py` — отдельный старый WA4-O стенд с синтетическими временными задачами; это **не** актуальный TEST. Не рекомендовать как пользовательскую точку; удалить после dependency review и отдельного разрешённого изменения, без побочного удаления используемых тестов. `Start_Ultra.cmd` запускает `ultra_ui.py` (Tkinter), сохранить как отдельный замороженный интерфейс, не считать третьим пользовательским Web Alarm.

## USER GO 16.11.2026 — связь ярлыков, режимов и Git-веток

**Неперемещаемые пользовательские точки входа:** сохранять имена, назначение и существующие Windows-ярлыки `Start_WebAlarm_Standard.cmd` (обычная текущая рабочая версия) и `Start_WebAlarm_Test.cmd` (изолированная тестовая оболочка). Не требовать от владельца новых ярлыков, перемещения каталога проекта или ручного выбора ветки для запуска. Новые этапы адаптировать к этим точкам входа, а не наоборот. Не создавать автоматическое переключение Git-веток из CMD.

**Разделять Git и режим:** `main` — опубликованная пользователем принятая версия; `GPT` — ветка подготовки/проверки ChatGPT, временные `review/*` — вспомогательные ветки. Пользовательский TEST — это режим запуска/изолированное хранилище, **не** Git-ветка с именем `test`. Оба постоянных CMD запускают код из своей физической папки: если переключить общий checkout на `GPT`/review, STANDARD тоже получит экспериментальные исходники. Поэтому не переключать пользовательский рабочий каталог, обслуживающий STANDARD, на непринятую ветку ради тестирования.

**Маршрут изменения:** готовить и коммитить в `GPT` по `DOC-COMMIT-01`; проверять исходный SHA в GitHub Actions/отдельном изолированном checkout, физический GUI — через утверждённый TEST-профиль со своими данными. Не подменять STD/TEST ярлыки и не переписывать действующий `main`. Если текущий TEST-профиль не способен проверить новый код без смены общего checkout, это отдельная техническая задача на безопасную маршрутизацию; **не** обходить её запуском эксперимента через STANDARD. Только после достаточных PASS и явного решения пользователя о публикации — merge `GPT` в `main` пользователем и обычное обновление его рабочего каталога `main`. GitHub push сам по себе не обновляет локальный проект.

**Поведение при обычном запуске:** STANDARD сразу открывает обычную текущую оболочку и сохранённые пользовательские данные; не заставляет выбирать Workspace, LIVE-сеанс или модель ради просмотра/обычного запуска. TEST открывает только свою тестовую оболочку, без принудительных LIVE-подтверждений, реальных/платных вызовов или доступа к данным STANDARD. Реальные запросы могут разрешаться только отдельным явным действием владельца в специально проверенном режиме, с обязательными границами и учётом. Внедрение этого UX не считается завершённым одной записью документа.

**Текущее техническое расхождение (OPEN на 16.11.2026):** в `GPT` у `web_alarm.launcher --standard` ещё вызывается `offer_standard_live` при интерактивном запуске с доступными credentials; это может показывать предложение `LIVE 12` в STANDARD, хотя новое пользовательское требование — не показывать его при обычном старте. TEST пока остаётся утверждённым OFFLINE-fixture, а не автоматическим запуском произвольного `GPT`-кода. До отдельного исправления и независимых тестов **не объявлять новый контракт реализованным и не рекомендовать merge `GPT` как полностью соответствующий этому UX**. Существующие истории/Workspace не удалять и не мигрировать автоматически.

**Контроль перед каждым handoff:** подтвердить два неизменных CMD/ярлыка, фактическую ветку и HEAD локального рабочего каталога, STD root и TEST temp-root, отсутствие неожиданных LIVE-вопросов/платных отправок, результаты независимых тестов и границы NOT RUN. Временные review-ветки удалять только после проверки, что нужные исходники/доказательства вошли в постоянную ветку; `GPT`/`main` не удалять.

Каноническая пользовательская инструкция — `WEB_ALARM_START.md`. Это не разрешение на технические изменения вне назначенного scope.

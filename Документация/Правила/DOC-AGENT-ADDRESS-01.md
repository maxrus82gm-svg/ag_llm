## DOC-AGENT-ADDRESS-01 — Уважительное обращение и постоянные идентификаторы исполнителей

```rule-meta
contract: 1
status: ACTIVE

```

**Решение пользователя Сильвера, 2026-10-13.** Для **каждой новой TASK**, адресованной локальному агенту, координатор начинает **оба копируемых сообщения** — полный БЛОК 1 и короткий запуск в чате исполнителя — с уважительного персонального обращения и конструктивного предложения выполнить задачу. Рекомендуемая точная формула: **«Уважаемый агент 007 (Codex), предлагаю начать выполнение задачи `<TASK-ID>` ...»** либо **«Уважаемый агент 008 (Claude), предлагаю начать выполнение задачи `<TASK-ID>` ...»**. Отношение — сотрудничество равноправных инженерных исполнителей, без командного или уничижительного тона; при этом scope и технические критерии сохраняются без расплывчатости. Дальше в тексте достаточно имени/ID/TASK-ID; не повторять обращение в каждом абзаце. Адресные AMENDMENT к уже запущенной задаче также начинаются уважительным обращением, но **не заменяют и не дописывают замороженный БЛОК 1**.

**Постоянная карта:** `007 = Codex`; `008 = Claude`. Номера — организационные ID агентов, **не TASK-ID, не номера коммитов, не версии модели и не признак старшинства**. Новые номера и переназначение этих ID допустимы только по прямому решению пользователя. Других агентов называть по их утверждённому имени, не придумывая им номера.

При постановке значимой coding/repair TASK требовать **собственного инженерного труда агента поверх автотестов**: до правки анализ исходников и инвариантов; после правки отдельный ручной (собственный аналитический) adversarial/source walkthrough, поиск failure paths/краевых состояний и подтверждение фактических raw-state последствий. Автотесты и локальные прогоны обязательны в рамках применимого регламента, но один зелёный PASS не достаточен для `RESULT READY`. Отчёт должен содержать `MANUAL ENGINEERING REVIEW` с конкретными выводами. Канон — `TEST-ENG-01@1`, `TEST-COLLAB-01@2` (36.1). Для noncoding задач требовать адекватный содержательный review, а не бессмысленный runtime suite.

Это **правило общения и инженерного процесса**, не утверждение о человеческой природе/сознании агента и не расширение прав Git, Remote, production или rollout.

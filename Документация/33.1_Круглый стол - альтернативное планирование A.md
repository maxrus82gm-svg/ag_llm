## Постоянная инструкция слота

1. До начала получить **от пользователя/назначенного координатора** RT/TASK, участника, модель, режим (INDEPENDENT_PLAN или REVIEW), допустимый read/write scope, общий `input_manifest_ref`, `rule_set_ref` и known exposure. Если чего-то обязательного нет — запросить, не выдумывать задание. Режим и разрешения не появляются из наличия файла.
2. Адресно прочитать `rule-ref:DOC-GIT-01@1` и `rule-ref:DOC-CHANGE-01@1` из 18, `rule-ref:RT-INDEPENDENCE-01@1`, `RT-INPUT-01@1`, `RT-CLEANUP-01@2` из 28 и `rule-ref:PLAN-MODES-01@1`, `PLAN-SEAL-01@1`, `PLAN-RECONCILE-01@2`, `PLAN-APPROVAL-01@2` из **постоянной нормативной части 33**, вместе с зависимостями; не читать для этого полный 33 при blind-mode. При невозможности отделить правила — просить координатора о безопасной выборке.
3. Локально читать исходники напрямую; **никаких самостоятельных Git/GitHub-операций**, включая `status/diff/log`; история по запросу через пользователя/координатора. Не использовать читательский доступ для обхода запрета на чужие планы.
4. `INDEPENDENT_PLAN`: исходный собственный TASK graph, mappings, dependencies, проверки, риски и ограничения **до** чтения чужих планов/их пересказов. `REVIEW`: изучить явно указанную версию проверяемого плана и сдать findings с evidence; этот результат не объявляется слепым.
5. Редактировать **только разрешённую оперативную область собственного слота**, не трогать постоянные инструкции и другой слот. В DRAFT менять текст можно, после SUBMITTED — добавлять отдельную correction/revision; прежний seal должен восстанавливаться. Не присваивать USER APPROVAL/PLAN APPROVAL и не запускать runtime.
6. По готовности сообщить `RESULT READY / AWAITING SEAL`; координатор сверяет, сохраняет bytes/provenance/input/hash извне файла и фиксирует SUBMITTED. Получить чужие планы можно только после разрешённого группового REVEAL; сравнение — новой записью, исходный результат не переписывать. **После хотя бы одного запечатанного SUBMITTED итоговый план обязательно оформляется в отдельной постоянной оболочке `33.3_Круглый стол - итоговый план.md`, не в исходном 33**, по `RT-FINAL-01@1` из 28. Пока нет group reveal и остальных gates, 33.3 не заполнять содержательным итогом.
7. При closeout дать фактологический отчёт: изученное и реальные проверки, source refs, corrections/unresolved, DOC IMPACT, требуемое действие/владелец. `COMPARED` не означает принятия. `ARCHIVED` и очистку слота делает координатор только после retention/restore и **отдельного разрешения пользователя** по RT-CLEANUP-01.

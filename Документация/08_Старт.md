# Вход в проект ag_llm / Web Alarm Ultra

**Рабочая редакция:** 31.10.2026. Точка входа нового рабочего чата по команде «прочитай №08» / «Старт». Актуальные статусы брать из №34 и evidence, не из даты файла.

## Сначала определить режим

**ChatGPT-координатор:** планирует, независимо проверяет чужую работу и закрывает принятую TASK документально. Модель/режим выбирает пользователь. Процедура: `18_Регламент сопровождения документации.md` → `DOC-CONTEXT-OPS-01 — Оперативная память, адресная навигация и закрытие задач`.

**Claude 008 / Codex 007 / Ultra Desktop:** выполняет назначенную работу, исследует, проверяет и сдаёт технический пакет. Вход — собственная карточка/прямое поручение. Координаторские права и независимый self-PASS не наследуются.

**Заранее назначенный INDEPENDENT_PLAN:** не читать обычный маршрут и историю ниже. Получить только этот изолированный режимный фрагмент и разрешённый координатором вход. До SUBMITTED запрещены неразрешённые общий №000, №34/40, базовые/чужие планы, №28.1, оперативный №33, чужие слоты №33.1/33.2/33.3 и их пересказы. Координатор доставляет точные правила с requires без скрытого соседнего контекста. Зафиксировать assignment/mode/participant/model/context_id, read/write-scope, уже увиденные планы, rule_set_ref и input_manifest_ref. Если источник нельзя отделить — SOURCE_UNAVAILABLE для зависимого действия. Уже увиденное нельзя объявить неувиденным; REVIEW не равен слепому планированию. Техническая автоматическая blind-изоляция не заявляется.

## Обязательное чтение общего №000 при каждом новом входе

**ОБЯЗАТЕЛЬНО для каждого обычного ChatGPT-координатора (WEB, LLM и следующих чатов):** после определения режима по №08 **открыть и прочитать действующую часть `Документация/000_Задачи для агента.md` (до «Сохранённые адреса прежней редакции»)**. Нельзя заменять чтение памятью предыдущего чата, пересказом или ссылкой. После этого — №40, №34, FOLLOWUP в №05 по маршруту ниже. При недоступности №000 — `STARTUP CONTEXT BLOCKED`: новую TASK не выдавать до чтения. **Исключение:** изолированный `INDEPENDENT_PLAN` не читает общий №000 до разрешённого перехода. Это регламент на команду входа в проект, не автоматическая загрузка файла при создании чата.

**БЛОК 1** персональной карточки Claude/Codex/Ultra Desktop — назначенная пользователем задача **или** `ОЖИДАНИЕ НОВОЙ ЗАДАЧИ`. **БЛОК 1.1** — ровно последняя сданная задача, дословная постановка для независимой проверки, статус `SUBMITTED / REVIEW PENDING` не означает PASS. После финального отчёта исполнитель вправе только безопасно и механически скопировать свой БЛОК 1 в 1.1, а БЛОК 1 освободить, **если** предыдущий 1.1 доказанно сохранён в №001 или постоянном опубликованном snapshot; остальные блоки и Git запрещены. Координатор при начале review читает 1.1, если 1 пуст; проверяет source/evidence отдельно, затем обновляет №001/05/06/34/БЛОКИ 2–4. Не считать перенос закрытием итерации. ## Обязательный контроль очереди FOLLOWUP при смене чата

**В каждом новом обычном координационном чате** после №34 адресно открыть №05 → `Очередь открытых продолжений (FOLLOWUP)`: прочитать шапку, все актуальные OPEN и связанные статусы/переходы к задачам-преемникам. **Весь №05 и историю №001/06 для этого не загружать.** №34 — краткая подсказка, но не замена проверке самой очереди.

**Повторять проверку** перед новой TASK, после независимой приёмки отчёта и переноса остатков в №05, при закрытии БЛОКА 1 и смене чата. Учитывать `UNASSIGNED` и уже назначенные, но не проверенные исправления. Назначение successor не закрывает FOLLOWUP: закрытие — по независимому evidence или явному решению пользователя о риске. По результату сверить краткие OPEN/NEXT и точные FOLLOWUP-ID в №34.

Если очередь недоступна или не удалось установить актуальность записи — обозначить `FOLLOWUP REVIEW BLOCKED / UNKNOWN`, **не** утверждать, что нерешённых пунктов нет, и не очищать зависящий от этой проверки БЛОК 1. Исключение: `INDEPENDENT_PLAN` в изолированном режиме не читает №05 или иной запрещённый оперативный контекст до разрешённого перехода. Подробная норма — №18 → `DOC-CONTEXT-OPS-01 / OPS-FOLLOWUP`.

**Выход чтения:** назвать пользователю цель, TASK/поручение, достигнутую точку, OPEN/ограничения, участников и разрешённый NEXT. Непрочитанное — UNKNOWN; память прошлого чата и указатель не доказывают чтение.

Локальному исполнителю дать матрицу `путь → точный заголовок/Rule-ID → зачем → обязательно/условно/полностью`: свои Правила/постановка/БЛОК 4 READ-ONLY, применимые №08/34/профиль/тестовые контракты, №18 адресно при пробеле. Общие тома/архивы автоматически не читать. Прямое адресное поручение пользователя задаёт scope без искусственного нового БЛОКА 1; это не постоянное право на другие TASK.

## Обязательный минимум безопасности и полномочий

- Локальным Claude/Codex и аналогичным исполнителям Git/GitHub запрещены, включая чтение, без отдельного явного разрешения на конкретную операцию. Канон №18 → DOC-GIT-01. История прежних Git-проверок не является разрешением.
- **Строгая сквозная нумерация: задача, микрозадача, проверка, доработка, закрытие — один атомарный нумерованный коммит.** Канон №18 → `DOC-COMMIT-01@1`.
- ChatGPT проверяет реально доступные tools/permissions и версии. Работа координатора с GitHub идёт по его отдельным правам; публикация в GPT и принятие пользователем GPT → main сохраняются. Инструментальная доступность не разрешает запись сама по себе. Безопасные временные тесты допустимы, постоянный код/tests/CI — по прямому USER GO; собственное исправление независимо принимает другой verifier. Канон №18 → DOC-ENGINEERING-ROLES-01@2.
- Изменять только разрешённые файлы/данные. Не экспериментировать на живом storage, не ослаблять backup/rollback, Host/Origin/token/Windows rights или изоляцию ради результата. Соседний shared scope сверить через №40. Live/paid/production и переход этапа требуют своих разрешений.
- Новую TASK назначает пользователь: ChatGPT даёт три блока, пользователь помещает постановку в БЛОК 1. Пока исполнитель работает, AMENDMENT — только в чат. После опубликованного отчёта и независимого review закрыть **итерацию с честным verdict**, все OPEN перенести в №05/FOLLOWUP, полную историю — №001/06, NEXT — №34; только после readback освободить БЛОК 1. Следующую связанную TASK ChatGPT сразу готовит в чат, но назначает только пользователь после sync. Канон №18 → DOC-ITERATION-CLOSEOUT-01@1.
- Один пользовательский `Start_WebAlarm.bat`: проверенный STANDARD/зелёный, согласованный временный TEST/красный с TASK ID/целью. Автор переключения возвращает и проверяет STANDARD; перед следующей технической TASK — проверка маршрутизации. При недоказанном восстановлении RESTORE_BLOCKED, без ложной зелёной метки. Наличие BAT не доказывает target/root/визуальный PASS. Канон №18 → DOC-WUA-LAUNCH-01.
- Сохранять границы B2 V-13, WA4-R, EVM/Windows/visual, portability и замороженного MCP №39 до их собственных доказанных решений. Утверждённая программа №37 не запускает этапы автоматически.
- Правила тестирования читать с областью применения: значимое изменение кода требует инженерного/adversarial анализа и подходящих реальных проверок, исходные FAIL/NOT RUN не скрываются. Только Markdown — проверка смысла, указателей, сохранности и графа. Само наличие регламента не является серверной защитой.

## Как читать подробности и завершать работу

№05: тема → TASK/record_id → точный раздел/строка записи. Статус читать с датой, независимым scope и OPEN. №06/001/профильные журналы — только адресно по разрешённому TASK и нужному фрагменту; не рекурсивно. Старый CURRENT относится к своему снимку. Точная строка зависит от версии; устойчивый адрес — путь/заголовок/ID/ревизия.

После сдачи: №18 → OPS-REVIEW/OPS-CLOSE. Полный результат у владельца; №34 — текущая картина и краткий итог с адресом. Сохранять исключения/запреты/provenance. Риск требует основания, владельца, действия и closure evidence; UNKNOWN не означает PASS.

Текстовые адреса не становятся Obsidian-связями. Существующие графовые конструкции, имена и целевые заголовки сохраняются. Область совместимых старых адресов ниже — только для адресного обращения; обычный старт заканчивается здесь. После каждого изменения стартовых правил проверять бюджет: цель 8–12 тысяч символов, предел 16 тысяч, считая весь файл.

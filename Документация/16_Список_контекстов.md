# Библиотека контекстов — каталог

`16_Список_контекстов.md` — документационный каталог для людей. Он сам не является runtime context, не передаётся модели автоматически и не служит автоматическим runtime Context Registry. Файлы библиотеки — подготовленные тексты и ориентиры для ручного выбора, копирования или отдельной явной TASK применения. Runtime хранит и подключает свои контексты отдельно; изменение Markdown не меняет их автоматически.

## Подготовленные контексты

| Документ | Уровень и назначение | Статус и возможное применение |
| --- | --- | --- |
| `14_Контекст проекта.md` | Project / Workspace context reference для `ag_llm`: устойчивые факты, решения и рабочий фокус проекта. | Актуальная документальная копия; человек может использовать её как эталон или текст для явного обновления реального Project Context. Сам файл автоматически не загружается. |
| `15_Глобальный контекст Ultra.md` | Global Ultra context reference: универсальные правила Executor, не зависящие от Workspace. | Актуальная документальная копия; человек может использовать её как эталон или текст для явного обновления реального Global Context. Сам файл автоматически не загружается. |

Новая запись должна кратко отвечать: **NAME, LEVEL / SCOPE, PURPOSE, STATUS, TARGET / WHERE IT MAY BE APPLIED**; связь с вариантом или preset указывать при необходимости. Перед добавлением проверить, нет ли контекста с той же ролью.

## Варианты и presets

Модели и роли различаются размером context window, устойчивостью к длинным инструкциям, скоростью и стоимостью. Поэтому библиотека может постепенно содержать контексты для разных проектов, ролей и LLM, а также компактные и расширенные варианты.

**Context Presets / Profiles — FUTURE, не реализованы.** Возможные наборы вроде FULL, COMPACT, MINIMAL или ROLE-SPECIFIC пока лишь примеры. Будущий preset должен выбирать зарегистрированные тексты или варианты, роль/модель, нужный объём и обязательные либо optional части; он не должен копировать содержимое всех контекстов. Runtime preset system сейчас отсутствует.

## Актуализация библиотеки

Для значимой TASK, затрагивающей контексты, Documentation Impact Check определяет `CONTEXT LIBRARY IMPACT: YES / NO`. Проверять влияние нужно при постоянном изменении реального Global / Project Context, принятии правила, улучшении текста, изменении назначения, появлении, замене или удалении типа/варианта, изменении будущей preset-логики либо появлении роли/LLM, которой нужен отдельный профиль. При `YES` проверить только затронутые документы библиотеки: `14` для Project Context `ag_llm`, `15` для Global Ultra Context, `16` для состава и назначения каталога, либо будущий профильный документ. Без фактического влияния правка не нужна.

**Документальный текст и runtime context — разные сущности.** Изменение одного не синхронизирует другое. Постоянно принятое изменение реального контекста человек или отдельная явная documentation TASK переносит в эталонную копию; новый самостоятельный context document также регистрируется здесь. Автоматической синхронизации нет.

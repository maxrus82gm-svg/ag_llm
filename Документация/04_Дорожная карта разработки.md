# Дорожная карта разработки GigaChat Ultra Local Agent

Этот документ фиксирует последовательность ближайших этапов развития системы. Дорожная карта разделена на конкретные TASK с критериями приёмки.

## Текущий статус

Система находится на этапе перехода от proof-of-concept к полноценной рабочей среде. Базовая инфраструктура (сервер, UI, file-agent, trace) готова. Следующий фокус — система чатов, workspace и управление контекстом.

## Этап 06: Система чатов и управление контекстом

### TASK 06.1 — Модель данных чатов и хранение на диске

**Цель:** Реализовать persistent storage для истории чатов.

**Критерии приёмки:**
- Каждый чат имеет собственную директорию с уникальной структурой.
- История сообщений сохраняется на диск в виде отдельных файлов.
- Метаданные чата (имя, даты, ID) хранятся в metadata.json.
- Реализован API для создания, чтения, обновления чатов.
- Проверка: после перезапуска UI отображает сохранённые чаты.

### TASK 06.2 — Навигация по чатам текущего workspace

**Цель:** UI и логика для работы с несколькими чатами.

**Критерии приёмки:**
- Sidebar или панель со списком чатов текущего workspace.
- Возможность создать новый чат.
- Возможность переключаться между чатами.
- При переключении контекст модели очищается и загружается контекст выбранного чата.
- Реализовано удаление и переименование чатов.

### TASK 06.3 — Настоящий multi-turn context

**Цель:** Устранить расхождение между историей UI и контекстом модели.

**Критерии приёмки:**
- Active context строится из полной истории чата.
- Модель получает все релевантные сообщения, а не только последнее.
- Проверка: модель помнит контекст из начала длинного разговора.
- Устранено поведение, когда UI показывает историю, но модель её «не видит».

### TASK 06.4 — Разделение raw history и active model context

**Цель:** Явное разделение полной истории и передаваемого контекста.

**Критерии приёмки:**
- Существует механизм учёта размера контекста (tokens/characters).
- Raw history всегда полная и неизменная.
- Active context — управляемый набор фрагментов.
- Реализован механизм trimming при превышении лимита (с предупреждением пользователю).

### TASK 06.5 — Управляемое сжатие контекста

**Цель:** Реализация интерфейса и логики сжатия.

**Критерии приёмки:**
- Пользователь может выбрать фрагмент истории для сжатия.
- Создаётся summary с сохранением критической информации.
- Оригинал остаётся на диске.
- В active context помещается summary.
- Интерфейс для действий: Сжать, Развернуть, Показать оригинал, Пересжать.
- Summary доступен для ручного редактирования.

## Этап 07: Переносимость между компьютерами

**Цель:** Start_Ultra.cmd и система должны работать независимо от окружения.

**Критерии приёмки:**
- Все пути относительные, не зависят от буквы диска.
- Скрипт определяет наличие Python в системе.
- При отсутствии .venv — создаёт его автоматически.
- Устанавливает зависимости из requirements.txt.
- Проверяет необходимые настройки (API-ключ, доступ к сети).
- Запускает приложение одной командой.
- Работает на разных машинах без ручной настройки.

> **Важно:** .venv — это локальное изолированное Python-окружение, НЕ виртуальная машина.

## Этап 08: Переход на web UI

**Цель:** Заменить Tkinter UI на браузерный интерфейс без переписывания ядра.

**Критерии приёмки:**
- Сохранена вся бизнес-логика server.py.
- UI переписан на HTML/CSS/JS (или легковесный фреймворк).
- Сохранена функциональность file-agent, trace, логирования.
- Приложение доступно по localhost:port.
- Поддержка нескольких одновременных сессий (опционально на этом этапе).

## Этап 09+: Дальнейшее развитие

После завершения этапов 06–08 система станет полноценной рабочей средой. Дальнейшие направления:
- Коллаборативная работа (несколько пользователей).
- Интеграция с внешними инструментами.
- Расширенные возможности управления контекстом.
- Поддержка других LLM API.

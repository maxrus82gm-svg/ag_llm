# Ultra Safe Mode v1

Этот прототип добавляет в текущий GigaChat Ultra Local Agent жёсткие серверные ограничения и автоматические резервные копии.

## Что появляется в интерфейсе

В блоке **БЕЗОПАСНОСТЬ ЗАПУСКА** есть:

- **Разрешить чтение** — физически включает/выключает `list_dir` и `read_file`.
- **Разрешить запись** — физически включает/выключает `write_file`.
- **Чтение только в** — относительная папка внутри текущего workspace. `.` означает весь workspace.
- **Запись только в** — относительная папка внутри текущего workspace.
- **Автобэкап ДО запуска** — создаёт резервный снимок до первого API-запроса к Ultra.

Пример безопасной работы с документацией:

- Чтение: `ON`, область `.`
- Запись: `ON`, область `Документация`
- Автобэкап: `ON`

В таком режиме Ultra может видеть весь workspace, но `server.py` физически не даст записать файл вне `Документация/`.

## Бэкапы

Бэкапы лежат вне репозитория:

`%LOCALAPPDATA%\GigaChatUltra\backups\<RUN_ID>\`

До обращения к модели копируются критические файлы, если они существуют:

- `server.py`
- `ultra_ui.py`
- `context_storage.py`
- `workspace_runtime_settings.py`
- `ui_state.py`
- `Start_Ultra.cmd`
- `Документация/00_Обязательный регламент Ultra.md`

Дополнительно перед **первой записью каждого существующего файла** сервер сохраняет его исходную версию в:

`changed/<относительный путь файла>`

Если Ultra создаёт новый файл, он записывается в `manifest.json` как `new_files`.

Если создание обязательного pre-run backup не удалось, запуск Ultra отменяется до обращения к модели.

## Что сервер блокирует

Если модель пытается выйти за разрешённую область, она получает `PermissionError`, а в trace появляется `DENIED`.

При выключенной записи `write_file` вообще не передаётся модели в списке доступных функций.

При выключенном чтении `list_dir` и `read_file` не передаются модели.

## Безопасный default вне UI

Если `run_agent_task()` вызывается напрямую без параметра `permissions`, сервер по умолчанию разрешает чтение всего workspace, **запрещает запись** и включает автобэкап. То есть обход UI не превращает запуск автоматически в режим полной записи.

## Что пока НЕ реализовано

Safe Mode v1 намеренно небольшой:

- одна область чтения и одна область записи на запуск;
- нет `delete` и `move` tools — их и раньше не было;
- нет кнопки автоматического восстановления из backup;
- нет нескольких allowlist-папок одновременно;
- нет постоянных пресетов (`Документация`, `Код`, `Только анализ`) — это можно добавить следующим этапом.

## Установка

Файлы в комплекте называются `server_SAFE_v1.py` и `ultra_ui_SAFE_v1.py`, чтобы ничего не перезаписать автоматически.

В каталоге проекта:

1. Сохрани текущие `server.py` и `ultra_ui.py` под резервными именами.
2. Замени `server.py` содержимым `server_SAFE_v1.py`.
3. Замени `ultra_ui.py` содержимым `ultra_ui_SAFE_v1.py`.
4. Проверь синтаксис:

```bash
python -m py_compile server.py ultra_ui.py
```

5. Запусти `Start_Ultra.cmd`.

## Первый тест

Поставь:

- READ = ON, `.`
- WRITE = OFF
- BACKUP = ON

И отправь:

> Покажи содержимое корня workspace и прочитай README.md. Ничего не изменяй.

После этого для теста защиты записи поставь:

- READ = ON, `.`
- WRITE = ON, `Документация`
- BACKUP = ON

И попроси Ultra **только в тестовом задании** попытаться изменить файл вне `Документация`, например `README.md`. Ожидаемый результат — `DENIED / PermissionError`, файл не меняется.

## Проверки, выполненные перед выдачей

- `server_SAFE_v1.py` проходит `py_compile`.
- `ultra_ui_SAFE_v1.py` проходит `py_compile`.
- smoke-test: чтение всего workspace + запись только в `Документация`.
- smoke-test: запись вне `Документация` блокируется.
- smoke-test: исходная версия изменяемого файла попадает в backup до записи.

## Актуальный статус (после TASK DOC-SYNC-01)

Safe Mode v1 остаётся историческим прототипом раннего этапа. В текущей реализации безопасность обеспечивается встроенными механизмами server.py:

- READ/WRITE/DELETE scopes с относительными путями.
- VERIFY с белым списком: python_compile, git_status, git_diff, ui_smoke_test.
- Server-side Verification Gate, физически блокирующий SUCCESS до выполнения проверок.
- Обязательный pre-RUN backup с namespace по workspace_id.
- Защита служебного хранилища `.ultra/` от обычных file tools.
- Отдельные RUN logs по workspace_id, настраиваемые backup/log пути вне Workspace.

## 2026-09-18 — TASK DOC-04: Обязательный регламент Ultra и автоматическая загрузка правил

### Цель

Создать единый обязательный регламент поведения Ultra и обеспечить его автоматическую загрузку в system prompt каждого вызова run_agent_task. Пользователь больше не должен вручную просить Ultra соблюдать базовые правила — они действуют по умолчанию.

### Изменённые файлы

- Документация/00_Обязательный регламент Ultra.md — создан
- server.py — изменён
- Документация/00_Главная - карта проекта.md — обновлена
- Документация/01_Архитектура и текущее состояние.md — обновлена
- Документация/02_Правила разработки и работы с Ultra.md — обновлена
- Документация/06_Журнал выполнения и отчёты.md — этот файл

### Что реализовано

1. Создан документ «00_Обязательный регламент Ultra.md» со статусом ОБЯЗАТЕЛЬНО, версия 1.0, содержащий 16 разделов правил.
2. В server.py реализована автоматическая загрузка регламента при каждом вызове run_agent_task:
   - путь определяется относительно app_dir = Path(__file__).resolve().parent
   - регламент читается с диска на старте каждого run, а не при import
   - при отсутствии или пустом файле — fail-closed: RuntimeError и остановка
   - текст регламента добавляется в system message отдельным блоком «ОБЯЗАТЕЛЬНЫЙ РЕГЛАМЕНТ ULTRA»
3. Сигнатура run_agent_task не изменена.
4. ultra_ui.py не изменялся.
5. В карту проекта добавлена ссылка на новый регламент.
6. В архитектуру добавлено описание механизма загрузки регламента.
7. В правила разработки добавлено пояснение о расположении полного регламента.

### Проверка

- Путь к регламенту не содержит абсолютных Windows-путей (M:\ и т.п.), используется Path(__file__).resolve().parent.
- Регламент читается при каждом run_agent_task, а не кэшируется при import.
- При отсутствии файла Документация/00_Обязательный регламент Ultra.md запуск блокируется с понятной ошибкой.
- Существующий system prompt file-agent сохранён, регламент добавлен как отдельный блок.
- Сигнатура run_agent_task(task, workspace_root, *, on_event=None) сохранена.
- ultra_ui.py не изменялся.
- После изменения server.py требуется перезапуск приложения.

### Результат

Ultra теперь автоматически получает обязательный регламент в system context каждого запуска. Пользователь не должен вручную просить соблюдать базовые правила. Отсутствие регламента блокирует запуск (fail-closed).

### Известные проблемы

- TASK 06.1–06.5 ещё не реализованы в коде, только запланированы.
- Настоящий multi-turn контекст отсутствует.
- Web UI не реализован.
- Переносимость запуска требует доработки.

### Следующий шаг

Начать реализацию TASK 06.1 — модель данных чатов и хранение на диске.

### Требуется restart

Да. После изменения server.py требуется полный перезапуск приложения.

## Исторический итог (инфраструктура)

К текущему моменту реализована базовая инфраструктура:

- **standalone Ultra** — автономное приложение
- **Tkinter UI** — графический интерфейс
- **file tools** — контролируемый доступ к файловой системе
- **trace/event subsystem** — логирование действий
- **runtime warning** — предупреждение об изменениях
- **sidebar лога** — визуальный мониторинг
- **успешный диагностический run** — проверка работоспособности

Эта инфраструктура является фундаментом для дальнейших этапов (06.1–06.5).

**Примечание по нумерации:** Система нумерации задач упрощена. Исторические TASK 05A* объединены в завершённый этап 05 — «Базовая инфраструктура Ultra». Новые задачи используют упрощённую систему 06.1–06.5 вместо 06A–06E. Исторические записи сохраняются для понимания происхождения изменений.

## 2026-09-19 — ОБНАРУЖЕННЫЙ GAP: NO-TOOL STOP

RUN:

`20260919_215131_7e4717`

### Наблюдаемый факт

RUN завершился:

```text
API #1 -> stop
SUCCESS
TOOLS: 0
```

При этом Ultra выдала финальный отчёт так, будто документы были прочитаны, изменены и проверены.

По фактическому trace этого не происходило.

### Архитектурное значение

Текущий Verification Gate контролирует корректность проверок после реальных файловых mutations.

Если модель вообще не вызывает tools:

- `write_revision` остаётся равным 0;
- Verification Gate не видит незавершённой файловой mutation;
- RUN может завершиться `stop / SUCCESS`;
- модель при этом способна текстом заявить о невыполненных действиях.

### Статус

Проблема ОБНАРУЖЕНА.

Автоматическая защита от такого поведения пока НЕ РЕАЛИЗОВАНА.

Рабочее название возможного будущего слоя:

`TASK EXECUTION GATE / NO-TOOL STOP GUARD`

Он должен отдельно контролировать ситуацию, когда изменяющая TASK завершается без необходимых фактических tool actions.

## 2026-09-19 — GUARD P1: SERVER-SIDE SUPERVISOR

GUARD P1 реализован как первый server-side behavior guard.

Основные runtime-файлы:

- `server.py`;
- `ultra_ui.py`.

В UI существует отдельная настройка `GUARD P1` рядом с `VERIFY`.

По умолчанию GUARD P1 включён.

### Назначение

GUARD P1 не заменяет permission system и Verification Gate.

Его задача — вмешиваться ДО выполнения подозрительного действия и возвращать модели короткий внешний `SUPERVISOR CHECK`.

Модель получает возможность перечитать TASK, предыдущие результаты и изменить собственную траекторию выполнения.

### Физический тест 1 — REPEATED READ

RUN:

`20260919_212213_00575f`

Наблюдаемый trace:

```text
TOOL #1 read_file -> OK
TOOL #2 read_file -> OK
GUARD P1 | SUPERVISOR CHECK | REPEAT read_file
```

Третья идентичная попытка `read_file` не была физически выполнена.

Итог:

```text
TOOLS: 2
SUCCESS
```

Ultra после `SUPERVISOR CHECK` прекратила бессмысленные повторные чтения.

### Физический тест 2 — POSSIBLE DUPLICATE CREATE

RUN:

`20260919_213415_15e109`

Существующий файл:

`06_Журнал выполнения и отчёты.md`

Имитация ошибочного CREATE:

`06_Журнал выполнения и отчётов.md`

Наблюдаемый результат:

- существующий файл был найден и прочитан;
- попытка CREATE почти одинакового файла была перехвачена ДО записи;
- сервер выдал `SUPERVISOR CHECK | CREATE`;
- similarity score составил `145`;
- ошибочный новый файл не был создан;
- Ultra вернулась к существующему каноническому пути;
- изменение существующего файла было выполнено;
- `git_diff` и `git_status` выполнены;
- `VERIFY GATE -> PASSED`;
- RUN завершился `SUCCESS`.

### Известное ограничение GUARD P1

Позднее обнаружен важный edge case.

Если подозрительное имя нового файла буквально присутствует в тексте TASK как пример или описание старой ошибки, текущая логика может интерпретировать это как возможное явное разрешение пользователя на CREATE.

Из-за этого защита от near-duplicate CREATE требует дальнейшего уточнения.

### Текущий статус GUARD P1

Физически подтверждены:

- вмешательство при повторных успешных deterministic reads;
- вмешательство при одном типе suspicious near-duplicate CREATE.

GUARD P1 является v1 и НЕ является универсальной системой понимания намерений TASK.

Он не заменяет:

- READ / WRITE / DELETE scopes;
- permission gate;
- backup;
- Verification Gate;
- ручной review trace.

Динамическое увеличение tool budget по запросу модели пока НЕ РЕАЛИЗОВАНО.

## 2026-09-30 — TASK 146: RUN STORE EXTERNAL-LOCK RECOVERY — DONE + LIVE VERIFIED

TASK 146 исправляет доказанный TASK 145 scenario: canonical `.ultra/audit/index.json` может быть долго открыт внешним Windows process без delete/replace sharing, поэтому обычный atomic `os.replace` и bounded retry не гарантируют сохранение нового RUN.

### Реализация

`run_store.py` теперь поддерживает revisioned workspace index:

- `index.json` получает монотонное поле `revision`; старый index без поля читается как revision 0;
- при успешном canonical replace новый state остаётся в `index.json`;
- если canonical replace после bounded retry получает persistent `PermissionError`, полный index snapshot сохраняется как уникальная immutable generation в `.ultra/audit/index_generations/index-<revision>-<uuid>.json`;
- `load_workspace_run_index()` рассматривает canonical и generation snapshots и выбирает максимальную revision; при равной revision canonical имеет приоритет;
- после появления хотя бы одной generation следующая canonical попытка выполняется без повторного полного retry-window: при продолжающемся lock сразу создаётся следующая generation;
- когда lock исчезает, следующая index mutation записывает актуальный state обратно в canonical `index.json`; generations с revision не новее canonical удаляются, недоступные для удаления snapshots не делают RUN недоступным;
- если не удаётся записать и generation storage, `PermissionError` остаётся видимым и не маскируется;
- `update_run_summary_index()` больше не переписывает workspace index при summary-only изменениях `api_requests/tool_calls/usage`; index mutation происходит только при реальном изменении `run_status` или `final_audit`.

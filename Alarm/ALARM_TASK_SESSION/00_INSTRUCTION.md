# ALARM TASK SESSION — инструкция удалённой работы

Эта зона используется при работе ChatGPT с проектом через удалённый доступ к компьютеру (Desktop Commander Remote / эквивалентный канал).

**ГРАНИЦА ПРИМЕНЕНИЯ (решение пользователя 2026-10-08):** этот per-action аварийный протокол предназначен **только для удалённого ChatGPT, зависящего от Desktop Commander Remote и подверженного обрывам соединения/контекста**. Локальные Claude Desktop/Code и Codex CLI **не обязаны** создавать `ALARM_TASK_SESSION/TASK_*`, `session.jsonl`, `context.md`, `history.md`, делать `INTENT/DONE/VERIFIED` для каждого изменения или safety copies всех файлов. Нельзя распространять этот протокол на них ссылкой из типовой TASK; ранее записанные требования такого рода для будущих локальных TASK считаются неприменимыми, если пользователь отдельно не утвердил специальный режим восстановления. Для локальных агентов действует раздел «Локальные исполнители» в `Документация/18_Регламент сопровождения документации.md`. Уже созданные материалы не удалять автоматически; реальные артефакты runtime Web Alarm (snapshot/rollback/receipts) этим правилом не отменяются.

## Обязательное правило входа
0. **CHAT-FIRST для новой значимой Remote TASK:** до первого Remote/Desktop Commander вызова полная постановка TASK должна уже быть опубликована ChatGPT в обычном Chat. Если это новая TASK и такой публикации ещё нет — не начинать Remote-работу: сначала вывести TASK в Chat, затем вернуться к этому маршруту. Для recovery уже начатой TASK достаточно существующей постановки в Chat / `000` / этой TASK-сессии; повторять её не требуется, если она не изменилась.
1. Определить номер текущей TASK.
2. Открыть `Alarm/ALARM_TASK_SESSION/TASK_<N>/`; если папки нет — создать её.
3. Перед продолжением прочитать `context.md`, `history.md` и последние записи `session.jsonl`.
4. Если последний шаг имеет `INTENT` без подтверждённого `DONE` / `VERIFIED`, сначала проверить фактическое состояние на диске и только потом решать, повторять ли действие.

## Правило каждой изменяющей операции
- Сначала записать в `session.jsonl`: `INTENT` — что именно планируется сделать и с каким объектом.
- Затем выполнить действие.
- После фактического выполнения записать `DONE`.
- После независимой проверки результата записать `VERIFIED`.
- Если действие не выполнилось или связь оборвалась до подтверждения, не придумывать `DONE`: незакрытый `INTENT` остаётся точкой аварийного восстановления.

## Файлы TASK-сессии
- `session.jsonl` — оперативный журнал шагов и состояний.
- `context.md` — краткое текущее состояние: цель, текущий этап, следующий безопасный шаг, риски.
- `history.md` — человеческая хронология значимых действий, решений, проверок и обрывов.

Чтения без изменения данных можно выполнять без отдельного INTENT. Любые write/edit/delete/move и другие изменяющие действия должны проходить через журнал.

## 4. Решение (этап C)

`web_alarm/evidence_sanitizer.py` — offline-инструмент оператора, runtime его не импортирует; `python -m web_alarm.evidence_sanitizer`:

- `scan PACKAGE [--manifest] [--json FILE]` — инвентаризация без единой записи в пакет; печатает только классы и счётчики; exit 2, если найдено что-то кроме иллюстративного/системного. Годится как **шлюз перед публикацией** любой папки.
- `stage PACKAGE --out DIR [--manifest]` — копирует оригиналы (с чтением назад и сверкой SHA), пишет очищенные копии и `mapping.json`: `id → source_sha256 → sanitized_id → sanitized_sha256`, замены по видам, `structure`, `safety`, совпадение с SHA исходного manifest. Заблокированный файл **не получает** очищенной копии. `--out` — новый пустой каталог вне пакета; внутри репозитория — только под git-игнорируемым `logs/`.
- `verify DIR [--package PACKAGE]` — пересчитывает SHA оригиналов и копий, ищет лишние файлы, **воспроизводит** каждую копию заново из сохранённого оригинала и сверяет с текущим пакетом.

Правила (политика v1, записывается в `mapping.json`):
- **Распознавание структурное:** диск + компоненты с любыми разделителями (`[\\/]+`), UNC с проверкой уровня экранирования (префикс UNC ровно вдвое длиннее разделителя того же уровня; два экранированных перевода строки подряд — не UNC), `\\?\`/`\\?\UNC\`, POSIX-home, обрезанные фрагменты `<имя>\AppData\Local|Roaming|LocalLow`, профиль без диска. Уровень экранирования определяется по ширине первого разделителя; `\uXXXX`-экранированное имя профиля остаётся одним компонентом на любом уровне.
- **Замена только префикса:** `C:\Users\<имя>\AppData\Local\Temp` → `<TEMP>`, `C:\Users\<имя>` → `<HOME>`, `…\ag_llm` → `<REPO>`, сервер и общий ресурс UNC → `<UNC>`, неизвестный абсолютный путь → `<ABS>\<последний компонент>`. Остаток пути — байт в байт. Не трогаются: системные (`C:\Windows`, `Program Files`, `ProgramData`, `Users\Public`), иллюстративные (`C:\…\…`, первый компонент — многоточие), корень диска, однокомпонентные пути, URL, время.
- **JSON — по строковым токенам:** числа, `NaN`, большие целые, пробелы, порядок и дубликаты ключей сохраняются байт в байт; изменённый токен кодируется тем же стилем (`ensure_ascii`), U+0085/2028/2029 остаются экранированными. После правки — сравнение деревьев (пары ключ-значение с дубликатами): иные типы, длины, нестроковые листья → отказ; коллизия ключей после очистки → отказ; изменение защищённого поля (`test`, `status`, `exit`, `label`, `task`, `selector`, `outcome`, `test_id`) → отказ. JSONL — построчно. BOM и CRLF сохраняются.
- **Шлюз:** после очистки повторный поиск путей, секретов и локальных имён (целые слова ≥ 3 символов: пользователь, компьютер, папка профиля и их части, кроме общих слов вроде `DESKTOP`) по опубликованному тексту, по декодированным JSON-строкам и по их `\uXXXX`-раскодированным формам. Любой остаток, найденный секрет (редактируется, но требует решения человека), неразбираемый JSON, бинарный файл с находками → `BLOCKED` и `REFUSED`.
- **Детерминизм:** результат — функция только (байты, политика); локальная идентичность влияет лишь на вердикт шлюза. Две подготовки дают побайтно одинаковые копии и `mapping.json`; `tool_sha256_lf` не зависит от LF/CRLF checkout.
- **Безопасные сообщения:** выводятся только относительные идентификаторы и счётчики; ошибки — через тот же санитайзер с маскировкой имён; для `OSError` — только `strerror`; любое неожиданное исключение перехватывается (стандартный traceback напечатал бы пути).
- **Линейность:** possessive-квантификаторы (Python ≥ 3.11) — серии в десятки тысяч обратных слэшей обрабатываются за доли секунды.

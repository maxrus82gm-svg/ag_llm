**ARCH CLASS:** Quality Transition / Final Audit / Evidence Packaging / Runtime Efficiency.  
**PRIMARY PROFILE:** `13_Архитектура оперативной верификации и контроля выполнения задач.md`.  
**SECONDARY PROFILES:** `01_Архитектура и текущее состояние.md`, `03_Чаты, проекты и контекст.md`, переходные `20` и `21`.

**Цель:** сделать Final Audit / Dredd packet полным по смыслу, но task-scoped и компактным. Workspace-wide Git diff не должен быть default payload; Server обязан механически доказать completeness до вызова Dredd, а Dredd проверяет semantic completeness относительно RAW TASK.

**Обязательный материал пакета:** RAW TASK; accepted contract / active requirements; requirement → evidence coverage; фактический material, нужный для semantic verification; mutation facts/receipts; exact verification + freshness identity; unexpected/external/unattributed task-relevant changes; unresolved/contradicting facts; candidate final response; completeness metadata.

**Fail-closed:** если mandatory material отсутствует или механическая coverage неполна, Dredd не вызывается «на догадку». Нельзя ослаблять authoritative Server, permission/scope gates, Planner contract, physical verification, TASK 151B evidence freshness, независимый Final Audit и Run Store reproducibility.

**Task-scoped Git evidence:** Git evidence по умолчанию ограничивается файлами/targets текущей TASK и текущего RUN. При этом нельзя скрывать unexpected target changes, external/unattributed mutation, stale state или conflict candidate final ↔ authoritative facts.

**Порядок:** сначала audit фактической реализации Final Audit/Git evidence → design → runtime changes → targeted tests → expanded Final Audit/lifecycle regression → full unittest → py_compile → UltraApp smoke → git diff --check.

**Live policy:** большие live RUN пока не выполнять. R-027/R-031 остаются stress/negative inputs будущей 151G; после offline/code/test verification отдельно решить, безопасен ли небольшой bounded live test.

**Критерий КТ-3:** Dredd получает task-scoped mechanically-complete packet по всем active requirements и negative facts; workspace-wide diff не default; incomplete packet блокируется до Dredd; freshness/authority invariants сохранены.

**Ожидаемый переход после независимой проверки:** `TASK 151C = DONE / КТ-3 = DONE / NEXT = TASK 151D — Server Direct Exact Evidence`.

### Как вернуться к отложенной задаче

1. Не переносить её обратно в «Текущую задачу» автоматически только по записи в этом файле.
2. Сначала перечитать профильные документы и сверить фактическое состояние репозитория, recovery-журнал и live evidence.
3. Установить, что из TASK 151C уже реально выполнено, что осталось незавершённым и не появились ли противоречащие изменения.
4. После reconciliation перенести актуализированную формулировку TASK 151C в блок **«1. Текущая задача»**.
5. Только после этого продолжать кодовые изменения или verification; незавершённые действия вслепую не повторять.
6. Пока TASK находится здесь, она считается **PAUSED / DEFERRED** и не блокирует запуск другой текущей TASK.

## 2. Причины подробно (по исходным байтам модуля, SHA `1b4fb52e…`)

- **F-ES-01.** `_mapping_row()` писал `manifest_sha256_match = expected == source_sha256`, но `process_bytes()` и решение о копии вызывались раньше и независимо; `stage()` считал вердикт только по `safety`. `package_files()` в режиме manifest принимал `files` как словарь **или список имён** (тогда без хешей вообще), читал манифест через обычный `json.loads` (дубль ключа — побеждает последний), не проверял неперечисленные файлы и не сверял размер. `verify()` не открывал сохранённый манифест.
- **F-ES-02.** `verify()` проходил по `mapping["files"]` и проверял лишь наличие/хеш оригинала и копии **для перечисленных строк** плюс лишние файлы только в `sanitized/`. Удаление строки + копии (сценарий verifier-а) оставляло лишний оригинал, который никто не искал. Итоги, вердикт, политика и `selection` не пересчитывались. Режим без `--package` никак не учитывал, что совместное удаление строки, оригинала и копии из комплекта без внешнего якоря необнаружимо в принципе.

## 3. Решение

**Целостность (stage/scan):** `package_files()` возвращает выборку из ровно тех файлов, за которые можно отвечать: обход каталога без следования ссылкам (ссылка/junction/спецфайл → отказ), безопасные id (относительный POSIX-путь без `\`, двоеточия — в т.ч. NTFS-потоков, `..`/`.`/пустых частей, завершающих точек/пробелов, управляющих символов), уникальность без учёта регистра; в режиме manifest — строгий JSON без дублей ключей, `files` только объект, манифест не перечисляет сам себя, каждый перечисленный файл существует, неперечисленные помечаются. Сверка записи: `sha256` — 64 hex-символа, `bytes` — целое ≥ 0 (не `bool`), оба совпадают с фактом; иначе `manifest-entry-invalid` / `manifest-sha256-mismatch` / `manifest-bytes-mismatch` → BLOCKED. `scan --manifest` помечает такие файлы `INTEGRITY` (exit 2). `stage` теперь: учёт → чтение один раз → обработка → сверка манифеста → перехэширование манифеста кандидата (+ повторный шлюз) → повторное чтение источника (изменение → BLOCKED) → запись. Заблокированный файл никогда не получает копию (`FileResult.refuse` сбрасывает выход).

**Полнота (verify):** ничего из карты не берётся на веру. Проверяются: строгий JSON карты, политика (версия, якоря — не имена профиля/системы, защищённые поля не урезаны), схема каждой строки, безопасные и уникальные id, отсутствие посторонних записей в корне комплекта, ссылок/junction в `originals/` и `sanitized/`, точное совпадение множеств файлов со строками, хеши и размеры оригиналов; каждая строка пересчитывается заново (`process_bytes` + сверка с сохранённым манифестом + воспроизведение перехэшированного манифеста кандидата), затем сравниваются `safety`, хеш и размер копии, флаги `changed` / `manifest_check` / `manifest_sha256_match`, итоги и вердикт. Читаются только файлы, реально найденные обходом внутри комплекта.

| Уровень полноты | Чем доказана | Вердикт при согласованном комплекте |
|---|---|---|
| `PROVEN_AGAINST_PACKAGE` | `--package`: инвентарь пакета (all-files — все файлы; manifest — перечисленные + манифест + неперечисленные) и байты каждого файла | SAFE CANDIDATE |
| `PROVEN_BY_EXTERNAL_MAPPING_SHA256` | `--mapping-sha256`: хеш `mapping.json`, напечатанный `stage` и записанный вне комплекта | SAFE CANDIDATE |
| `NOT_PROVEN` | только сам комплект | **REFUSED** (exit 2) |

**Ограничение (прямо по постановке):** манифест внутри пакета — заявление, а не криптографический якорь; `--package` доказывает соответствие пакету **в его текущем состоянии**, а не тому, что было опубликовано раньше. Совместную подмену пакета и комплекта обнаружит только якорь, записанный в другом месте (например, хеш карты в отчёте/коммите — Git агенту недоступен).

**Манифест кандидата:** в режиме manifest `sanitized/manifest.json` описывает очищенные байты (`sha256`/`bytes` изменённых файлов обновлены, остальное содержимое сохранено, JSON пересериализован с отступом 1, окончания строк и BOM сохраняются); исходный манифест — в `originals/`. Без этого кандидат публиковал бы манифест, который не соответствует его файлам, и сам не прошёл бы `scan --manifest`. В режиме all-files `manifest.json` — обычный файл (его заявления не проверяются; см. §8).

**CLI:** `IntegrityRefusal` → exit 2 (`publication: REFUSED`); `stage` печатает `mapping_sha256` для записи вне комплекта; `verify --mapping-sha256 HEX`; небезопасный `--repo-anchor` → exit 3; отсутствие `mapping.json` или каталога пакета — по-прежнему exit 3 (это не комплект).

## 12. REVISE F-ES-03 — независимость `--package` (AMENDMENT 2026-10-24)

Текст AMENDMENT дословно — `amendment-F-ES-03.md`. Получен в чате исполнителя; БЛОК 1 оставался в ожидании; БЛОК 4 не менялся; архивы `001` не читались (кроме readback своих записей).

**Причина.** `verify(out, package)` объявлял `completeness = PROVEN_AGAINST_PACKAGE` для **любого** существующего каталога `package` и сравнивал инвентарь и байты, не проверяя, что этот каталог не является частью самого комплекта. `out/originals` содержит ровно исходные файлы с теми же хешами, поэтому «пакет» тривиально совпадал с комплектом — независимого подтверждения полноты не было.

**Минимальное исправление** (`web_alarm/evidence_sanitizer.py`, +31 строка, 5 точечных правок и один блок помощников; обратная реконструкция в `tools/build_mirror.py pre-es03` даёт ровно опубликованный SHA `f1a98cc4…` — т.е. других изменений нет):
- `_canonical(path)` — одно сравнимое написание существующего пути: `os.path.realpath(..., strict=True)` (абсолютный, символические ссылки, junction и 8.3-имена раскрыты), снят префикс `\\?\` / `\\?\UNC\`, `normcase` (регистр в Windows);
- `_overlap(a, b)` — один каталог совпадает с другим или лежит внутри него (`commonpath`; разные диски — не пересечение);
- в `verify`: если `package` пересекается с `out` в любую сторону → проблема `package-not-independent`, сравнение с пакетом **не выполняется**, полнота `NOT_PROVEN` (или `PROVEN_BY_EXTERNAL_MAPPING_SHA256` при верном якоре — но проблема всё равно даёт REFUSED);

**Оценка сложности:** два небольших помощника (~20 строк) и три условия в одной функции; публичный контракт прежний, новых параметров нет. `samefile` — единственная проверка, которая ловит дерево жёстких ссылок (путь там действительно независимый); снятие префикса `\\?\` нужно для случая корня комплекта, где общих файлов нет (мутант R16 это доказал). Лишнего усложнения не вижу; отказался от более тяжёлых вариантов (сравнение томов/идентификаторов каталогов, запрет любых пакетов на том же диске, обязательный `--mapping-sha256`), как от несоразмерных.

**Исправление (только `tools/check_package.py`):** строгая загрузка `manifest.json`, `runs-map.json`, `census.json`, `evidence.json` — повтор ключа даёт `<файл>-duplicate-key`; уникальность `id` в `runs-map.json` (`runs-map-duplicate-id` — число лишних вхождений, в том числе для полностью идентичных записей); безопасный относительный `id` (`runs-map-unsafe-id`, такой файл не читается).

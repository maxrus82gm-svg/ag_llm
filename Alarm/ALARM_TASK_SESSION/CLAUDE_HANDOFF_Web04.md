## Принятые решения (не переоткрывать без причины)
- **Authority файла:** SHA-256 точных байтов + размер. Git и нормализация EOL — не доказательство; EOL-only drift — только диагностика.
- **Контракт:** своя версия контракта; глобальная `SCHEMA_VERSION=1` не поднимается. Legacy v1 (2 записи WA-3.7) читается, но никогда не даёт re-arm и не владеет целями.
- **Resolver:** берёт evidence только из persistent state (post из контракта v2 или manifest), post-state от вызывающего не принимает. ABORT окончателен. STALE / REJECTED сохраняются. RETRY — только re-arm, ROLLBACK в RC-2 — только запрос.
- **RC-3:**
  - identity конфликта — физический resolved path;
  - release для STARTED / UNKNOWN — только после fresh ADOPT или ABORT;
  - операция не в INTENT получает владение только через fresh accepted RETRY;
  - `/authorize` — только evidence; authority на запись существует лишь внутри `mutation_boundary`;
  - для WA4-E: STARTED фиксировать под уже взятой TASK-блокировкой ДО записи (нужен lock-held transition path; обычный `transition()` внутри boundary даёт self-deadlock).
- **RC-4:**
  - полная проверка свежести резолюции — до первой мутации, дальше «с поправкой на свои изменения» плюс доказательство текущих байтов по каждой цели;
  - receipt — история, не доказательство текущего состояния: финальная проверка в `_finalize` перед VERIFIED / снятием claims;
  - PARTIAL / FAILED финальны (`close` + новая reconciliation);
  - claim исходной операции при откате переходит к rollback (`SUPERSEDED_BY_ROLLBACK`).

## Нюансы, на которых легко ошибиться
- **Переводы строк:** `core.autocrlf=true`, `.gitattributes` нет; ничего не нормализовать. Код `web_alarm/` и карточка — LF. Документы править Python-скриптом с сохранением байтов (`newline=''` или bytes) и проверять, что CRLF не появился.
- **Bash здесь ломается на heredoc** с кавычками или `'''` внутри (`unexpected EOF`). Скрипты класть через Write в scratchpad и запускать оттуда. Синтаксическая ошибка bash означает, что ничего не выполнилось, но это надо проверить.
- **Obsidian — внешний писатель:** переписывает `.obsidian/*`, может держать файл (EPERM при атомарном rename). Тогда проверить целостность файла и повторить только неприменённую правку.
- **Тесты:** разрушающие сценарии — только во временных workspace. Гонки — через реальные процессы с барьером старта плюс проверка чувствительности (без блокировки тест обязан падать). Если тест падает «правильным» fail-closed с другим кодом — сначала понять порядок проверок, а не ослаблять assertion.
- `git diff --check` может ругаться на хвостовые пробелы в тексте, который вставил пользователь, — чужой текст не трогать.
- **Метрики Remote** берутся из `~/.claude-server-commander/tool-history.jsonl` — только время и имя инструмента, никогда аргументы и вывод.

# Постоянные файлы запуска Web Alarm Ultra

Двойной щелчок по одному из двух файлов в корне проекта:

| Файл | Режим |
| --- | --- |
| `Start_WebAlarm_Test.cmd` | Текущий TEST-профиль. Сейчас Stage 5 OFFLINE: fake LLM, временные чаты, браузер. |
| `Start_WebAlarm_Standard.cmd` | Штатный Web Alarm Ultra с обычными постоянными данными пользователя. |

Оба файла используют существующий `web_alarm.launcher` и Python из `.venv`, сами выбирают каталог проекта и оставляют окно с диагностикой при ошибке. Можно создать обычные ярлыки Windows на эти файлы; их имена и назначение постоянны.

TEST выбирается в `web_alarm/launch_test_config.json`. При следующем тестовом этапе разработчик обновляет профиль в этом файле, сохраняя обе точки входа. Отсутствующая, повреждённая или переключённая на `standard` TEST-конфигурация останавливает TEST-запуск. Штатная точка входа всегда выбирает встроенный стандартный режим, независимо от активных тестовых профилей.

Сейчас TEST автоматически открывает **Web Alarm Ultra в браузере**. Адрес `http://127.0.0.1:.../` также печатается в окне запуска; порт выбирается автоматически. Для остановки нажмите **Enter в окне запуска**. Сервер завершится и удалит временные данные; тестовые чаты не сохраняются между запусками. Закрытие вкладки браузера само по себе сервер не останавливает.

Поле `args` текущего TEST-профиля содержит `["--web"]`: браузерный запуск без импорта или создания Tkinter-окна. Ultra Star/Tkinter заморожен; эта правка развивает запуск Web Alarm Ultra через существующее ядро. Изменять ярлыки или вводить параметры в терминале не требуется.

## Первый ограниченный STANDARD LIVE (подготовленный переход)

Новые изменения STANDARD предназначены для **явного подтверждения владельцем в локальном консольном окне**. Никакой HTTP-запрос, URL, env-флаг или JS-кнопка сами по себе не создают разрешение GigaChat. Без такого подтверждения действуют прежние STANDARD и история, отправка остаётся OFFLINE.

Для LIVE выводятся только зарегистрированные Workspace, у которых уже есть **проверенная Ultra-идентичность и S3a BudgetLedger**. Существующие Workspace без журнала не мигрируются и не переинициализируются автоматически: это самостоятельная задача с проверкой исходных данных. Выберите номер Workspace и введите точную фразу, которую покажет окно STANDARD. Закрытие окна прекращает серверную сессию; после истечения срока для новых отправок понадобится отдельное подтверждение при следующем запуске.

**Начальное ограничение интеграции:** лишь реально испытанная модель `GigaChat-2`, ответ версии `GigaChat-2:2.0.30.01`. За одно включение не больше 12 реальных отправок, 128 токенов ответа и 8192 байт входного wire на отправку, консервативная liability не выше 99 840 токенов, срок до 30 минут. Это не утверждение тарифа, остатка или предельного размера ответа у поставщика. Остальные пять моделей видны в каталоге, но отправка в них удерживается до отдельной проверки версий и контрактов. Автоматических платных повторов нет.

**Пока не выпуск:** локальная настройка STANDARD должна пройти независимые Windows CI, затем физический браузер/GUI, до широкого использования. TEST/Tkinter и их отдельные точки запуска не меняются. Отчёт этапа: `reports/CHATGPT-WUA-STANDARD-LIVE-ONRAMP-001/report.md`.

**Решение USER 07.11.2026:** STANDARD/TEST — две постоянные пользовательские точки Web Alarm Ultra, менять профиль TEST, а не CMD или ярлыки. Старый `Start_WebAlarm.bat` оказался пустым в №531, новые CMD от него не зависят, восстанавливать третью точку автоматически не нужно. `Start_WebAlarm_Demo.cmd` — отдельный старый изолированный WA4-O демонстрационный стенд, не текущий TEST; файл остаётся до проверки зависимостей. `Start_Ultra.cmd` открывает существующую отдельную Tkinter Ultra и сохраняется. На Windows пользователь показал параллельное открытие STANDARD с прежней историей (порт 8765) и Stage5 TEST с пустым Workspace (порт 51238); адреса не фиксированы, полная изоляция и окончательная браузерная приёмка ещё NOT VERIFIED.

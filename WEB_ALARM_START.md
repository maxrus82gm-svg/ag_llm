# Постоянные файлы запуска Web Alarm Ultra

Двойной щелчок по одному из двух файлов в корне проекта:

| Файл | Режим |
| --- | --- |
| `Start_WebAlarm_Test.cmd` | Текущий TEST-профиль. Сейчас Stage 5 OFFLINE: fake LLM, временные чаты, браузер. |
| `Start_WebAlarm_Standard.cmd` | Штатный Web Alarm Ultra с обычными постоянными данными пользователя. |

Оба файла используют существующий `web_alarm.launcher` и Python из `.venv`, сами выбирают каталог проекта и оставляют окно с диагностикой при ошибке. Можно создать обычные ярлыки Windows на эти файлы; их имена и назначение постоянны.

TEST выбирается в `web_alarm/launch_test_config.json`. При следующем тестовом этапе разработчик обновляет профиль в этом файле, сохраняя обе точки входа. Отсутствующая, повреждённая или переключённая на `standard` TEST-конфигурация останавливает TEST-запуск. Штатная точка входа всегда выбирает встроенный стандартный режим, независимо от активных тестовых профилей.

Сейчас TEST автоматически открывает **Web Alarm Ultra в браузере**. Адрес `http://127.0.0.1:.../` также печатается в окне запуска; порт выбирается автоматически. Для остановки нажмите **Enter в окне запуска**. Сервер завершится и удалит временные данные; тестовые чаты не сохраняются между запусками. Закрытие вкладки браузера само по себе сервер не останавливает.

Поле `args` текущего TEST-профиля содержит `["--web"]`: браузерный запуск без импорта или создания Tkinter-окна. Ultra Star/Tkinter заморожен; эта правка развивает запуск Web Alarm Ultra через существующее ядро. Изменять ярлыки или вводить параметры в терминале не требуется.

`Start_WebAlarm.bat`, `web_alarm/launch_config.json` и исходный JSON Stage 5 профиля остаются без изменений. В существующий Stage 5 fixture добавлен браузерный режим. Старые `Start_WebAlarm_Demo.cmd` и `Start_Ultra.cmd` относятся к другим существующим интерфейсам; для этой пары режимов используйте два файла выше.

# Постоянные файлы запуска Web Alarm Ultra

Двойной щелчок по одному из двух файлов в корне проекта:

| Файл | Режим |
| --- | --- |
| `Start_WebAlarm_Test.cmd` | Текущий TEST-профиль. Сейчас Stage 5 OFFLINE: fake LLM, временные чаты, браузер. |
| `Start_WebAlarm_Standard.cmd` | Штатный Web Alarm Ultra с обычными постоянными данными пользователя. |

Оба файла используют существующий `web_alarm.launcher` и Python из `.venv`, сами выбирают каталог проекта и оставляют окно с диагностикой при ошибке. Можно создать обычные ярлыки Windows на эти файлы; их имена и назначение постоянны.

TEST выбирается в `web_alarm/launch_test_config.json`. При следующем тестовом этапе разработчик обновляет профиль в этом файле, сохраняя обе точки входа. Отсутствующая, повреждённая или переключённая на `standard` TEST-конфигурация останавливает TEST-запуск. Штатная точка входа всегда выбирает встроенный стандартный режим, независимо от активных тестовых профилей.

Сейчас TEST автоматически открывает **Web Alarm Ultra в браузере**. Адрес `http://127.0.0.1:.../` также печатается в окне запуска; порт выбирается автоматически. Для остановки нажмите **Enter в окне запуска**. Сервер завершится и удалит временные данные; тестовые чаты не сохраняются между запусками. Закрытие вкладки браузера само по себе сервер не останавливает.

Поле `args` текущего TEST-профиля содержит `["--web"]`: браузерный запуск без импорта или создания Tkinter-окна. Ultra Star/Tkinter заморожен; эта правка развивает запуск Web Alarm Ultra через существующее ядро. Изменять ярлыки или вводить параметры в терминале не требуется.

## STANDARD и отдельный операторский LIVE (GigaChat-2, ограниченный режим)

**Начиная с №627** обычный запуск `Start_WebAlarm_Standard.cmd` сразу открывает штатную оболочку и сохранённую историю. При запуске по ярлыку **не требуется** выбирать Workspace, вводить `LIVE 12` или отвечать на приглашение о платных вызовах — даже если на компьютере настроен GigaChat. Сам по себе STANDARD не инициирует OAuth, запрос каталога или генерацию GigaChat.

Подготовленный ранее ограниченный LIVE-контур **не удалён**, но пока доступен только через **отдельное явное операторское действие**: интерактивный запуск `python -m web_alarm.launcher --standard --live` из каталога проекта с настроенной средой, затем точное подтверждение `LIVE 12`. Это временный диагностический путь, **не** новая пользовательская точка входа, и не команда для обычного запуска. Он не подходит для TEST и не может включиться из обычного CMD, HTTP, браузера или переменных среды. Будущий удобный пользовательский LIVE Start/Stop в самом интерфейсе ещё не внедрён; до этого отправка в настоящую GigaChat из обычного STANDARD **недоступна**.

После такого **явного подтверждения владельца** программа создаёт (или открывает существующие) **«Личные чаты»** в стандартном машинном каталоге данных, используя тот же Ultra Core, Workspace identity и S3a BudgetLedger **внутри**, без внешней папки проекта. Новый каталог создаётся только после подтверждения; первый диалог `Первый диалог` появляется сразу. В веб-интерфейсе личные чаты по умолчанию открываются первыми при активном LIVE, кнопка `+ Новый чат` создаёт обычные дополнительные диалоги без выбора Workspace и папки. Workspace остаются отдельной возможностью для проектной работы.

**Сохранность:** старые Workspace, включая исторический тестовый `GigaChat LIVE`, и их история остаются на месте. Не выполняется перенос, адаптация старых ledger или подмена проекта. Если предполагаемый личный каталог уже существует, но не имеет доверенной регистрации, идентичности либо аудита, REAL прекращается с диагностикой, **без очистки и повторной инициализации**. Реальная отправка разрешена только в «Личные чаты» выбранного LIVE-сеанса. В остальных Workspace можно просматривать данные, но отправка этим разрешением не открывается.

**Модели:** ограниченное включение касается только `GigaChat-2`, с уже реально наблюдавшейся версией `GigaChat-2:2.0.30.01`. Остальные пять моделей отображаются как ожидающие проверки/недоступные; их нельзя выбрать для физической отправки. При возврате с прежнего заблокированного выбора на разрешённую модель блокировка кнопки отправки снимается; устаревший запрос настроек не может восстановить запрещённый выбор.

Один сеанс: не более **12 inference**, **1 OAuth**, **1 каталог**, **128** токенов ответа и **8192** байт wire на одно сообщение, суммарная консервативная liability до **99 840**, действие до **30 минут**. Это не подтверждённая стоимость, свободный баланс или лимит провайдера. Не выполнять автоматический повтор при сомнительном исходе. При закрытии сервера grant закрывается, кроме ситуаций, требующих диагностики.

# Ротация и просмотр карточки

Правило: №18 → DOC-BLOCK1-SLOT-01@2. Штатная сдача после финального пакета — один процесс:

```powershell
python -B tools/task_slot_rotate.py finish --card "Документация/000_Задачи Codex.md" --task-id TASK-ID --no-chat-amendment --apply
```

При отдельных принятых поправках заменить `--no-chat-amendment` на `--chat-amendment FILE` для каждой. Без `--apply` — проверка без записи. `--monitor` показывает окно на один запуск; `--headless` гарантированно запускает без окна. Основная логика одна: check → dry-run → apply → readback. JSON на stdout; окно сохраняет полный JSON в адресной папке `reports/<TASK-ID>/slot_finish_<time>.json`. После добавления доказательств исполнитель обновляет manifest своего пакета. Скрипт не публикует файлы.

Скрипт получает предыдущий snapshot из служебной строки БЛОКА1.1. Точная копия есть — переиспользует без записи. Нет — сохраняет и проверяет прежде замены 1.1. Существующий отличающийся snapshot не затирает. Утраченные CHAT-ONLY AMENDMENT не восстанавливает предположением. Пути допускаются только к адресным handoff_task.md под reports, без reparse/symlinks. Исторический №001 читается только при явном --archive-001. Размер адресного файла ограничен4MiB; глобального обхода нет.

Постановка короче100 непробельных Unicode-символов запрещена: TASK_TOO_SHORT для источника либо PREVIOUS_TASK_TOO_SHORT для прежнего слота. Ожидание распознаётся до этой проверки и не является постановкой. Порог — дополнительная эвристика, не оценка содержательности; обходного --force нет.

Повторы:

- `ROTATED` — задача перенесена, БЛОК1 ожидает.
- `CLEARED_DUPLICATE_BLOCK1` — одинаковая задача уже была в1.1, очищен только повтор в1.
- `ALREADY_ROTATED` — всё уже сделано; bytes и mtime карточки не меняются.
- `NOTHING_TO_ROTATE` / `NO ROTATE` — нет допустимого источника либо guard не пройден; строка ожидания никогда не копируется в1.1.
- `MONITOR_REUSED` — запрос передан уже открытому окну; это подтверждение очереди, **не** итог выполнения. Проверить итоговое состояние/полный JSON процесса в папке TASK.

## Открыть окно статусов

```powershell
python -B tools/task_slot_rotate.py watch --card "Документация/000_Задачи Codex.md"
```

Само открытие/watch никогда не ротирует. Окно можно двигать, растягивать, прокручивать журнал и менять шрифт10–16. Видны текущие БЛОКИ1/1.1. «Обновить статус» запускает read-only check; периодическое обновление — каждые30 минут, пока окно открыто. «История(10)» показывает краткие последние запуски из локального TEMP-кэша. Это не архив постановок. Закрытие watch останавливает наблюдение; закрытие во время работы finish не прерывает запись.

## Самостоятельно завершить задачу

Откройте ярлык **«Карточка Codex — статус»** на рабочем столе → **«Завершить текущую задачу…»**. Кнопка доступна только при успешной проверке настоящей TASK в БЛОКЕ1. При ожидании, пустом слоте или ошибке она неактивна.

Окно заново проверит карточку и покажет ID, название и папку итогового пакета `reports/<TASK-ID>/`. Отметьте готовность отчёта, manifest и evidence. Явно выберите «Отдельных принятых поправок из чата нет» либо укажите все файлы поправок. Затем нажмите **«Проверить и перенести»**. Отмена ничего не меняет. Пакет в нестандартной папке закрывается CLI-командой с `--report-dir`.

Запускается тот же `finish --apply`, со всеми проверками и сохранением протокола. Окно не копирует блоки самостоятельно. `--expected-card-sha256` связывает подтверждение с показанной версией карточки: изменение даже при том же TASK ID останавливает перенос с `CARD_CHANGED`; обновите статус и проверьте заново. Отсутствие готового пакета или конфликт останавливает операцию. После успешного переноса БЛОК1 ожидает, БЛОК1.1 содержит постановку; это сдача слота, не независимая приёмка.

Одна карточка — одно окно. Повторный запуск восстанавливает/обновляет его. Если операция уже выполняется, второй процесс ротации не запускается. Краткие события показываются в окне; полные JSON — на диске. Сохранение снимков и карточки не означает публикацию или independent PASS.

## Настройки

Файл tools/task_slot_debug.json:

```json
{"enabled": false, "auto_close_seconds": 8, "font_size": 12, "refresh_minutes": 30, "history_limit": 10}
```

enabled=true — finish показывает отладочное окно постоянно при следующих запусках. false — без окна, если нет явного --monitor. Watch/ярлык всегда открывает окно по явному запросу пользователя. Успешный finish автоматически закрывается через8 секунд; кнопка «Оставить окно» отменяет автозакрытие только в текущем окне. Ошибка остаётся для просмотра. Настройка refresh_minutes действует при следующем открытии окна. Фон тёмный; синий — ожидание/уже сделано, зелёный — работа/успех, красный — ошибка.

## Ярлык Windows

```powershell
./tools/create_task_slot_shortcut.ps1
```

Создаёт на рабочем столе «Карточка Codex — статус». Pythonw определяется по PATH, пути текущей машины закрепляются только в локальном .lnk, а не в коде. Существующий чужой ярлык не перезаписывается; свойства своего читаются обратно. Ярлык открывает наблюдение; перенос возможен только через явную кнопку и подтверждение выше. Назначения новой постановки в этом окне нет.

## Веб/GitHub

Удалённый исполнитель должен реально запустить тот же Python-инструмент в разрешённой среде с актуальными файлами и сохранить протокол. Одного GitHub file API недостаточно для исполнения. Нет runtime — передать локальную команду пользователю, не переносить вручную. Облачный запуск не открывает окно на Windows. Изменения GitHub станут видны локальному watch после штатной синхронизации пользователем; автоматических Git/network действий нет.

## Назначить новую задачу через окно

Вставка текста сама не сохраняет назначение: нужно нажать «Отправить». При уменьшении формы кнопки и строка результата сохраняют место; сжимается поле Markdown, вплоть до одной строки с прокруткой. Минимальная высота учитывает переносы подсказок и текущий шрифт. В основном окне журнал также уступает место панели действий.

Если БЛОК1 **ОЖИДАЕТ НОВУЮ ЗАДАЧУ**, справа вверху доступна **«Новая задача…»**. Вставьте в большое поле полный Markdown постановки с TASK ID и нажмите **«Отправить»**. Например, строка идентификатора:

```markdown
**TASK ID:** `CODEX-PROJECT-TASK-001`
```

Вставлять заголовки и служебные маркеры всей карточки не нужно.

В форму принимается настоящая постановка, не строка ожидания: один TASK ID, не менее100 непробельных символов, до4MiB UTF-8. Сохраняются Markdown, пробелы и Unicode; нормализуются CRLF/LF, начальный BOM и завершающий перевод строки. Если проверка не пройдена, «Отправить» недоступна, причина показана под полем.

Запись проходит через ядро `assign`: новый check, сверка SHA показанной карточки, проверка WAITING, блокировка, атомарная запись и readback. Изменяется только тело БЛОКА1. БЛОК1.1 и вся история сохраняются. Занятый, пустой или некорректный слот не перезаписывается; принудительного обхода нет. Повторная отправка уже назначенной задачи отклоняется. TASK ID последней сданной задачи повторно не назначается; полного поиска по историческим архивам нет.

При ошибке текст остаётся в форме; **«Проверить слот»** обновляет проверку без потери текста. После успешной записи форма закрывается, основное окно показывает новую задачу; новую постановку поверх неё вставить нельзя. «Закрыть» до отправки не меняет карточку. Отправка только записывает задачу в Markdown-карточку — сама не запускает агента и не отправляет сообщение в его чат. Затем сообщите агенту о назначении.

Техническая команда того же действия (только по поручению пользователя):

```powershell
python -B tools/task_slot_rotate.py assign --card "Документация/000_Задачи Codex.md" --task-file "новая_задача.md" --expected-card-sha256 SHA_ИЗ_CHECK --apply --headless
```

Без --apply только dry-run. Процесс не требует финального отчётного пакета новой задачи. В локальном TEMP-каталоге окна сохраняются последние10 протоколов assignment и краткая история; это не архив постановок. Неотправленный текст существует только в открытой форме; после неудачной попытки записи её черновик также остаётся в TEMP. Права Git/GitHub и самостоятельного назначения агентами этим механизмом не расширяются.

Открыть сразу пустую форму (без отправки): `python -B tools/task_slot_rotate.py watch --card "Документация/000_Задачи Codex.md" --new-task`. Тот же guard WAITING; действующее окно переиспользуется. --new-task и --headless несовместимы.
# История по ID — дополнение 04.11.2026

Обязательный порядок для веб-планировщика: общий `000_Задачи для агента.md` → №18. Исполнитель запускает `finish` после готового report/manifest/evidence; пользователь может сделать то же через окно. Окно и CLI вызывают одно ядро.

`finish` теперь до освобождения БЛОКА 1 сохраняет `reports/<TASK-ID>/task_record.json` и выдаёт постоянный номер `H-CODEX-000001` / `H-CLAUDE-000001` / `H-ULTRA-000001`. TASK ID поручения не меняется. Номер виден в новой служебной строке 1.1, JSON-протоколе и статусе окна. Повтор использует тот же номер и не стирает независимый verdict. Ошибка сохранения истории оставляет активный слот; проверенный snapshot может сохраниться для повтора.

Старые карточки без H-номера читаются совместимо. Повторная сдача старого 1.1 не переписывает его ради номера: использовать протокол/поиск точного TASK ID. Новый TASK ID нельзя повторно назначить, если его запись уже есть в истории. Счётчики `reports/task_history_sequences.json` не удалять; пропуски после отказов допустимы, номера не переиспользовать.

Авторская сдача — `SUBMITTED / REVIEW PENDING`, не independent PASS. Скрипт не пишет короткие №001/05/06/34 за веб-координатора. После проверки координатор обновляет существующую запись через `task_history.py review`, затем `render --apply` для таблиц №001/05. FOLLOWUP, событие №06 и текущие OPEN/NEXT №34 обновляет отдельно. Подробности в №18.

```powershell
python -B -X utf8 tools/task_history.py list --agent codex --last 10
python -B -X utf8 tools/task_history.py read --id H-CODEX-000001
python -B -X utf8 tools/task_history.py --max-tokens 4000 read --id H-CODEX-000001 --part assignment --start-line 1 --lines 40
```

Ниже прежняя техническая справка. Упоминания полного №001 как места будущей записи заменены новым порядком выше; проверки сохранности постановок, прав и слотов остаются.

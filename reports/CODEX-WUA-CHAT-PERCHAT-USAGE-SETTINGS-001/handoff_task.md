# CODEX-WUA-CHAT-PERCHAT-USAGE-SETTINGS-001

**TASK ID:** `CODEX-WUA-CHAT-PERCHAT-USAGE-SETTINGS-001`

**Предыдущая задача:** `H-CODEX-000028`, P0/P1 INDEPENDENT OFFLINE PASS  
**Режим:** STRICT OFFLINE / NO LIVE LLM

## 1. Цель

Реализовать отображение токенов и пользовательские настройки отдельного чата в Web Alarm Ultra.

Использовать уже работающий маршрут:

`Web Chat → OrdinaryCoreChatService → Turn → Usage → Ultra Storage`

Не создавать новую систему подсчёта токенов. Максимально переиспользовать существующую Ultra.

## 2. Обязательный вход

Прочитать №08, актуальные №000, №34, №40, №37 §3а, №20 §5а, относящиеся OPEN/FOLLOWUP из №05, регламент тестирования №36.3 и отчёты H-CODEX-000027/000028.

Учесть:

`FOLLOWUP-WUA-ORDINARY-CORE-BRIDGE-ACTIVATION-001`

Перед работой проверить актуальный HEAD и соответствие локальных исходников. При конфликте — STOP.

## 3. P0 — счётчики токенов

Подключить к веб-интерфейсу существующую информацию о расходе Turn.

Отображать:

- Input tokens.
- Output tokens.
- Reasoning tokens — только если источник их действительно предоставляет.
- Total tokens без двойного подсчёта reasoning.
- UNKNOWN, если достоверных данных нет.

**Обязательно:** показывать статистику текущего чата, не смешивая её с другими чатами или Workspace.

Желательно сделать компактное представление:

- Расход последнего ответа.
- Суммарный известный расход текущего чата.

Использовать уже сохранённые события Turn и usage. Не создавать второй ledger и не пересчитывать повторные попытки как новые ответы.

При неполной статистике явно показывать, что общий расход известен не полностью.

В TEST-режиме подписывать данные как синтетические, чтобы пользователь не принимал их за реальные расходы GigaChat.

## 4. P1 — настройки каждого чата

Добавить в интерфейс компактные настройки:

**Контекст:**
- Значение по умолчанию: 250 000 токенов.
- Пользователь может изменить число для конкретного чата.
- Это порог будущего управляемого сжатия, а не гарантированный размер контекстного окна модели.
- Автоматическое сжатие сейчас НЕ включать.

**Ответ:**
- Значение по умолчанию: 10 000 токенов.
- Расширенное рекомендуемое значение: 20 000.
- Разрешить пользовательское изменение с проверкой положительного целого значения.
- Не объявлять число реальным ограничением провайдера, пока возможности выбранной модели не подтверждены.

Настройки сохранять в существующем хранилище соответствующего чата.

Проверить, что настройки:

1. Сохраняются после F5.
2. Не распространяются на другой чат.
3. Не сбрасываются при смене выбранной модели без предусмотренного предупреждения.
4. Не обходят ограничения и защиту настоящих запросов.

Если применение числового ограничения требует ещё не реализованной S3b-защиты, сохранять его как пользовательское предпочтение, но не объявлять применённым к физическому LLM-вызову.

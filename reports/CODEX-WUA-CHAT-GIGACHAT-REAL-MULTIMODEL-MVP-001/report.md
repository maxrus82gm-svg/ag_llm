## Что изменено

- В существующем gigachat_transport.get_access_token один общий кэш: expires_at в миллисекундах, запас 30 секунд, привязка к credentials fingerprint/account/scope/trust, сериализация refresh. Default и старые неавторизованные callers по-прежнему получают HOLD до чтения env/cache.
- gigachat_runtime.ProviderSession — серверный ограниченный допуск, не второй Chat Core. Он принимает только Python LiveApproval от доверенного владельца сервера; HTTP/env/launcher config не выдают этот объект. Реальный HTTP использует проверяемый SSLContext, hostname verification, trust_env=False, retries=0, follow_redirects=False. MockTransport подменяет только физическую сеть в TEMP и использует ту же реализацию OAuth/catalog/inference.
- Счётчики OAuth/catalog/inference и верхняя token liability фиксируются до I/O в небольшом provider-session authorization record существующего Workspace writer. Это журнал допуска, **не второй расчётный ledger**. Все inference reserve/SENT/terminal остаются в одном BudgetLedger. Single-use grant и durable account marker блокируют повторное открытие/конкурентный grant в том же Workspace. Нормальное close не обнуляет ни расход, ни историю.
- ordinary_gigachat_transport.create_real_transport теперь строит реальный adapter только при точном ProviderSession. Двойная защита не допускает сетевой клиент даже при случайно возвращающем default authority gate.
- OrdinaryCoreAdapter и TurnService адаптированы к этому транспорту. Существующие serializer, immutable request, reservation/readback, SENT/readback, final recheck, cancellation, UNKNOWN, recovery и RAW сохранены. Лимиты малого MVP: 32 messages, 2048 B/message, до 8192 B request/response, 8 s request deadline; output — минимум preference/approval/contract. Ни 250000, ни 10000/20000 не превращаются в caps API.
- STANDARD сохраняет любую из шести существующих registry-моделей в ordinary_chat_model отдельно по Chat. TEST сохраняет свой test_chat_model независимо. Показаны REGISTERED/UNVERIFIED/AVAILABLE/UNAVAILABLE; точные provider ID проверяются по явно разрешённому catalog probe. Version-bearing response принимается только из точного списка разрешённых observed IDs контракта. Принятая версия сохраняется в Turn evidence.
- Cached input теперь доходит до ledger и видимой проекции: billed total = prompt + completion, full input = prompt + precached. Reasoning остаётся вложенной частью completion. Missing остаётся UNKNOWN. Старые usage без cached читаются с прежней формой.
- HOLD/restart/close не закрывают чтение истории, последнего результата и статистики. Версия модели/ошибка отображаются безопасными статическими diagnostic codes. REAL и TEST подписаны раздельно.
- S1 census учитывает новый inference sink и общий OAuth/models sink. Существующий восьмиточечный EXPECTED_SEND_SITES, используемый S2 как исторический policy contract, сохранён. Дополнительный точный census содержит восемь LLM sinks и один OAUTH_OR_MODELS sink. AST и полный reference census закреплены в rt002_multimodel_reconciliation.json; S2 продолжает анализировать все модули, exact gates разрешают только существующий policy/ledger.

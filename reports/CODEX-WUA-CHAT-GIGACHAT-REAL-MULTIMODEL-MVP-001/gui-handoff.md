# Передача владельцу для UX-проверки

Сборка: текущие локальные исходники, fingerprints в manifest.json. AUTHOR OFFLINE-tested; independent review и owner UX PENDING. Постоянные точки: Start_WebAlarm_Standard.cmd и Start_WebAlarm_Test.cmd; обе сохранены. Закрытие вкладки сервер не останавливает.

1. STANDARD: открыть два существующих чата, выбрать разные модели из шести. Ожидается пометка непроверенного доступа; это предпочтение, REAL пока HOLD. Переключиться и выполнить F5 — выбор и настройки отдельны.
2. Проверить прежнюю историю/настройки: ничего не стирается; отсутствие usage остаётся UNKNOWN, а не нулевой стоимостью. Для реально известных cached метрик отдельно видны кэш и полный вход; reasoning внутри выхода.
3. TEST: создать два synthetic чата, выбрать разные модели, отправить Enter и кнопкой, F5/перезапуск. TEST подписан явно, ни одна реальная модель не вызывается.
4. Оценить понятность HOLD/UNAVAILABLE/UNKNOWN и сохранённой ошибки, необходимость подписей/кнопок; факт успешного fake ответа не считать GigaChat LIVE.

Не проводить API/OAuth/account probes в этой UX-проверке. Предстоящий ограниченный REAL smoke — только после независимых ворот и отдельного точного GO из live-readiness.md. Отмена/возврат: штатно остановить TEST, его TEMP очищает существующий launcher; запустить STANDARD. Кодовый откат — вернуть только перечисленные изменённые sources по проверенным исходным snapshots/версии, не откатывать пользовательские данные и не удалять ledger/authorization facts.

Native CMD/Chromium физически в этой авторской сессии не запускались: parent OFFLINE guard отклонил cmd.exe. Actual HTTP app+DOM и Tk controls тестировались отдельно в TEMP. Нужна пользовательская оценка всей функции, включая модельный выбор и сообщения, после независимой технической проверки.

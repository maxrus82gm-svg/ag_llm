# Жизненный цикл процессов

`Start_WebAlarm_Standard.cmd` запускает Python launcher и один `ThreadingHTTPServer` на loopback. TEST использует отдельный временный storage и порт; часть профилей — отдельные скрипты. `webbrowser.open` может открыть вкладку в уже существующем общем браузере, поэтому его процесс не принадлежит Web Alarm целиком. GigaChat network calls выполняются обработчиками того же сервера, не отдельным транспортным процессом.

Кнопка завершения адресована только серверу, ответившему на запрос. Его поток `serve_forever` останавливается, текущие HTTP worker threads ожидаются до 20 с, затем закрываются server socket, runtime provider session и launcher port claim. Lock аккаунта освобождается при `close()` либо ОС при аварийном выходе процесса. Состояние EVM, модельный выбор, Workspace, RAW и ledger не удаляются.

Без надёжной метки происхождения другого процесса нельзя безопасно завершать отдельно работающий TEST/STANDARD или дочерний процесс. `taskkill` по имени, убийство всех Python/Chrome и очистка портов не используются. Поведение при зависшем worker после тайм-аута остаётся PARTIAL: консоль сообщает, что исход требует проверки.

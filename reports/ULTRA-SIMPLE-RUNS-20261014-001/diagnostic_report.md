## Подтверждённые результаты по механизмам

1. **Переключатели действительно отключили вызовы** в R-039 и R-040: Planner = 0 физических вызовов, Dredd = 0, Executor = 1. Данных о вызовах отключённых ролей в этих RUN нет. Executor остаётся главным модельным исполнителем и должен вызываться.
2. **Проблема прямого режима — объём входа, а не лишний Planner:** в R-039 диагностический message_count=70, 69 provider-блоков истории, 4 системных блока и 1 tool_schema; context_chars=59213, request_total_chars=60012, prompt_tokens=13094. В R-040 71 блок истории; context_chars=59364, request_total_chars=60165, prompt_tokens=13128.
3. **Системная нагрузка даже на «привет»:** из контекста Executor в R-039 около 21231 символа приходится на четыре системных блока, в том числе global_context=16473, project_context=2573 и policy≈1867; исторические сообщения составляют ещё 33335 символов. Повторяющиеся SHA блоков: 20 дополнительных экземпляров в R-039 и 21 в R-040; это факт повторения содержимого, но ещё не доказанный дефект.
4. **Планировщик меняет состав контекста:** в R-038 при Planner ON executor_diagnostic_context: 3 сообщения; context_chars=22305, request_total_chars=23039, prompt_tokens=4413. В коде server.py выбор seed для Planner ON — только новая задача; при Planner OFF — копия active_chat_messages. Простое выключение Planner не гарантирует снижения суммарных токенов.
5. **Dredd R-033 получил необычно большой Final Audit:** context_chars=65788 (system=2875, user=62913), фактический расход 17424 токена. В R-034 при той же короткой задаче и Planner OFF: context_chars=6997 (system=2875, user=4122), Dredd=1805 токенов. Причина изменения audit user-блока пока не установлена; требуется исследовать сборку verification context.
6. **R-041 BLOCKED — защита записи сработала, а не сломалась.** Planner после одного ConnectError спланировал две стадии и потребовал создать файл hello.cpp. Executor вызвал write_file, но RUN запущен с allow_write=false и WRITE scope «Документация». События mutation_preflight_rejected → permission_denied → permission_scope_blocked → permission_escalation_terminal. Реальная запись не была произведена. Вопрос к Planner: почему «напиши мне код» интерпретировалось как обязательное создание файла при WRITE OFF вместо вывода кода в ответе?
7. **Счётчик API в интерфейсе не равен всем физическим вызовам модели:** например, у R-038 summary api_requests=1, но provider calls Planner=2, Executor=1, Dredd=1. Это важный риск неверной интерпретации метрик, а не автоматически неисправность подсчёта токенов.

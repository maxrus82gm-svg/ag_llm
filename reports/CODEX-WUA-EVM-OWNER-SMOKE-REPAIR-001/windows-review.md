# Windows / multi-monitor review

Три разных объекта: прежний `#evmPins` живёт внутри DOM; `↗` создаёт самостоятельное browser popup через `window.open`; «Поверх всех окон» создаёт Document Picture-in-Picture по явному нажатию. Перемещение DOM панели не является перемещением окна Windows. JS EVM 50/50 проверяет вызовы popup/PiP, независимые имена трёх окон, синхронизацию и негативные ветви, но не физическую геометрию ОС.

Исполнитель подготовил одноразовый локальный сервер `127.0.0.1:61052` на временном хранилище и выбрал отдельную вкладку Chrome. При попытке открыть локальный URL Computer Use остановил сеанс: не удалось достоверно определить текущий browser URL Windows для применения политики. Сервер остановлен; последующих UI-команд не было. Поэтому фактический перенос на второй монитор, перемещение PiP, topmost над другим приложением, масштаб дисплеев и F5 в физических окнах — **NOT VERIFIED**. Содержимое пользовательских окон не использовалось как доказательство работы Web Alarm.

В код добавлено объяснение, что браузерный popup следует перемещать за его **системный заголовок**, а не за HTML карточку; для Windows указан `Win + Shift + ←/→`. Для PiP пояснено, что перенос зависит от платформы. Это улучшение UX, не доказательство устранения симптома F-01. Если оба штатных способа не работают на STANDARD, зафиксировать title bar, монитор, DPI, масштаб и видео/скриншот; затем отдельно выбрать техническое решение. Новый нативный менеджер окон или сервис не создавался.

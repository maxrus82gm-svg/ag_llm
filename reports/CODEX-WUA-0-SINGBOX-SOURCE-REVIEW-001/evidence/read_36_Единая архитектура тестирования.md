По умолчанию без поручения инженерные файлы не изменяются. Самопроверка своего исправления не является независимой приёмкой. Роли Claude/Codex и их ограничения Git, scope, live/production неизменны. См. `Решение пользователя - ChatGPT тесты и правки кода - 2026-10-22.md`.

**Решение пользователя:** GitHub Actions — предпочтительная повторяемая площадка испытаний Web Alarm и Ultra на временны́х Windows/Linux runners, с фиксированным source SHA, результатами и публикационно-безопасными evidence. **Что УЖЕ есть:** `.github/workflows/web-alarm-tests.yml` использует `windows-latest` + Python 3.12, PR `paths` и ручной `workflow_dispatch` в YAML. **Что только запланировано:** новый Ubuntu/Linux job/матрица и унификация multi-OS CI, ещё НЕ реализованы. Изолированная Linux-лаборатория ChatGPT — дополнение для независимых ad-hoc проверок; постоянный Windows-стенд на сервере пользователя — FUTURE/ON HOLD.

Каждый новый ChatGPT сверяет реальную GitHub-связь, permissions, HEAD и инструментальные возможности (чтение source/test/docs/CI; публикация только разрешённой общей документации), а не предполагает, что GitHub недоступен. **Как различать проверки:** существующий `workflow_dispatch` в GitHub UI ≠ подтверждённая возможность dispatch через текущий GitHub-коннектор; прежний `rerun` проверяет прежний SHA. Новый CI запускать только штатным подтверждённым средством с `run_id`, `head_sha`, job/OS, точными FAIL/PASS/SKIP, raw evidence и отрицательными контролями. Проверять PR `paths`, не создавать фиктивные изменения/тесты ради запуска. Windows Actions не доказывает реальные WFP/native host, power loss или состояние live-storage; GitHub-hosted Linux CI не внедрено. Критичные отчёты в публичном GitHub должны проходить проверенную анонимизацию; один зелёный тест не заменяет независимую оценку oracle и исторических FAIL. Новые Linux jobs и реорганизация тестов — отдельные ограниченные инженерные TASK, не документная запись ChatGPT.



## Общий цикл: исполнитель → независимый verifier → накопленная база (2026-10-13)

**Local-first / independent-review / risk-based CI.** Исполнитель (Codex, Claude, Ultra или другой назначенный агент) читает существующий каталог тестов и профиль, определяет risk/test impact, **самостоятельно запускает доступные разрешённые локальные target/integration/regression tests**, исправляет обнаруженное, повторяет проверки и передаёт исходники, diff, точные команды, результаты, версии и raw evidence. Локальный PASS исполнителя — это `RESULT READY`, а не независимая приёмка.

**Исполнитель (Claude/Codex) самостоятельно развивает единую накопительную базу тестов:** создаёт regression/reproducer, усиливает oracle/assertions, обновляет selectors, добавляет negative controls и фиксирует покрытие/каталог. **ChatGPT-verifier проверяет эти тесты и может запросить дополнительные, но сам тестовый код не изменяет.** Не создавать параллельные частные «тесты агента» вместо общей базы. Не дублировать проверки без полезного отличия. Каждый новый/изменённый тест сам проходит review и quality/trigger checks; нельзя скрывать исходный FAIL, ослаблять oracle, silently skip/XFAIL или объявлять PASS без исполнения.

**Самостоятельная инженерная работа необходима помимо тестов:** агент до изменения читает код и формирует причинные гипотезы, после — выполняет ручной source/adversarial walkthrough алгоритмов, неблагоприятных последовательностей и краевых состояний, сравнивает raw state с контрактами и документирует выводы. Отдельный `MANUAL ENGINEERING REVIEW` обязателен перед `RESULT READY` для значимых кодовых TASK; зелёная регрессия без этого анализа недостаточна. Канон: `TEST-ENG-01@1` (36.1).

После отчёта исполнителя **ChatGPT без повторного GO начинает независимую проверку** source/diff, тестов, рисков и evidence. Если обнаружена ошибка, verifier оформляет evidence-based finding/repair TASK Claude или Codex и после самостоятельного исправления агентом проверяет новую ревизию. **ChatGPT не меняет код или тесты**, даже при наличии технического write-доступа. Координационная документация остаётся разрешённой по `DOC-ENGINEERING-ROLES-01@1`. По результатам risk matrix назначается дополнительный platform/CI/stress gate; GitHub CI — независимое подтверждение по необходимости, **не замена локального цикла** и не обязательный полный прогон для каждой мелочи. Для Windows races, recovery, safety и исторических красных CI сохранять платформенные проверки и первый FAIL с provenance. Если локальные tools недоступны, отметить `NOT RUN / BLOCKED` и использовать разрешённую альтернативу, не выдумывая local PASS.

Итог независимой приёмки привязывать к конкретному source revision, фактической collection, PASS/FAIL/ERROR/SKIP, isolation, доказательствам и открытым рискам. Общее тестовое наследие должно оставаться пригодным для следующего чата и агента. Нормативный исполнительный контракт: `36.1`, правило `TEST-COLLAB-01@1`.

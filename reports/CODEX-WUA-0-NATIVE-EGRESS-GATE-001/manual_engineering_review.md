## Reference helper order and branches

`egress_reference.py` is synchronous control-policy reference only:

1. Validated Endpoint requires literal 127.0.0.1/tcp4 and exact integer port;
   missing/hostname/UDP/v6 settings fail before API, no resolver is called.
2. Synthetic identity uses name+generation with exact types; bool is not accepted
   as generation 1. This guards a Python equality pitfall but is **not** OS process
   authentication; caller-provided tuple is not a production security identity.
3. State/membership/exact-edge checks precede socket creation. DIAL_API_INTENT is
   correlated with independent audit connect event by per-thread operation ID.
   Empty origin traffic by itself is not used as the no-attempt oracle.
4. Exactly configured upstream is dialed, no environment lookup or alternative
   endpoint. Failed connect/handshake trips the model, closes tracked sockets and
   stops future root/child calls. No auto-renewal or reconnect.
5. Child admission is an in-memory registry operation only, default refusal and
   chain trip; no subprocess launcher exists in the helper. Actual child boundary
   must be OS-derived, not this model's controller_authorized argument.
6. `trip()` closes only registered helper sockets. It cannot close a raw socket
   opened outside the helper: the intentional orphan control demonstrates this
   risk and is cleaned up by the test harness. Production must stop/deny the whole
   authenticated process scope, not trust a Python resource registry.

## Rejected shortcuts / security findings

1. Global proxy flag or a correct CONNECT adapter does not cover all native/child
   paths. Runtime NO_PROXY/default, extra transport and V2Ray DIRECT risks remain.
2. All-loopback allowance permits another local relay to internet. Exact port
   still needs trusted receiver identity; read-then-connect PID check has a race.
3. Executable-path WFP rules cannot simply be presumed to follow arbitrary child
   binaries; shared Python paths can affect other apps. Need closed OS scope.
4. PID-only scope is vulnerable to reuse; model generation checks do not solve
   actual OS lifetime/birth-time enrollment. Usermode post-launch enrollment is
   insufficient until its race is demonstrably excluded.
5. Controller/engine/session failure or early rollback can remove denial while
   processes live; existing flows may survive connect-time changes. Do not assume
   flag names establish safe lifetime, ordering or reauthorization semantics.
6. A live broker's own routing/DNS must be verified separately. OS denial for the
   client does not tell whether sing-box selects protected remote or DIRECT.
7. Air-gapped VM must exclude NIC/host-relay/integration escape channels; guest
   route list or absence of observed packets is not the enforcement proof.

These are design/acceptance conditions, not newly discovered defects in official
tunnel-client or installed Windows. Changes to live policies are outside scope.

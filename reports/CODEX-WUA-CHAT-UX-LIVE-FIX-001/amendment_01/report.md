## Что изменено

- «+» и действие создания разрешены для `ok` и `missing_history`; остальные состояния остаются недоступными для создания. Форма первого чата явно сообщает, что нажатие **«Создать первый диалог»** создаст хранилище Ultra и чат. Открытие формы/отмена ничего не записывают. Запрос формируется только по submit, с отдельным write-token и флагом `initialize_workspace: true`.
- API принимает этот флаг только как точное JSON `true`. Без него папка без истории по-прежнему получает отказ. Невалидные title/ID/body и запросы без правильной авторизации не инициируют storage.
- Для `missing_history` preflight повторно проверяет зарегистрированный canonical root и допускает только отсутствующий либо совершенно пустой каталог `.ultra`. Непустой `.ultra` без identity — случай восстановления, а не право создавать новый ID; orphan/повреждения/ссылки не переинициализируются. Обычные файлы проекта при этом разрешены и сохраняются.
- После такого preflight вызывается существующий `context_storage.create_chat_record(..., expected_workspace_id=None)`. Он валидирует title, выполняет прежний `ensure_workspace_storage`, затем создаёт чат через общий writer с блокировкой и публикацией. Собственного формата или второго писателя нет. Для уже существующей identity сохраняется прежний путь с `expected_workspace_id`, включая ownership и no-follow проверки.
- После подтверждённого первого create перечитывается каталог Workspace, затем список и история. Новый чат выбран и показан, статус становится `ok`, дальнейшие чаты создаются обычным путём. При потере ответа форма сохраняет тот же `chat_id` и согласие; явный повтор не создаёт дубль и не меняет identity.

## Причины, RED и исправления

1. **Потеря DOM-узлов.** Формы Workspace/диалога, состояние и список чатов переносились внутрь раскрытого дерева. Сворачивание через `replaceChildren` удаляло их из документа. Следующий `getElementById` возвращал `null`; `append` преобразовывал четыре значения в буквальное `nullnullnullnull`, а обращение к полям/формам вызывало TypeError. Прежний адаптер тестов всегда возвращал ID из словаря, даже после удаления из DOM, и не моделировал перенос узлов. Теперь адаптер учитывает родителей, отсоединение, перенос и преобразование аргументов `append`. В продукте четыре узла сначала переносятся в существующий подключённый скрытый `chatListDock`, затем помещаются в раскрытую группу. При сворачивании они остаются подключены к документу. Обновление сохраняет свёрнутое состояние и выделение.
2. **Ложная ошибка регистрации.** После подтверждённого POST `/workspaces` выполнялась загрузка дерева/диалогов. В описанном состоянии она падала на потерянном `chatListState`. Возвращённый без `await` Promise из `loadChatWorkspaces` выходил за его `try/catch`; общий `catch` создания выдавал «Не удалось создать Workspace», хотя регистрация уже сохранилась. RED сохраняет одновременно факт POST и ошибочное сообщение. Теперь подтверждение подключения показано отдельным статусом, ошибки каталога/диалогов/истории сообщаются отдельно. Отказ 4xx отделён от неподтверждённого результата POST (потеря ответа, 5xx, неверный ответ). Автоматической повторной регистрации нет. HTTP-тест повторной регистрации подтверждает прежний ID и одну запись.
3. **Переименование Workspace и диалога.** Исправление DOM сохраняет доступность обеих форм после сворачивания, обновления и переключения. Карандаш другого диалога теперь выбирает его через штатную загрузку истории; раньше менялся ID, но оставались сообщения прежнего диалога. Формы взаимно закрываются, запоздалые действия проверяют целевой Workspace/чат, редактор ожидающего сохранения скрывается при смене Workspace. Переименование Workspace обновляет и подпись выбранного объекта. При конфликте перечитывается имя, введённый текст остаётся, а замена нового имени требует отдельного второго Save. При провале перечитывания UI прямо сообщает об этом. Ошибка транспорта не объявляется доказанным отсутствием записи.
4. **Дополнительный подтверждённый случай.** Запоздалый плюс другого Workspace мог открыть форму уже в новом выборе пользователя. Добавлена проверка совпадения выбранного Workspace перед открытием. Отдельный RED сохранён.

Серверные endpoint, Host/Origin/read/write-token проверки и общие писатели Ultra не менялись. Переименование Workspace изменяет только его отображаемое имя в прежнем реестре. ID, путь, исходная Ultra и история сохраняются. Папка без истории возвращает `missing_history`; регистрация/чтение не создают `.ultra`, а создание диалога там получает `workspace_unavailable`. Отправка сообщений остаётся отключена; Stage 3, Turn и LLM-запросы не запускались.

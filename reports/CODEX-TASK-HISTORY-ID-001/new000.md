# Рабочий вход веб-планировщика ChatGPT

Редакция 04.11.2026. **Этот общий №000 — инструкция веб-планировщику**, а не персональное поручение Codex. Основной регламент — №18. Новая архитектура: полные задачи хранятся отдельно, №001/05 содержат короткие строки с ID. Старый порядок копирования полной истории сюда больше не применять.

## Ваши действия

1. Вход: №08 → этот документ → текущие №34/40 → все открытые FOLLOWUP №05 → рабочий порядок №18. Чужие архивы и все зависимости правил на старте не читать.
2. Новая задача: подготовить пользователю три блока — полную постановку с TASK ID, короткий запуск, объяснение результата. Пользователь назначает её в БЛОК 1. Рабочее поручение не переписывать; уточнения — отдельные AMENDMENT с тем же ID.
3. Сдача: исполнитель либо пользователь запускает `tools/task_slot_rotate.py finish`. Программа использует то же ядро. Скрипт сохраняет точный snapshot и запись, выдаёт постоянный HISTORY ID, затем переносит БЛОК 1 в 1.1. Повтор сохраняет номер. Не переносить слот вручную и не придумывать результат запуска.
4. Приёмка: после публикации взять HISTORY ID и `record` из БЛОКА 1.1/протокола. Открыть только `reports/<TASK-ID>/task_record.json`, затем нужные sources по путям и SHA. Старую 1.1 без номера искать по TASK ID; если записи нет, поручить сохранение. Нельзя выдавать новый H-номер вручную.
5. Проверить исходники/evidence в разрешённом scope, сохранить собственный review с точной версией, PASS/PARTIAL/REVISE/FAIL/BLOCKED и NOT RUN. Авторские тесты не называть собственной независимой проверкой. Собственную инженерную правку независимо принимает другой verifier.
6. Обновить verdict существующей записи через `task_history.py review`; выполнить `render`, получив короткие №001/05. Сохранить все OPEN в FOLLOWUP, короткое событие с обоими ID в №06 и текущий итог/NEXT в №34. №40/профили менять только при влиянии на них. Уже освобождённый слот не трогать повторно.
7. Проверить чтение по ID и сохранность источников. Пользователь принимает публикацию GPT → main и синхронизирует локальную копию. Следующая TASK не назначается автоматически из результата прошлой.

## Самое важное о формате

- **TASK ID** — имя поручения до работы; сохраняется.
- **HISTORY ID** — номер `H-CODEX-000001`, `H-CLAUDE-000001` или `H-ULTRA-000001`; выдаёт скрипт при сохранении, повтор не создаёт новый.
- **№001 исполнителя** — десять последних строк: дата, оба ID, понятное название, статус и адрес записи. Ни одного полного задания/отчёта.
- **№05** — те же ID в общем индексе и все незакрытые FOLLOWUP/риски. Ограничение десяти строк не распространяется на OPEN.
- **Папка задачи** — полные исходники поручения/поправок и результата. Запись `task_record.json` хранит их адреса, хеши и отдельный review. Ничего не восстанавливать по памяти вместо точного источника.
- Старые BP-ID в №43.1/43.2 остаются действующими; при связи с инженерной задачей добавить ссылку, не переименовывать старые записи.

## Если веб не может запустить скрипт

Готовую запись читать через доступный файловый инструмент по точному пути. Результат проверки можно внести в существующую запись и короткие строки с уже выданным ID, сохраняя прежнюю версию метаданных. Отсутствующее сохранение/номер/ротацию поручить локальной среде с точным TASK ID и командой из №18; явно отметить **SCRIPT EXECUTION REQUIRED**. Наличие файлового API не означает выполненный Python. Публикация не обновляет файлы Windows автоматически.

## Команды адресного чтения

```powershell
python -B -X utf8 tools/task_history.py list --agent codex --last 10
python -B -X utf8 tools/task_history.py read --id H-CODEX-000001
python -B -X utf8 tools/task_history.py --max-tokens 4000 read --id H-CODEX-000001 --part assignment --start-line 1 --lines 40
```

Не читать полную папку, весь №001/06 или архив ради одного ID. При ошибке адреса/хеша/бюджета остановить зависимое действие и получить точный фрагмент. Бюджет, источники, команды сохранения/review/render, права и обработка ошибок — №18. Полный каталог дополнительных правил не является маршрутом входа.

## Постоянные границы

Git/GitHub локальных исполнителей без отдельного разрешения запрещены. Веб использует только свои реально подтверждённые права; USER GO нужен для расширения scope и технических изменений, paid/live/production, merge и новых этапов. Не менять чужие активные задачи и не ослаблять storage/backup/rollback/изоляцию. Исторический PASS не отменяет современные OPEN. Действуют B2/WA4-R/portability/MCP freeze. INDEPENDENT_PLAN до разрешённого перехода не читает этот общий маршрут и чужие оперативные данные.

Для прямого поручения без активного слота есть `task_history.py register`; не освобождать чужой/прежний БЛОК 1. Перед новой TASK и сменой чата заново проверять FOLLOWUP; назначенный successor не означает закрытый вопрос. Результат пользователю: что сделано, что реально проверено, что осталось открытым и какой NEXT разрешён.

# Вход в проект ag_llm / Web Alarm Ultra

Редакция 04.11.2026. **Новая история по ID:** №001 — последние десять названий и ID, полные задачи — в папках reports. Общий `000_Задачи для агента.md` объясняет работу веб-планировщика; №18 — порядок ведения документации. Начинать с них, а не с архивов.

## Сначала определить роль

- **Веб-планировщик / ChatGPT-координатор:** назначение готовит для пользователя, независимо проверяет опубликованную сдачу, ведёт записи и индексы по общему №000/№18. Собственную правку не принимает как независимый verifier.
- **Codex / Claude / Ultra Desktop:** собственные Правила и конкретное поручение в БЛОКЕ 1 либо прямой запрос пользователя. Чужие задачи, полные истории и все нормы автоматически не загружать.
- **INDEPENDENT_PLAN:** только разрешённый изолированный вход. До разрешённого перехода не читать общий №000, №34/40, чужие планы/слоты/пересказы, №28.1 и оперативный №33. Получить assignment, mode, participant/model/context_id, read/write-scope, rule_set_ref и input_manifest_ref. Если источник нельзя отделить — SOURCE_UNAVAILABLE. Уже увиденное нельзя объявлять неувиденным; автоматическая blind-изоляция не заявляется.

## Обычный вход веб-планировщика

1. Этот №08 → действующая часть общего **000_Задачи для агента.md**.
2. №34: текущая картина до «Сохранённые адреса прежней редакции»; №40: свежая шапка, занятость и пересечения направлений. Старые датированные состояния не выдавать за текущие.
3. №05 → **«Очередь открытых продолжений (FOLLOWUP)»**, все актуальные OPEN/UNASSIGNED и переходы successor. Короткий индекс читать только если нужны прежние задачи. Весь прежний реестр не нужен.
4. №18 → «Прочитать сначала», «Кто и когда запускает сохранение», «Порядок веб-планировщика». Перед конкретным действием — относящееся правило; весь каталог дополнительных правил и requires на старте не раскрывать.
5. Если поручение техническое: №01 как карта → один нужный профиль → применимые контракты №36/36.1 и №36.2 либо №36.3. Для документации — смысл, сохранность, адреса и граф; запуск продукта не требуется автоматически.

В конце входа кратко назвать цель, поручение, текущую точку, OPEN, участников и разрешённый NEXT. Непрочитанное/недоступное — UNKNOWN. Для обычного координатора общий №000 и очередь FOLLOWUP обязательны; при недоступности не выдавать новую TASK, не объявлять очередь пустой. Память прошлого чата не заменяет проверку изменившихся источников.

## Как теперь сдаётся и сохраняется задача

TASK ID существует до работы. Когда итоговый report/manifest/evidence готовы, исполнитель или пользователь запускает **`tools/task_slot_rotate.py finish`** для этого TASK ID. Программа через окно вызывает то же ядро. Скрипт:

1. Проверяет назначение, отдельные AMENDMENT и сохранность предыдущего слота.
2. Сохраняет дословный snapshot, создаёт/переиспользует номер **HISTORY ID** и `reports/<TASK-ID>/task_record.json`.
3. Проверяет запись, переносит БЛОК 1 в БЛОК 1.1 и освобождает БЛОК 1. В новой 1.1/протоколе видны номер и адрес.

Повтор не создаёт новый номер; ошибка сохранения не разрешает очистку. Вручную переносить/очищать нельзя. Без Python — SCRIPT EXECUTION REQUIRED, а не заявление о выполнении. Прямое поручение без своего активного слота сохраняется через `task_history.py register`; прежнюю чужую TASK ради этого не ротировать.

**После публикации веб-проверяющий открывает одну запись по HISTORY ID**, проверяет источники и добавляет свой verdict. Затем обновляет краткие №001/05, все FOLLOWUP, событие №06 и текущий №34. Автоматическая сдача не является independent PASS или публикацией. Полные постановки и отчёты обратно в №001/05 не вставлять.

## Как читать историю

```powershell
python -B -X utf8 tools/task_history.py list --agent codex --last 10
python -B -X utf8 tools/task_history.py read --id H-CODEX-000001
python -B -X utf8 tools/task_history.py --max-tokens 4000 read --id H-CODEX-000001 --part assignment --start-line 1 --lines 40
```

Первый вызов выводит только названия/ID. Второй — метаданные одной записи. Третий — выбранный кусок полного поручения. Пути и parts брать из записи; неизвестный ID или превышенный бюджет — отказ, не чтение целого архива. Начальный ориентир суммарного чтения — 12 тысяч токенов; дальнейшее чтение обосновать текущим действием. Лимит инструмента — на один вывод, не на весь чат. Старые №001/05 сохранены отдельно и не являются обязательным входом.

## Обязательные границы

Пользователь назначает и расширяет TASK; три блока постановки готовит координатор, БЛОК 1 назначает пользователь. Локальным Claude/Codex Git/GitHub, включая чтение, запрещены без отдельного адресного разрешения. Публикация, GPT → main, live/paid/production и новый этап требуют собственных полномочий. Собственный результат не является независимой приёмкой.

Один Start_WebAlarm.bat; после разрешённого TEST вернуть и проверить STANDARD, иначе RESTORE_BLOCKED. Не менять чужой shared scope, живое storage, права ОС, backup/rollback или изоляцию побочно. B2, WA4-R, EVM/Windows/portability и freeze MCP №39 не сняты. Технические действия требуют применимых тестовых контрактов и честных FAIL/NOT RUN. Канонические подробности безопасности — №18 → точные файлы правил.

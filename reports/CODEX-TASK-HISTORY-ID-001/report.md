## Скрипты и номера

`tools/task_history.py` предоставляет register/list/read/review/render/validate. Запись живёт в `reports/<TASK-ID>/task_record.json`; источники адресованы по путям/SHA, большие старые фрагменты — диапазонами. Состояния автора и независимой проверки раздельны. История изменений метаданных сохраняется в previous.

HISTORY ID имеет вид `H-CODEX-000001`, `H-CLAUDE-000001`, `H-ULTRA-000001`; TASK ID не переименовывается. Счётчики хранятся в `reports/task_history_sequences.json`. Глобальная блокировка, атомарная запись и монотонный счётчик защищают от дублей; пропуски после сбоев допустимы. Счётчик не откатывается при удалении последней записи.

`tools/task_slot_rotate.py finish` сохраняет запись ДО освобождения слота. Новая служебная строка БЛОКА 1.1, JSON-протокол и окно показывают номер. Повторная сдача переиспользует номер и сохраняет уже имеющийся review. Если история не записалась, БЛОК 1 не освобождается; snapshot может остаться для безопасного повтора. При конкурентном резервировании номера операция требует повтора без очистки слота. При несовпадении HISTORY ID/пути в 1.1 с записью — отказ. `assign` не позволяет повторно использовать уже зарегистрированный TASK ID.

`tools/task_slot_monitor.py` вызывает то же ядро, показывает номер истории и сохраняет его в локальном протоколе окна. Это не публикация и не независимая приёмка. Самостоятельный полный GUI-прогон окна после изменения текста NOT RUN; проверены код, команды и синтетические сценарии ядра.

`read` выдаёт одну запись/одну часть/явный диапазон либо ничего. Бюджет по умолчанию 8 000, максимум 20 000 на весь вывод. При tiktoken считается o200k_base; без него применяется консервативная верхняя граница по UTF-8-байтам. Тело источника не попадает в list. При неверном ID, границах, хеше или лимите архив не печатается. Это ограничение одного ответа инструмента, не глобальная защита от всех возможных shell-команд.

## Ограничения и дальнейшее сопровождение

- Исторические результаты при миграции не переоценены. Их verdict/scope остаются в исходных фрагментах; текущие индексы явно маркируют историческое происхождение.
- Ранее существующие ссылки на полные записи №05/001 могут требовать обращения к точному сохранённому снимку. Новые записи используют оба ID и прямой путь к task_record.json. Нет автоматической переквалификации всех древних задач в новый каталог.
- `render` пересобирает только отмеченные таблицы. FOLLOWUP, №06, №34, №40 и профильные документы обновляет координатор после реальной независимой проверки. При сбое между заменами таблиц повторный render восстанавливает их; записи задач не удаляются.
- Веб без Python работает с уже выданными ID/путями и поручает локальное сохранение/валидацию доступной среде. Новый номер вручную не выдаёт, завершение скрипта не имитирует.
- Существующую проблему NO_TASK_ID в активной карточке Claude должен разрешить её владелец по точному назначению. Обход защиты или угадывание ID не добавлялись.
- Независимая приёмка и публикация этого изменения ещё не выполнены. Новые этапы продукта, live/paid, смена системных прав и чужих задач не запускались.

# Manual engineering / adversarial source review

Codex 007, 2026-10-21. Это отдельный source/architecture self-review, не независимая приёмка WEB_11. Прочитаны local contracts, прежний PoC, API dispatch/status/context, SDK2 signatures/stdio source, предыдущие WFP/route ограничения и новые core/channel/worker/server/route/contracts/tests/шаблоны. Не запускались старые Git-зависимые тесты, Go, WFP/installer или рабочий V2Ray.

## Находки и решения

**F1 — hidden asyncio TCP / BLOCKER.** Проверка не остановилась на зелёном SDK: установленный socket.socketpair — `_fallback_socketpair` AF_INET, AF_UNIX отсутствует; ProactorEventLoop._make_self_pipe вызывает его. Отдельный собственный loopback probe реально зафиксировал bind127:0 и connect к динамическому порту, отличному от зарезервированного P. Python guard специально начинает действовать после инициализации loop; выдавать это за startup containment нельзя. При намерении C-only-P current Python SDK-child несовместим. Никакой WFP-правки, native verdict или dynamic-port range не делали. Предпочтён будущий C-owned no-TCP relay ↔ local authenticated pipe ↔ server-owned SDK/API U. Его implementation/peer proof ещё отсутствуют, это BLOCKED, а не «решено настройкой». Отвергнуты undocumented monkeypatch event-loop internals и установка отсутствующего Trio без разрешения.

**F2 — настоящий V2Ray egress owner / BLOCKER.** B wrapper→host-user SOCKS не переносит B rules на процесс V2Ray. Само существование 127.0.0.1:10808 не доказывает ни владельца, ни CONNECT, ни remote route. Даже V2Ray под B добавляет B→localS edge, которого нет в прежней B-only-R:Q модели. Выбран один будущий layout: отдельный V2Ray native HTTP CONNECT inbound P под actual B token, затем только R:Q. Текущие profiles/processes не читали/не меняли. Поддержка выбранной версии и отсутствие DIRECT/resolver/fallback требуют отдельного evidence.

**F3 — STDIO/API authority.** Реальная работа MCP не означает право читать storage напрямую. Worker самостоятельно создаёт новый root, владеет WebAlarmApi и HMAC/session/scope authorization, а adapter видит только bounded read protocol. Реальные task roots не принимаются; POST только fixture setup до baseline, runtime только два fixed GET. Production gateway должен жить у существующей server authority и иметь Windows peer/DACL + реальный TASK grant. Текущий fixture worker не разрешается использовать для открытия production. Reusable boundary реализована, production connector не выдуман.

**F4 — initial NUL refusal / FIXED.** Initial `mcp01`/`mcp02` завершились до initialize: файловый audit guard запрещал subprocess.DEVNULL (`os.devnull`). Разрешён только literal reviewed null-device stderr sink; общий запрет записи вне нового fixture root не снимался. Ошибки сохранены, диагностические пути редактированы до `<REPO>/<PYTHON>`; ранний redacted stderr был недостаточен для причины, добавлены только безопасные class/code. Это один исправленный defect, не две независимые неисправности сервера.

**F5 — cleanup brackets / FIXED.** Source review выявил, что исключение при channel startup могло обойти runner.close. Вынесены вложенные finally: own channel закрывается, runner освобождается даже при ошибке cleanup. Проверены API EOF/error/terminated child/replay/bad MAC и oversized real MCP frame; SDK restart и read-only OpenProcess(SYNCHRONIZE)/WaitForSingleObject для полученного PID подтверждают завершение **собственного** MCP process, API receipt — завершение собственного worker/reader. Это не Windows SID/token proof и не native supervisor. Никаких чужих процессов/служб не останавливали.

## Проверенные атаки / оставшиеся границы

|---|---|
| Чужой TASK, traversal, unknown operation/extra field/type | MCP callback и API worker независимо ограничивают operation/TASK; strict JSON, UUID/replay/quota, additionalProperties=false; generic bounded errors. Не дают system/file/Git/model API |
| Подмена nonce/session/context/storage digest | Adapter проверяет API response binding; negative response substitutions закрывают канал и worker. SDK independently пересчитывает content hash и fixture tree hash; nonce совпадает с заранее заданным synthetic goal |
| Forged auth / replay | Valid-MAC wrong scope/write и wrong-MAC/replay проверены напрямую на отдельном worker. MAC keys одноразовые, bootstrap удалён в finally; они не real credentials. HMAC pipe fixture не доказывает production peer identity |
| Partial/large input/output | MCP stdin wrapper проверяет byte/depth/items/type/duplicate-key limits до SDK parser; SDK ведёт настоящий MCP. Actual oversized raw MCP frame вызывает bounded stop. API queue/line/response/time bounds; own child reaped. Tests не доказывают все DoS/OS scheduling cases |
| DIRECT/secondary/NO_PROXY/env | Route simulation имеет один dial к P, broker — один к S, fakeSOCKS — к owned receiver; no DNS/retry/secondary. Ambient overrides явно отклоняются до dial. Independent role observer проверяет attempts/receipts и намеренно ловит unexpected owned-loopback edge. Это Python fixture boundary, не Go/WFP/whole-host guarantee |
| CONNECT/SOCKS failures | Closed listeners, timeout, abrupt EOF, malformed SOCKS, refusal; no CP receipt и никаких других recorded role edges. HTTP redirect/oversized body отклоняются. Реальная TLS/OpenAI/proxy-health semantics Go не испытаны |
| Port takeover | Owned fake listener на прежнем P возвращает неправильную authority nonce, клиент отказывается. Это fixture oracle; production bind ownership, effective token, TLS и reauthorization не доказаны |
| Broker/child wrong SID/owner/startup pin | Pure contract rejects same/UI/builtin/foreign-machine SID, unknown/wrong-owner/hash child, endpoint/layout mismatch, unsigned config changes. Три строки SID — не LookupAccountSid/AccessToken/ACL proof; реальные accounts не исследовались/не создавались |
| Fake proof / all approvals true | preflight ignores untrusted evidence; can_apply/can_start_tunnel всегда false. Нет activation executor. Synthetic PASS и настоящий SDK result не снимают старые барьеры |
| IPC-mediated escape / DNS system services | WFP C/B socket predicates не закрывают произвольный pipe/BITS/COM/SYSTEM resolver. Server-owned pipe read API не должен делегировать network/file/process operations; другие IPC-каналы требуют отдельного native/T2 gate. U/UI не покрыты двумя SID |
| Shared files / path races / host compromise | Fresh TASK roots, local/reparse/recall checks, no arbitrary root selector, minimal environment и protected source hashes. Доверенные installed SDK/OS/filesystem/launcher — TCB; file checks не race-free против локального администратора. Не объявлена hostile-native sandbox |
| Secrets/env/children | Final runner sanitizes parent environment; SDK's built-in safe-inherit defaults therefore receive no proxy/token profile from test parent. Worker env отдельный minimal. Native Go child env/secret inheritance и все companions ещё требуют source audit; данные templates не обеспечивают OS enforcement |

## Oracles и мутации

SDK client импортирует официальный `mcp.ClientSession`, не вызывает handler напрямую. Persistent fixture bytes и independently заданный nonce/hash проверяются отдельно от заявления adapter. Route receiver independently формирует correlation receipts, observer фиксирует попытки до dial и не доверяет возвращённому `direct_attempts=0`. Один intentional unexpected-loopback контроль PASS только при обнаружении нарушения; финальные normal fault cases не имеют необъяснённых violations. Для bad-route mutation положительный маршрут перестаёт достигать independent receiver и тест падает; для bad-owner mutation тест обнаруживает пропущенный V2Ray ownership predicate. По одному targeted test на mutation, оба inner exit1/1FAIL/0ERROR, это не искусственно удвоенная полная suite.

Модель прежнего WFP оставляет selected edge unmatched, не создаёт overriding allow. Explicit Windows block/allow precedence, ALE types/byte order, listeners/accepted flows, SID inheritance/impersonation/delegation, IPv6/DNS/BFE/boot и existing flows не проверялись. Старые core/installer flags и файлы read-only; их прошлые PASS не объявляются новым native verdict.

## Вывод

Работающий local MCP integration и synthetic strict-route checker готовы для независимой проверки. Найденные hidden-runtime и V2Ray-owner конфликты честно блокируют production. Ближайшее исправление — отдельная инженерная TASK на no-TCP C relay + server-owned pipe peer, затем выбранный dedicated B engine/source review и lab native gates. Никакие широкие permissions, host network changes или hosted activation не требуются для принятия текущего offline результата.

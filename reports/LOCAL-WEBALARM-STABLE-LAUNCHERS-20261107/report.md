# Локальная правка стабильных запусков Web Alarm Ultra

Итоговый режим: **Web Alarm Ultra в браузере**. Ultra Star/Tkinter заморожен согласно уточнению пользователя. Из существующего Stage 5 используются готовые Web API, fake-транспорт, Turn и временное хранилище. Tkinter-интерфейс не дорабатывался; финальный TEST-режим не импортирует `ultra_ui`/`tkinter`.

Постоянные точки входа в корне: `Start_WebAlarm_Test.cmd` и `Start_WebAlarm_Standard.cmd`. Двойной щелчок; текущий каталог не важен. Оба файла — ASCII/CRLF, используют `.venv` и существующий `web_alarm.launcher`, при ошибке показывают диагностику и `pause`. TEST выбирается отдельным `web_alarm/launch_test_config.json`; менять ярлыки при следующих этапах не требуется. Сейчас там существующий Stage 5 fixture с аргументом `--web`. Остановка Web TEST — **Enter в окне запуска**, после чего временные чаты удаляются. Закрытие браузерной вкладки само по себе сервер не останавливает.

В существующий launcher добавлены явный `--standard` и запрет перехода TEST в штатный режим `--require-test`. Отсутствующая, повреждённая или выбранная как `standard` TEST-конфигурация останавливает запуск. В существующем Stage 5 fixture добавлен `--web`: открытие браузера и уже существующий жизненный цикл Web-сервера с остановкой через stdin. Повторного ядра, хранилища или сервера реализации не добавлено.

## Реальные проверки

- Финальная регрессия `test_web_alarm_launcher`: **19 PASS, 1 FAIL**, без пропусков. FAIL воспроизведён до изменения launcher: `BatTests.test_t1...` обнаруживает пустой `Start_WebAlarm.bat` (0 байт). BAT оставлен без изменений по прямому требованию пользователя. Исходный FAIL и полный финальный вывод сохранены. Включены четыре новые проверки выбора режима/отказа небезопасного перехода.
- Отдельный оракул браузерного жизненного цикла: исходный fixture — **FAIL**, `browser opens=0`; исправленный — **PASS**: браузер вызывается один раз, HTTP 200/OFFLINE, импорт Tk запрещён тестом, Enter завершает сервер, временное хранилище удалено. Сначала обнаружена особенность argparse: старый `--web` воспринимался как сокращение `--web-smoke`; первоначальный `web_mode_red.txt` фактически содержит успешный probe, а не RED. Его код 0 не переименован в ошибку; настоящий RED — `web_browser_baseline.*`.
- Финальный `.cmd` реально выполнен через CMD из `%TEMP%`: существующий профиль, временная папка `stage5_тест_*`, Web HTTP 200 с `data-stage5-offline="true"`. Автоматически открылось окно Chrome `Web Alarm Workspace - Google Chrome`, Tk TEST-окон не обнаружено. Отправлен Enter через stdin, **exit 0**, временная папка удалена. Полный stdout/stderr сохранён.
- До уточнения Web-only также проверено открытие `.cmd` через Windows ShellExecute из `%TEMP%` (тот же механизм системного открытия файла, без клика Explorer): **exit 0**. Этот ранний запуск использовал прежний двухинтерфейсный профиль; финальный Web-only запуск проверен отдельно, как описано выше.
- Негативная проверка отсутствующего Python: понятное сообщение, процесс ждёт ввода, затем **exit 1**. Проверка из другого каталога с путём, содержащим пробелы, кириллицу и `&`.
- Компиляция изменённых Python-файлов и ASCII/CRLF обоих CMD — PASS. Штатное ядро проверено существующими self-test тестами с `LOCALAPPDATA` во временной папке; отдельный живой стандартный UI с реальными данными не запускался.

## Данные, доказательства и ограничения

Сравнение **764 защищённых файлов**, включая `.ultra`, пользовательские чаты, `.obsidian` и штатный `%LOCALAPPDATA%/WebAlarmWorkspace`: изменений/добавлений/удалений нет. `Start_WebAlarm.bat`, стандартная `web_alarm/launch_config.json` и исходный JSON Stage 5 профиля совпадают с baseline по SHA-256. Сетевые проверки Python ограничены loopback существующим guard; реальные LLM/OAuth/Colibri/B2 не вызывались. Git/GitHub не использовались; коммитов/публикации нет.

Новый код `review_fixture.py` находится внутри прежнего Stage 5 пакета, поэтому прежний manifest продолжает описывать его историческую ревизию. Старые manifest/логи не менялись. Точный исходный fixture сохранён здесь как `review_fixture.py.before.txt`; исходный launcher — `launcher.py.before.txt`. Снимок тестового файла сделан уже после добавления четырёх RED-тестов; он не объявляется исходным состоянием до всех правок.

Визуальный осмотр страницы Chrome остановлен Computer Use: инструмент не смог уверенно определить URL для применения своей политики. После остановки UI-действия прекращены. Полный визуальный browser PASS не заявляется; подтверждены HTTP, автоматическое появление Chrome, отсутствие Tk и нормальная остановка. Проверочный сервер завершён.

Это отдельная небольшая локальная UX-правка по текущему запросу; карточка задания и история слотов не изменялись. Инструкция пользователю — `WEB_ALARM_START.md` в корне.

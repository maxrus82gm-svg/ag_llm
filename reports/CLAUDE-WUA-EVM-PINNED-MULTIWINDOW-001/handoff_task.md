# TASK: EVM — независимые закрепляемые окна для сравнения моделей

**Исполнитель:** Claude 008  
**Проект:** Web Alarm Ultra / `ag_llm`  
**Направление:** А — EVM / Ultra Chat UI  
**Предыдущая задача:** `CLAUDE-WUA-EVM-INTERACTION-DND-001`  
**Идея развития:** `FUTURE-EVM-PINNED-COMPARE-001`  
**Статус:** новая пользовательская задача, приступить после синхронизации принятой документации №465.

## 1. Цель

Развить существующий боковой предпросмотр EVM в систему независимых, свободно перемещаемых окон.

Пользователь должен иметь возможность открыть несколько моделей одновременно, расположить их рядом или в разных частях экрана, изучать характеристики и в дальнейшем сравнивать визуальную статистику.

**Главное правило: каждую модель можно закрепить только один раз, и закреплённое окно остаётся открытым до явного нажатия собственной кнопки закрытия «×».**

Новая механика должна развивать, а не заменять уже принятую реализацию №464.

## 2. Взаимодействие с окнами

### 2.1. Ctrl + наведение

Сохранить быстрый предпросмотр:

- Ctrl + наведение на карточку показывает подробное окно сбоку.
- При переходе к другой карточке меняется содержимое временного предпросмотра.
- Временное окно располагается поверх всех закреплённых окон.
- Отпускание Ctrl закрывает только временное окно, не затрагивая закреплённые.
- Если модель уже закреплена, не создавать её вторую временную копию. Можно визуально выделить существующее окно и вывести его вперёд в пределах слоя закреплённых окон.

### 2.2. Превращение предпросмотра в независимое окно

Когда пользователь нажимает на временное окно предпросмотра:

1. Это окно становится закреплённым.
2. Оно перестаёт следовать за исходной карточкой.
3. Появляется доступная для перемещения область заголовка.
4. Окно сохраняет полный функционал карточки.
5. Его можно перетащить мышью в любое удобное место внутри рабочей области приложения.

Альтернативные команды Ctrl + клик по карточке и кнопка «⧉» также должны закреплять или активировать окно соответствующей модели.

### 2.3. Несколько окон одновременно

- Допускаются несколько закреплённых окон разных моделей.
- Каждое окно имеет независимые координаты, фокус и кнопку закрытия.
- Открытие новой модели не закрывает ранее закреплённые.
- Повторное открытие уже закреплённой модели не создаёт дубль, а активирует существующее окно.
- Для идентификации использовать стабильный `connection_id`, а не отображаемое имя, позицию в списке или название секции.
- При открытии модели из «Избранного» и её основной колонки используется одно и то же закреплённое окно.
- Клик по закреплённому окну поднимает его над остальными закреплёнными, не создавая новую копию.

### 2.4. Закрытие

**Закреплённые окна закрываются только своей кнопкой «×».**

Не закрывать их при:

- отпускании Ctrl;
- нажатии Escape;
- клике вне окна;
- открытии другой модели;
- перетаскивании карточек EVM;
- переключении между представлениями Web Alarm;
- потере фокуса браузера.

Escape по-прежнему может закрывать временный предпросмотр или активное модальное окно, но не закреплённые окна.

После нажатия «×» соответствующую модель можно закрепить заново.

## 3. Перемещение по экрану

Использовать область заголовка как ручку перетаскивания.

- Перемещение должно работать обычной мышью Windows.
- Начало перемещения не должно активировать кнопки карточки.
- Перемещение должно быть плавным, без рывков и скачков координат.
- Окна не должны автоматически возвращаться к исходным карточкам.
- При отпускании мыши окно остаётся на выбранной позиции.
- Внутренняя прокрутка, выделение текста, кнопки «Настройки» и «Проверить чат» продолжают работать.
- Не допускать ухода окна целиком за край экрана. Заголовок и крестик должны оставаться доступными.
- При изменении размеров браузера или масштаба корректировать позиции, если окно оказалось недоступным.

Перетаскивание закреплённого окна и существующий drag-and-drop компактных карточек должны быть независимыми механизмами без конфликтов.

## 4. Порядок слоёв

Ожидаемая последовательность снизу вверх:

1. Основной интерфейс Web Alarm и доска EVM.
2. Несколько закреплённых окон моделей.
3. Текущий временный Ctrl-предпросмотр — **выше всех закреплённых окон**.

Внутри слоя закреплённых окон активное окно находится сверху остальных.

Системные диалоги приложения («Настройки», подтверждения и другие модальные действия) должны оставаться доступными и не блокироваться перекрытием. При активном модальном диалоге временный предпросмотр можно приостановить.

Здесь под окнами понимаются плавающие панели внутри интерфейса Web Alarm. Реализация отдельных окон Windows с OS-level always-on-top не требуется.

## 5. Сохранение расположения

После перемещения нужно сохранять расположение каждого закреплённого окна.

Желаемое поведение:

- координаты сохраняются после отпускания мыши, без записи на каждом пикселе движения;
- после обновления страницы и перезапуска сервера окна восстанавливаются в ранее сохранённых местах;
- открытый набор окон также восстанавливается, пока пользователь явно не закрыл конкретное окно;
- закрытие через «×» удаляет запись об открытом окне;
- при изменении размера экрана координаты приводятся к безопасным границам;
- отсутствующая или удалённая модель не создаёт битое окно или ошибочную копию;
- настройки расположения не должны содержать токены, ключи, диагностические секреты или копии записей реестра моделей.

Сначала исследовать существующий механизм `ultra/evm_view.json` и `/ultra/model-cards/view`. Предпочесть развитие уже существующего хранения вида EVM, с сохранением его `base_revision`, проверок происхождения запросов и защиты от конфликтов.

Не создавать отдельную несовместимую систему хранения, если подходящий механизм уже существует. Если для сохранения позиций необходимы изменения сервера, обосновать их и ограничить только полями layout.

## 6. Архитектура

Текущая реализация использует одиночные `evm.peek` и DOM-элемент `#evmPeek`.

Нужно аккуратно разделить:

- временный предпросмотр одной модели;
- коллекцию закреплённых окон, индексируемую по стабильному ID модели;
- независимое состояние перетаскивания и координат;
- порядок слоёв и активный фокус;
- сохранённый layout.

Не создавать отдельные реализации полной карточки модели. Повторно использовать имеющуюся `fullCard()` и существующие источники данных, избегая дублирования обработчиков, идентификаторов DOM, настроек и серверных записей.

Особенно проверить `evm.fk`, возвращение клавиатурного фокуса, повторную перерисовку, смену модели и закрытие окна.

Внутренние обновления карточек должны отображаться в закреплённых окнах без повторного создания окон и без потери пользовательских координат.

## 8. Обязательные проверки

Проверить не только тестами DOM, но и реальными событиями ввода браузера:

1. Закрепить модель A, затем B и C — три независимых окна одновременно.
2. Перетащить каждое в разные позиции; убедиться, что окна не меняются местами сами.
3. Повторно открыть A из основной колонки и «Избранного» — по-прежнему одно окно A.
4. Открыть временный Ctrl-предпросмотр D над A, B и C — временное окно выше всех.
5. Отпустить Ctrl — исчезает только D, A/B/C остаются.
6. Нажать Escape, кликнуть вне окон, переключить вкладку интерфейса — закреплённые окна сохраняются.
7. Закрыть B крестиком — A и C остаются; повторно закрепить B — создаётся ровно одно новое B.
8. Переместить A и проверить сохранение координат после обновления страницы и рестарта сервера.
9. Изменить размеры окна браузера, масштаб 150 %, проверить работу на 1400 px и 390 px без потери доступного крестика.
10. Проверить обычное перетаскивание компактных карточек, «Избранное», Ctrl-preview и открытие полной карточки на месте — не допустить регрессии №464.
11. Проверить действия «Настройки», «Проверить чат», клавиатуру, доступность, безопасную обработку HTML и фокус.
12. Проверить конфликт двух браузерных вкладок при сохранении расположения, повреждённые координаты, отсутствующие модели и ошибки записи.

Запустить релевантные Python/JS-тесты, полный regression и mutation gate по применимому профилю №36, №36.1, №36.2, №36.3.

Не скрывать первоначальные FAIL, flaky-прогоны, NOT RUN и ограничения среды. Если физическая Windows-мышь недоступна, явно указать это и приложить точную инструкцию для пользовательской проверки.

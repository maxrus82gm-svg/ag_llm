# Передача этапа 1: главный экран Ultra Chat с чтением существующих диалогов

**Источник:** `CLAUDE-WUA-CHAT-S0-BASELINE-CONTRACT-001` (программа №37, этап 0). Технический контракт — `architecture-contract.md`, факты и доказательства — `report.md`.
**Рабочее имя будущей задачи:** WUA-2A-CHAT-READONLY-001 по аналитике Астры; окончательный TASK ID назначает координатор.
**Статус:** подготовленная спецификация. Этот документ не назначает задачу и не разрешает начинать её.
**Редакция 2.** Учтено уточнение координатора: доступ к истории не зависит от Windows folder picker. Изменены §3, §4, §5, §6.1, §6.2, §6.3, §8.

## 1. Цель этапа 1 одной фразой

Пользователь открывает Web Alarm и сразу видит Ultra Chat: выбирает зарегистрированный Workspace, открывает существующий чат и читает сохранённую переписку. Веб при этом ничего не записывает в папку Workspace, не обращается к сети и не умеет отправлять сообщения.

## 2. Когда этап 1 начинать НЕЛЬЗЯ

Этап 1 не начинается, если выполнено хотя бы одно условие:

1. **Нет решений пользователя.** Не утверждена программа №37 или не назначен этап 1 (№37 §9, п. 1–2). Сейчас №37 — «программа-кандидат», №34 подтверждает: «AWAITING USER PLAN APPROVAL».
2. **Этап 0 не принят.** Этот пакет не прошёл независимую проверку ChatGPT, или решения §5 `report.md` (владельцы файлов, топология, контракт) не приняты.
3. **Не закрыта приёмка EVM.** Не закрыта независимая Windows/визуальная приёмка EVM (`CLAUDE-WUA-1-EVM-CONNECTIONS-001`); по №34 она «OPEN». Этап 1 меняет вид по умолчанию, который закреплён тестом EVM E1, и показывает выбор модели из EVM.
4. **Не разведены файлы с WA4-R.** Не решено, кто владеет `web_alarm/server.py` и `web_alarm/ui.py` на время этапа 1 относительно LLM15/Codex WA4-R/TOCTOU (№34). Отдельно нужно согласие владельца folder picker: общая проверка HTTP-границы выделяется из `_folder_picker_request`.
5. **Исходники не совпадают с базой.** Байты любого файла §4 отличаются от `evidence/baseline.json` и от опубликованной ревизии, которую назовёт координатор. Или есть неизвестные локальные правки этих файлов.
6. **Нельзя выполнить обязательную негативную проверку §6 и честно её закрыть.** Например, на хосте нельзя создать junction. Такую проверку нельзя объявлять PASS — только NOT RUN с причиной, и тогда этап 1 не принимается.
7. **Есть параллельная реализация.** Другой исполнитель одновременно меняет те же файлы или общее хранилище `.ultra`. По №20 §5а у Codex одновременно одна активная implementation TASK.

## 3. Что пользователь увидит в браузере

1. **Первый экран.** `http://127.0.0.1:<порт>/` открывается на **Ultra Chat**. В верхней панели три раздела: «Ultra Chat», «Операторская панель», «EVM · Подключения Ultra». Прямые ссылки на TASK операторской панели продолжают работать.
2. **Выбор Workspace.** Список зарегистрированных в Web Alarm папок, у каждой понятное состояние:
   - «История Ultra найдена»;
   - «В папке нет истории Ultra» — ничего не создаётся;
   - «Папка недоступна»;
   - «Данные Ultra повреждены».

   Незарегистрированную папку пользователь добавляет существующей кнопкой регистрации Web Alarm. Отдельная регистрация в Ultra Chat не делается, `ui_state.json` Tk не читается.
3. **Список чатов.** Названия и даты создания. Повреждённый чат показан как «Чат повреждён», без содержимого; остальные чаты доступны.
4. **Переписка.**
   - Сообщения пользователя и ассистента идут в порядке создания.
   - Старые ошибки выполнения помечены «Ошибка выполнения (старая запись)».
   - Сообщение пользователя без ответа помечено «Ответ не сохранён».
   - Кнопка «Показать ранее» подгружает более ранние страницы.
5. **Состояния истории** различаются видимо:
   - «В этом чате нет сообщений»;
   - «Показана не вся история: N записей повреждено или принадлежит другому чату»;
   - «История слишком большая для просмотра (N файлов, M МиБ)»;
   - «История недоступна: <понятная причина без путей>».
6. **Модель.** Значок «Модель: <название из EVM>». Если выбора нет или он повреждён — соответствующий текст EVM и ссылка на раздел EVM.
7. **Поле ввода** честно неактивно: «Отправка сообщений появится на следующем этапе». Активной кнопки «Отправить» с поддельным успехом нет.
8. **Изменение истории.** Кнопок создания, переименования и удаления чатов нет, редактора контекстов нет.
9. **Чтение недоступно.** Если сервер запущен не на loopback или с `--disable-ultra-chat`, раздел Ultra Chat показывает «Чтение истории Ultra Chat недоступно в этом режиме сервера». Операторская панель и EVM работают. Включён или выключен folder picker, на Ultra Chat не влияет.
10. **Сервер перезапущен при открытой странице.** Следующее чтение один раз само обновляет доступ. Если не получилось — «Доступ к истории недействителен — обновите страницу».

## 5. Минимальный технический объём

1. **Функции ядра.** Перечень чатов и страница истории с проверками §7.2–7.4 контракта. Параметры: `ultra_workspace_id`, `chat_id`, курсор, лимиты. Результат — элементы с метками и `history_state`.
2. **Адаптер.** Привязка Workspace, классификация исходов, коды ошибок.
3. **Маршруты:**
   - `GET /ui/ultra-chat/capability` — выдача собственной возможности чтения, контракт §7.1.1;
   - `GET /ultra/chat/workspaces`;
   - `GET /ultra/chat/workspaces/<wa_workspace_id>/chats`;
   - `GET /ultra/chat/workspaces/<wa_workspace_id>/chats/<chat_id>/messages?before=&limit=`.

   Все маршруты защищены проверками §7.1 контракта. Маршруты истории дополнительно требуют токен из заголовка `X-WebAlarm-Ultra-Chat-Token`, в том числе для GET. Токен не зависит от folder picker.

   **Образец.** `tools/proto_ultra_chat_access.py` из пакета этапа 0 показывает возможность и содержит готовую матрицу HTTP-тестов. Это изолированный прототип, а не production. На этапе 1 его логика переносится в `web_alarm/ultra_chat.py` и `web_alarm/server.py`, а тесты — в `test_web_alarm_ultra_chat.py`, уже против настоящих маршрутов и синтетического хранилища.
4. **Страница.** Вид по умолчанию, три раздела, состояния §3, неактивное поле ввода.

## 6. Обязательные проверки

Все проверки выполняются на синтетических Workspace в TEMP через guarded runner `wa4a_acceptance.py`. Живые Workspace, сеть и credentials не используются. Код проб этапа 0 (`tools/probe_s0_storage.py`) можно переиспользовать как образец фикстур.

### 6.2. Качество тестов (TEST-QA-01)

Мутанты в копии кода в TEMP должны быть убиты:

- **проверки чтения:** без проверки `workspace_id` чата; без сравнения имени файла с ID; переход по junction; чтение без лимита; перечень через `list_chats` (создаёт файлы);
- **граница HTTP и возможность чтения** — те же 10 мутантов, что убиты на прототипе этапа 0 (`evidence/access_gate_mutants.json`), теперь против настоящего кода:
  - возможность зависит от folder picker;
  - один токен на обе возможности;
  - GET истории без проверки токена;
  - нет точной проверки `Host`;
  - параметры URL не проверяются;
  - заголовок folder picker принимается как токен Chat;
  - `Origin` не сравнивается;
  - `Sec-Fetch-Site` не сравнивается;
  - возможность выдаётся при привязке не к loopback;
  - допускаются два заголовка токена;
- **ошибки и страница:** вывод через `innerHTML`; ошибка с путём в ответе;
- **отображение:** выдача сообщения дважды; режим по умолчанию — операторская панель;
- **страница:** токен сохраняется в `localStorage`; заголовок токена уходит на все маршруты API; бесконечные повторы после `ultra_chat_token_invalid`.

## 7. Критерии готовности

- Все проверки §6.1 выполнены и PASS, либо имеют честный NOT RUN с причиной. Во втором случае итог этапа — PARTIAL.
- Мутанты §6.2 убиты, регрессия §6.3 зелёная, нарушений изоляции 0.
- Сдача: manifest с SHA исходников, отчёт, evidence через `web_alarm.evidence_sanitizer` (`scan` с кодом 0).
- Независимая проверка ChatGPT и визуальная приёмка §6.4.

## 8. Откат

Быстрый откат без изменения кода — запуск с `--disable-ultra-chat`: возможность чтения недоступна, маршруты истории отвечают 403. Полный откат — вернуть операторскую панель как вид по умолчанию и убрать маршруты `/ui/ultra-chat/capability` и `/ultra/chat/*`. Общая проверка происхождения остаётся у folder picker. Хранилище `.ultra` этапом 1 не менялось, поэтому откат данных не нужен. Добавленные функции чтения в `context_storage.py` никем, кроме веба, не используются и могут остаться или быть удалены.

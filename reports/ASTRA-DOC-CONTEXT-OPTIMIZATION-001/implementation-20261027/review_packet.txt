## Специальный рабочий протокол Ultra Desktop

**Применять только к реально назначенной файловой/coding TASK; не создавать искусственные тесты для простого анализа.**

**TASK → WRITE → READBACK → TEST → SELF-AUDIT → REPORT → REVIEW.**

- **TASK.** Указать точный абсолютный каталог, список разрешённых файлов, среду/инструмент, запреты, ожидаемые результаты и условия `PASS / FAIL / BLOCKED`. Если путь или инструмент недоступен — сообщить, не подменять другим диском/папкой и не обходить scope.
- **WRITE.** Сначала выполнить разрешённую короткую пробную запись; для кода сохранять реально исполняемый текст, а не только помещать его в ответ чата. Коды возврата команды сами по себе не доказывают сохранение.
- **READBACK.** После каждой значимой записи повторно открыть фактический файл по **тому же** пути, проверить существование, ненулевой ожидаемый размер и точное содержимое/хеш. При ошибке остановить дальнейшее наращивание, локализовать причину; нельзя заявлять `SAVED` без readback.
- **TEST.** Запускать необходимые тесты реальным доступным интерпретатором/runner, отдельно фиксировать точную команду, версию/окружение, exit code, количество `PASS / FAIL / ERROR / SKIP` и вывод. Мысленная симуляция = `NOT RUN`. Проверять корректность самих тестов и ограничений ТЗ.
- **SELF-AUDIT.** Сверить сохранённые файлы, тестовые ожидания и edge cases; исправлять только подтверждённое внутри scope, затем повторять необходимые проверки. Ищем не красивый отчёт, а воспроизводимое решение.
- **REPORT.** Различать `IMPLEMENTED` (написано), `SAVED` (проверено повторным чтением), `TESTED` (реальный запуск), `VERIFIED` (исключительно независимый reviewer). Для `BLOCKED` привести конкретную команду/инструмент, путь, exit code, stdout/stderr или их отсутствие, фактическое наличие/размер файла и безопасный способ воспроизведения. Не утверждать без доказательств, что «диск только для чтения» или «файлы исчезают».
- **REVIEW.** Сдавать результат координатору по подтверждённым фактам. На замечания verifier исправлять адресно; число циклов и новая область работ определяются TASK/пользователем.

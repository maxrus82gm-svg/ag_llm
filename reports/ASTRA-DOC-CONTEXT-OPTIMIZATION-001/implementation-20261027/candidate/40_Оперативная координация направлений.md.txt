## Правила для обоих рабочих чатов

1. **Перед новой постановкой** читать **только эту сводку** в свежем опубликованном GitHub; при пересечении файлов, функций, хранилища или API — переходить по адресным ссылкам. Не читать чужие полные архивы без причины.
2. **До фактического старта** обновить свою строку: `PLANNED` → после подтверждённого запуска `ACTIVE`; TASK ID, одна фраза о цели, исполнитель, **разрешённые изменения** и **возможные пересечения**. Состояние из неподтверждённого чата не считать опубликованным. Публикация в `main` и локальная синхронизация — за пользователем.
3. **При изменении scope** сначала актуализировать сводку и согласовать новый конфликт. Совпадение имени файла не означает автоматический запрет: проверить конкретные участки, совместимость и последовательность интеграции. Право изменять файл принадлежит конкретной разрешённой TASK, а не направлению навсегда.
4. **После независимой проверки** обновить итог и ссылку, не копируя отчёт. Старые детали остаются у исторических владельцев №06/профильных журналов/№001 и в отчётах; №34 обновляется без накопления истории. Два рабочих чата обновляют **один файл последовательно**, перечитывая текущую ревизию перед записью; при конфликте Git сначала согласовать изменения.
5. **Не переопределять ограничения:** постановка TASK — три блока **в чат**, БЛОК 1 заполняет пользователь; Claude/Codex не получают Git-права автоматически; `GPT → main` объединяет только пользователь. EVM gate, №37 approval, B2 V-13 и заморозка MCP №39 остаются как прежде.

**При смене чата** меняются только его название, исполнитель и текущие сведения; направления А и Б сохраняются.

**Правило графа Obsidian:** единственная внутренняя связь этого документа — с `000_Задачи для агента`; ссылки на карточки, историю и контекст остаются внешними GitHub-ссылками, чтобы не создавать дополнительных рёбер.

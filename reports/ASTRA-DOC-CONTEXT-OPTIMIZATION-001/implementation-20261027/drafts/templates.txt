# Формы рабочего цикла проекта

**Редакция 27.10.2026.** Это каркасы для заполнения, не готовые результаты и не дополнительные разрешения. Канон ролей, состояний, сохранности и порядка — №18 → DOC-CONTEXT-OPS-01. Названия полей ниже служат интерфейсом координатору; неизвестное отмечать UNKNOWN/NOT RUN/UNASSIGNED с причиной. Не копировать пустые формы в оперативный контекст как реальные TASK.

## Форма назначения TASK

```text
TASK ID / понятное название:
Источник назначения: пользователь / точное поручение / дата
Исполнитель / роль / персональный путь:
Цель и наблюдаемый результат:
PRIMARY PROFILE / SECONDARY при реальном пересечении:
Исходное состояние / точная версия / evidence:
Read scope:
Write scope: точные существующие и новые пути
Не делать / права / отдельные live-paid-production gates:
Матрица чтения: файл → точный заголовок/Rule-ID → зачем → объём
Требования и критерии приёмки:
Риски/допущения / влияние на существующие инварианты:
Обязательные проверки / изоляция / допустимые tools:
Отчёт: reports/<TASK-ID>/report.md + manifest + безопасные evidence
DOC IMPACT / канонические владельцы / shared scope:
Условие RESULT READY / ожидаемый независимый review:
NEXT: предложение, не автоматическое назначение
```

Координатор передаёт пользователю три блока: полная постановка, короткий запуск исполнителю, понятный результат и границы. Обычный БЛОК 1 назначает пользователь. Прямое адресное поручение пользователя в текущем чате само определяет разрешённую работу; не создавать лишние согласования. Исполнитель не очищает БЛОК 1 после сдачи. При реализации использовать имеющиеся механизмы и самостоятельный adversarial analysis по релевантному риску.

## Форма технической сдачи исполнителя

```text
TASK / AMENDMENT / исполнитель:
Статус: DRAFT / RESULT READY / PARTIAL / FAIL / BLOCKED
Версия пакета / дата / source version / report digest:
Фактически изменённые и созданные пути:
Что реализовано и наблюдаемый результат:
Проверки: команда, среда, exit, PASS/FAIL/ERROR/SKIP, evidence locator
Первые FAIL и исправления:
NOT RUN / ограничения доказательств:
Самостоятельный инженерный/adversarial разбор:
Риски / найденные дефекты / verification gaps:
Отклонения от задания и почему:
DOC IMPACT / точная SHARED DOC DELTA:
Manifest / report / evidence / доступность публикации:
NEXT / получатель:
```

Отчёт обязателен для любой TASK, в том числе исследования или BLOCKED. Текст в чате не заменяет сохранённый файл. RESULT READY не является независимым VERIFIED. При незавершённых обязательных проверках сообщать, что работа продолжается; не выдавать финальный копируемый результат. Не придумывать число тестов, публикацию или доставку сообщения.

## Форма независимого verdict

```text
TASK / report digest / проверенная source revision:
Verifier / дата / независимость от автора:
Публикация: подтверждённая версия / LOCAL ONLY / UNKNOWN
Проверенный scope:
Что прочитано / что независимо исполнено:
Evidence integrity / воспроизводимость:
Findings с приоритетом и точным адресом:
NOT RUN / недоступные источники / остаточные gates:
Вердикт: PASS / PARTIAL / REVISE / FAIL / BLOCKED
Что этот verdict НЕ подтверждает:
Условия следующего шага / кто отвечает:
Историческая запись №06 / personal БЛОК 4:
```

Авторские результаты при пересказе явно обозначать как авторские. PASS по документу, source, автоматическим тестам, Windows visual и production — разные области. Не объединять их в общий VERIFIED. При собственном исправлении verifier становится автором изменения и нужен отдельный независимый проверяющий.

## Форма записи №05

```text
record_id: постоянный уникальный ключ записи
TASK ID / понятное название / тема / подсистема:
executor / coordinator / verifier:
event_date / source_revision / report_digest:
execution_state / publication_state:
review_verdict / review_scope / result_kind:
Краткий результат и ограничения:
depends_on / blocked_by / open_gates:
supersedes: record_id + область изменения, либо NONE
report_locator / manifest_locator / evidence_locator:
history_06_locator / personal_001_locator / profile_history_locator:
risk_ids / NEXT / updated_at:
```

Старую запись не стирать ради нового статуса. Новое принятое событие имеет собственный record_id и точный supersedes. Для FUTURE без TASK ID оставить явное отсутствие назначения; ключ записи не создаёт TASK. Если исторический report никогда не существовал в стандартном пути, дать проверенный иной источник, NOT APPLICABLE с причиной либо LOCATOR PENDING. Нельзя писать фиктивный путь по шаблону.

## Форма истории №06 и персональной №001

```text
event_id / TASK ID / дата / тип события:
Исполнитель / verifier / source revision:
Что произошло и почему это существенно:
Исходная постановка и AMENDMENT:
  полные байты в №001 либо точный постоянный snapshot + SHA-256
Технический результат / report + digest:
Независимый verdict / scope / evidence / NOT RUN:
Сохранённые риски, ограничения и решения пользователя:
supersedes / связи с прежними событиями обычным текстом:
NEXT / основания закрытия либо сохранения TASK:
Readback новой записи / hash / archive prefix unchanged:
```

№06 хранит общее событие и verdict; №001 — полную постановку/AMENDMENT и итог именно этого исполнителя; профильный журнал — специальные подробности. Один технический отчёт не копировать целиком во все места. Старую историю не переписывать. Новая история и её readback предшествуют очистке карточки. Архивы не загружать полностью для добавления одной записи.

## Форма риск-карточки

```text
risk_id / TASK / подсистема:
Тип: FACT_DEFECT / RISK_HYPOTHESIS / VERIFICATION_GAP
Условие → возможное событие → последствие:
Основание / точный locator / версия / что ещё неизвестно:
impact: HIGH / MEDIUM / LOW / UNASSESSED + объяснение
likelihood: OBSERVED / PLAUSIBLE / LOW_WITH_EVIDENCE / UNKNOWN + основание
confidence / пределы evidence:
affected_gate: конкретное действие, которое ограничено
owner / verifier: имена или UNASSIGNED
action: проверяемое действие / срок либо trigger
closure_evidence: что и на какой версии требуется доказать
status: PROPOSED / UNDER_REVIEW / OPEN / MITIGATED / CLOSED / ACCEPTED_BY_USER
updated_at / next_review_trigger / residual_decision:
```

Классификации и полномочия — №18 → OPS-RISK. Не ставить проценты без основания. Исправление без независимой проверки не закрывает gate. UNKNOWN — честное поле, требующее следующего действия. В №34 переносится короткая строка с risk_id и влиянием на NEXT, полный текст остаётся в №05.

## Форма оперативной памяти №34

```text
Дата среза / автор / точные источники / что не перепроверено:
Рабочие ориентиры: проект, локальная среда, роли, безопасный запуск
Текущее состояние направлений: назначение, TASK, execution/review, NEXT
Действующие решения: смысл, область, источник, отмена/замещение
OPEN/gates/риски: ID, влияние, owner/action, точный адрес
Последние существенные результаты: 3–5 на основное направление
  TASK, дата/версия, краткий итог, bounded verdict, OPEN, locator
Ближайшие действия и условия разрешения:
Контроль размера/сохранности: до→после, что вытеснено и где сохранено
```

Цель — восстановление работы нового чата, а не перечисление всех завершённых задач. Размер и отбор — №18 → OPS-BUDGET. Старые устойчивые ограничения сохраняются независимо от окна результатов. Не выдавать LOCAL ONLY, историческое CURRENT или user plan approval за свежую реализацию.

## Форма координации №40

```text
Направление / цель:
Текущий чат / исполнитель / дата сверки:
TASK / источник назначения / или NOT ASSIGNED:
execution_state / review_state:
Занятость исполнителя вне этого направления:
Разрешённые файлы/функции/данные / возможные пересечения:
Кто согласует пересечение / порядок интеграции:
Ближайший шаг / блокирующее условие / risk_id:
Точные адреса карточки, №05/отчёта:
```

Одна актуальная запись на направление. При смене чата/состояния обновить запись. Подробный report и историю не копировать. Владение файлом принадлежит разрешённой TASK, а не агенту навсегда.

## Форма closeout-проверки координатора

```text
TASK + report digest / independent verdict:
USER GO / scope / source version подтверждены:
№05: record_id / точный адрес / readback
№06: event_id / readback новой записи
№001: постановка/AMENDMENT/result snapshot + hash / readback
Профильный владелец: адрес / либо NO IMPACT с причиной
№34: current/OPEN/NEXT обновлены; размер до→после; loss-check
№40: пересечения/занятость обновлены либо NO IMPACT
№08: маршрут изменился? только тогда обновить
Риски: owner/action/closure evidence / открытый остаток
Персональная карточка: B2/B3 окно; B4 verdict; B1 последним
Граф/целевые заголовки/адреса/исторический префикс сохранены:
Публикация и принятие: что фактически выполнено / что pending
Общий статус: DOC CLOSEOUT COMPLETE / INCOMPLETE / BLOCKED
NEXT / безопасная точка возобновления:
```

Значение COMPLETE допустимо лишь после фактических проверок всех применимых полей. Пустая строка не означает PASS. Стоп-условия и порядок — №18 → OPS-CLOSE/OPS-EXIT. При прерывании сохранить промежуточный статус и продолжить со сверкой, без очистки неподтверждённой задачи.

## Форма архитектурного решения

```text
Проблема / доказательство необходимости:
Варианты и сравнение:
Выбранное решение / причина:
Инварианты, права, данные и совместимость:
Риски / ограничения / непринятые допущения:
Затронутые владельцы и документы:
План проверки / критерии / откат:
Статус: PROPOSAL / USER PLAN APPROVED / фактическая реализация отдельно
Основание пользовательского решения / дата / версия:
```

Прежние примеры ниже сохранены только адресами к исходному снимку: они не описывают нынешний runtime и не разрешают новую TASK.

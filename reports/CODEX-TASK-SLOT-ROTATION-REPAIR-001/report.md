## MANUAL ENGINEERING REVIEW

Проверены ветви: точный сохранённый snapshot → reuse; отсутствующий snapshot → create/no-replace/readback → card write last; конфликт → NO ROTATE; обе копии одинаковы → очистить только1; waiting → повтор без записи; same-ID/different-bytes → отказ; amendments count/hash и потерянный файл → отказ. Используются нормализация только CRLF/LF, проверка SHA и повторное чтение. Короткий Unicode-текст проверяется по символам, не bytes; whitespace padding и граница99/100 испытаны.

Снимки создаются через fsync временного файла и atomic no-replace hard link. Если FS не поддерживает операцию, отказ без освобождения карточки, без небезопасного fallback. Существующие файлы не перезаписываются. Блокировка карточки и compare/readback защищают обычные конкурирующие запуски. Это не sandbox против злонамеренного администратора, не доказательство power-loss durability и не абсолютная защита от same-user FS races. При сомнении остаются снимки и исходная TASK.

Окно не содержит второй реализации ротации. Workflow работает в child process, чтение stdout/stderr отделено от Tk loop. Большой протокол не печатается синхронно из event loop; на диск сохраняется полный JSON, в консоль — краткий результат. PID probe Windows только query; нет изменения прав, процессов движка, firewall или сети. Single-window mailbox и TEMP-cache не являются доверенным долговременным архивом; при неясном owner автоматического убийства/снятия чужого lock нет.

## Причина и исправление

На установленном Windows CPython 3.12.10 event loop использует `GetTickCount64` с объявленной дискретностью 15,625 мс. В `BaseEventLoop._run_once` таймеры выбираются до `loop.time() + _clock_resolution`. Таймер на 10 мс может вызвать отмену, пока измерение ещё показывает тот же тик. `asyncio.wait_for()` возвращает значение корутины, подавившей отмену. Старый сервис после такого возврата знал только о результате и разнице показаний `time.monotonic()`. Если разница была меньше 10 мс, он возвращал `COMPLETED`.

Детерминированный oracle сохранил настоящий asyncio timer и доставку `CancelledError`, зафиксировав часы и задав разрешение event loop в 15,625 мс. Fake один раз получил отмену при исходном показании часов и вернул валидный ответ с usage. Старый код повторил ложный `COMPLETED`. Это воспроизводит причинную цепочку CI, а точный порядок событий на исходном runner остаётся неизвестен. Выдержки из локальной stdlib и измерения сохранены в `evidence/natural_before.stdout.txt`.

В `execute_request()` теперь одна абсолютная граница на часах текущего event loop и явный `asyncio.timeout_at(deadline)`. `expired()` сохраняет факт срабатывания таймера после выхода из его контекста. После получения и разбора ответа сервис учитывает этот флаг, `loop.time() >= deadline` и прежнюю проверку отмены. Флаг защищает при неизменном тике. Проверка часов защищает при задержанном callback таймера. Ответ при сработавшем таймере или на границе и позже даёт `UNKNOWN_AFTER_START / RESPONSE_RECEIVED` с пустым текстом и валидным доступным usage. Обычный timeout без ответа даёт `MAY_HAVE_EXECUTED` и неизвестный usage. Своевременный ответ остаётся `COMPLETED`. Лимит передаётся fake без изменения. Вызов единственный, retry отсутствует. До отправки сохраняются проверка отмены, frozen model и request binding.

Изменены два исходника из WRITE-scope. S4B продолжает преобразовывать `unknown_after_start` с обеими формами execution в `turn_uncertain / UNKNOWN` через действующий Turn. Таймер остаётся кооперативным. Транспорт, блокирующий event loop, может задержать возврат, а проверка абсолютной границы отбрасывает его поздний результат при возврате. `asyncio.timeout_at` доступен с Python 3.11. Локальная проверка выполнена на принятом в Windows тестах Python 3.12.

Хеши всех 595 файлов пользовательской истории и 10 файлов редактора совпали с baseline до сдачи. Launcher остаётся в STANDARD по проверенным BAT/config. В отчётной папке лежат только источники и контрольные хеши данных, без копий пользовательской истории.

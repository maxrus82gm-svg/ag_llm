### 2. Gate A — проверить существующий V2Ray

Только read-only:

1. Изучить сохранённые сведения о слушателях `127.0.0.1:10808` и `127.0.0.1:10813`.
2. Проверить, есть ли в действующей конфигурации sing-box уже готовый HTTP CONNECT или mixed inbound.
3. Не считать GUI-настройки доказательством загруженной конфигурации процесса.

5. Установить, что известно о выборе remote outbound, DNS, маршрутизации и возможном DIRECT.

Никаких live CONNECT-запросов через рабочий V2Ray, внешних DNS/HTTP-запросов или fault injection на действующем listener. Не менять, не перезапускать и не перенастраивать V2Ray.

### 4. Gate C — исследовать HTTP → SOCKS5 адаптер

Если готовый HTTP CONNECT inbound не подтверждён, спроектировать минимальный локальный адаптер.

**Обязательные свойства кандидата:**

- HTTP CONNECT endpoint слушает исключительно `127.0.0.1` на отдельном выделенном порту.
- Исходящие соединения адаптера — только к явно заданному loopback SOCKS5 endpoint.
- Целевые адреса разрешаются по строгой allowlist, исходно только синтетические.
- DNS-имена передаются SOCKS5 по доменному адресу, без самостоятельного локального разрешения в direct route.
- Запрещены прямые соединения к целевому серверу, запасные proxy endpoints и автоматический fallback.
- При отказе SOCKS5, timeout, разрыве связи, неверном ответе или ошибке конфигурации — отказ операции и закрытие соединения.
- Ограничить размер HTTP-заголовков, число соединений, время ожидания и ресурсы.
- Не записывать токены, пароли, заголовки авторизации и содержимое пользовательских запросов в evidence.

Разрешается реализовать **отдельный изолированный прототип** адаптера в пределах папки AM07 и проверить его на полностью синтетических loopback SOCKS5/origin fixtures.

Не подключать прототип к живому V2Ray и не изменять launcher или production-конфигурацию.

### 5. Gate D — локальные отрицательные тесты

Проверить в изолированном стенде:

1. Успешный CONNECT через фиктивный SOCKS5.
2. SOCKS5 listener отсутствует.
3. SOCKS5 возвращает отказ.
4. Timeout или разрыв соединения.
5. Некорректный SOCKS5 handshake.
6. Запрещённый destination.
7. Попытка прямого обхода.
8. Влияние proxy environment и NO_PROXY.
9. Невозможность перехода на альтернативный сетевой маршрут при ошибке.

Снимать фактические socket traces. Проверять не только отказ, но и отсутствие direct-соединения.

Не выдавать PASS на безопасность native tunnel-client по результатам тестов прототипа.

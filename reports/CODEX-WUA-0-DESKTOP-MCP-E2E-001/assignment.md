## 1. Цель

Уважаемый агент 007 (Codex), предлагаю приступить к следующему этапу подключения ChatGPT Desktop к Web Alarm.

**Главная цель — установить реальную работоспособную связь:**

Обычный ChatGPT Desktop → локальный MCP-плагин → ограниченный MCP-адаптер → локальный Web Alarm API.

По итогам задачи ChatGPT должен получить возможность из обычного пользовательского чата вызвать три безопасных MCP-инструмента и получить данные синтетической TASK непосредственно от локального Web Alarm.

Это продолжение завершённого исследования `CODEX-WUA-0-MCP-FEASIBILITY-001`, а не повтор его первоначальных 34 проверок.

**Не путать:** вызов MCP из локального SDK-клиента Codex уже был продемонстрирован; теперь требуется настоящий end-to-end вызов из обычного ChatGPT Desktop.

## 4. Порядок реализации

### A. Preflight

1. Сверить доступный локальный Web Alarm API и MCP-прототип.
2. Проверить фактически поддерживаемую процедуру установки локального плагина в обычном ChatGPT Desktop на Windows.
3. Уточнить требования и разрешения текущей конфигурации ChatGPT, не предполагая их по тарифу или имени установленного процесса.
4. Проверить конфигурацию плагина и необходимые зависимости по актуальной документации.
5. Если обнаружена несовместимость или ограничение, оформить точный BLOCKED/PARTIAL с альтернативами, не обходить запреты.

### B. Подготовка рабочего MCP-подключения

Разработать отдельный минимальный кандидат плагина с безопасной конфигурацией и тремя инструментами:

- `ping` — проверить доступность синтетического сервера.
- `list_capabilities` — прочитать разрешённые инструменты и их ограничения.
- `read_synthetic_context` — получить синтетический TASK Context Pack.

Использовать disposable fixture и loopback, сохранив read-only allowlist, строгую проверку TASK ID, размерные ограничения, timeout и fail-closed поведение.

Не изменять production Web Alarm ради удобства теста.

### C. Desktop end-to-end gate

При готовности плагина подготовить понятную пользователю инструкцию установки и подключения.

**Важное ограничение:** если установка или выбор плагина требует действий в ChatGPT Desktop, которые Codex не вправе автоматизировать, остановиться на manual gate и запросить участие пользователя. Не обходить ограничения другим UI-методом.

После разрешённого подключения организовать проверку непосредственно из обычного ChatGPT-чата:

1. Вызвать `ping`.
2. Вызвать `list_capabilities`.
3. Вызвать `read_synthetic_context`.
4. Сопоставить ответ с фактическим синтетическим серверным контекстом, TASK ID, nonce и hash.
5. Проверить, что попытка вызвать запрещённый инструмент либо другой TASK ID отклоняется.
6. Подтвердить отсутствие изменений реальных Workspace и production storage.

**Настоящий Desktop E2E PASS** разрешается фиксировать только если вызовы выполнены именно из обычного ChatGPT Desktop, а не только из SDK-клиента.

При недоступности такого вызова — `PARTIAL / DESKTOP E2E NOT RUN`, независимо от успешности локальных тестов.

### D. Инженерная проверка

Выполнить собственные adversarial и regression проверки:

- отказ неразрешённому TASK ID;
- path traversal;
- неизвестный MCP tool;
- неверный тип аргумента;
- отказ недоступного HTTP API;
- отсутствие неожиданного outbound network;
- отсутствие mutation;
- изоляция временной fixture и сохранность исходных данных.

Фиксировать настоящие результаты тестов и первоначальные FAIL без стирания истории.

Перед публикацией выполнить разрешённый scoped Git preflight. При dirty/conflict, чужих изменениях, необходимости pull/rebase или неопределённом состоянии — **PUBLISH BLOCKED**, запросить пользователю безопасное окно. Не применять `git add -A`, reset, stash, clean, rebase или force push к чужой работе.

После успешной разрешённой публикации: один task-scoped commit и обычный push, проверка полного SHA и доступности отчёта/evidence.

Если безопасной публикации пока нет, сохранить результат локально и не объявлять его опубликованным.

## Обычный Chat и локальное выполнение

Общая [документация Plugins](https://learn.chatgpt.com/docs/plugins) описывает
плагины в Chat и Work и требует нового чата после установки. Поэтому утверждение
«обычный Chat вообще не поддерживает MCP» из имеющихся данных не следует.

Для [desktop-only плагинов](https://developers.openai.com/plugins/deploy/desktop-only)
документация отдельно требует локальное выполнение: stdio-плагины доступны в
потоках, работающих локально. Наш кандидат использует stdio и
requires_local_executor=true. Само настольное приложение не доказывает, что
конкретный обычный Chat использует локальный исполнитель.

[Локальные каталоги](https://developers.openai.com/plugins/build/plugins)
документированы как источники в Work mode/Codex. Там же описан
codex plugin marketplace add для локального корневого каталога. Отсутствие отдельной
секции mcp_servers для WUA в config.toml само по себе не ошибка: конфигурация
MCP поставляется внутри плагина.

Рабочая гипотеза: неполное discovery и/или отсутствие локального исполнения у
целевой Chat-сессии. Разделить их можно новым локальным Work/Codex-сеансом с одним
ping, затем таким же запросом в новом обычном Chat. Успех Work не заменит Desktop
E2E исходной задачи. Даже разница двух режимов будет фактом данной конфигурации,
а не доказательством универсального запрета для всех обычных чатов.

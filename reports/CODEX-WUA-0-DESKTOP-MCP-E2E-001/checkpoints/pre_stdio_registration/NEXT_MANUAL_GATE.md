# Минимальный следующий ручной gate

TASK: CODEX-WUA-0-DESKTOP-MCP-E2E-001. Кандидат v0.2.0 не меняется.

Обнаружено: копия плагина установлена и enabled=true, но локальный менеджер не
рассматривает marketplace `wua-desktop-e2e-local`. Из основного проекта и из папки
TASK он возвращает только три встроенных каталога, а WUA listing пуст.
Поэтому сначала нужно устранить этот конкретный пробел обнаружения.

## 1. Ручная регистрация существующего локального каталога

Если согласен на добавление **только локального источника плагина** в настройки
Codex, выполни одну команду в PowerShell:

```powershell
codex plugin marketplace add "M:\GitHub\ag_llm\reports\CODEX-WUA-0-DESKTOP-MCP-E2E-001"
```

Это изменение регистрации каталога; агент его не выполнял. Оно не является
Git-синхронизацией или публикацией в GitHub. Используется уже существующий
локальный пакет, без обновления/переустановки сервера и без изменения permissions.
Если команда или UI требуют нового разрешения, остановиться и сообщить.

Передай Codex результат команды. Он повторно проверит discovery чтением.
Пока не перезапускай приложение и не останавливай работу Claude. Если host потребует
перезапуска для перечитывания каталога, сначала согласуем подходящий момент.

## 2. Один вызов для сравнения режимов

После подтверждения discovery — в **новом Work с локальным выполнением** (или новом
локальном Codex, если Work Local недоступен) выбери через @ именно WUA Desktop
Read-only и отправь:

```text
Вызови только ping плагина WUA Desktop Read-only настоящим MCP-вызовом.
Покажи status и session_id. Если инструмент недоступен, сообщи об этом без имитации.
```

Если ping сработал — повтори тот же короткий запрос в **новом обычном Chat** с
выбранным тем же плагином. Нужны два результата: Work Local и обычный Chat.

Work/Codex PASS не считается PASS первоначальной цели. Такое сравнение поможет
отделить ограничение режима Chat от проблемы локального discovery/активации.
Если уже Work Local не получает tool, не повторять длинный сценарий: передать
ошибку/отсутствие tool, продолжим диагностику слоя загрузки.

Новый чат нужен для нового набора доступных tools; старый отрицательный результат
сохраняется. Открытие новых чатов и выбор плагина пользователь делает вручную.

## Что этот gate не меняет

Production Web Alarm, GitHub, сеть, proxy/VPN/firewall, ключи и permissions остаются
без изменений. Туннели и broad-access permissions для этого gate не предлагаются.

Команда регистрации и необходимость нового сеанса описаны в официальной
[документации локальных marketplaces](https://developers.openai.com/plugins/build/plugins)
и [установки плагинов](https://learn.chatgpt.com/docs/plugins).

Manual gate следует TASK §4.C. Прочитанный

самостоятельно менять настройки без согласования.

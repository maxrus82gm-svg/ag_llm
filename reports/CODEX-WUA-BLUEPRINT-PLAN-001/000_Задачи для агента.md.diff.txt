+## План → индекс ID → полная задача
+
+**Дополнение по поручению пользователя / 03.11.2026.** Каноническое правило — №18 → `DOC-PLAN-TASK-INDEX-01@1`; форма — №07. При создании или сопровождении любого плана планировщик указывает, где находятся краткий индекс задач и полные записи. Существующий подходящий журнал переиспользовать; старые архивы массово не переносить.
+
+Для понимания выполненного сначала читать **индекс ID**: постоянный порядковый ID, описание примерно в **15–20 слов**, этап, статус и адрес. Индекс можно читать целиком. Подробности получать только по выбранному ID — одну запись между точными маркерами/границами строк. Не открывать весь реестр «для контекста». Последние пять полных задач — лишь обоснованное исключение, по одной, с сохранением read-scope и BLIND-START.
+
+После сдачи/проверки **обязательно**: сохранить полное поручение с уточнениями и фактическим результатом → сделать контрольную копию → прочитать запись по ID → обновить индекс → обновить активный план. Авторскую сдачу не называть независимым PASS. Завершённые подробности убрать из рабочей очереди только после сохранения и проверки; оставить короткую отметку с ID. Незавершённое и FOLLOWUP не терять. Историю не удалять, ID не переиспользовать.
+
+Для Blueprint: №43 — план, №43.1 — индекс, №43.2 — полные записи. Пример адресного чтения из корня проекта:
+
+```powershell
+python -B -X utf8 tools/read_task_record.py --registry "Документация/43.2_Реестр задач Blueprint LLM.md" --id BP-0001
+```
+
+При ошибке ID/границ/объёма не заменять отказ печатью всего файла. Сверить индекс и получить точную выдержку. Указатель не даёт прав на чужие персональные архивы. №05/06/001, карточки, независимые вердикты и правила публикации сохраняют свои обязанности.

## 1. Итог (DONE)

EVM переделана из полноширинной сетки больших карточек в компактную доску из четырёх колонок: **★ Избранное | API | MCP / Агенты | Локальные LLM**. Карточки в колонках идут сверху вниз.

**Компактная карточка** одна для всех типов записей. В ней:

- ручка перетаскивания;
- название;
- тип и провайдер;
- индикатор API, если он применим;
- число параметров, если оно известно;
- звёздочка.

**Полная карточка** раскрывается поверх списка и не сдвигает соседние. Внутри та же общая карточка, что и раньше: роли с подсказками, описание, статус API, «Настройки», «Проверить чат». Добавлены «✎ Изменить описание», «↑ Выше», «↓ Ниже».

| Действие | Как работает |
|---|---|
| Наведение | Открывает карточку через 120 мс. Переход на другую карточку переключает сразу. Уход закрывает через 180 мс, если курсор не перешёл в саму полную карточку |
| Клик / касание | Закрепляет карточку открытой; повторный клик закрывает |
| Клавиатура | Enter / Space открывают и ставят фокус в карточку, Escape закрывает и возвращает фокус, Alt+↑ / Alt+↓ переставляют |
| `prefers-reduced-motion` | Анимация выключается |

**Порядок** каждой колонки меняется перетаскиванием внутри колонки или кнопками «Выше» / «Ниже». Колонки независимы. Порядок хранится на сервере и переживает обновление страницы и перезапуск.

**Избранное** — ссылки на исходные записи, а не копии моделей. Звёздочка добавляет и убирает запись. Колонка сортируется отдельно и показывает актуальный статус и описание источника.

**Описание.** Дефекта сохранения нет (§4). Проблема была в обнаруживаемости. Добавлена видимая команда «✎ Изменить описание»; щелчок по полю описания открывает «Настройки → Модель» с курсором в поле.

**Выбор модели Ultra Chat** перенесён из большого блока EVM к полю ввода Ultra Chat (кнопка «‹модель› ▾»). Переносится только пользовательское предпочтение (§6). На освободившемся месте EVM — компактная информационная панель: текущая модель чата, сводка статусов API, источник ролей и подсказка по работе с доской. Сетевого мониторинга и «новостей» нет.

### 3.1. Хранение порядка и избранного

- `GET /ultra/model-cards` → `view: {state, revision, sections: {favorites, api, mcp, local}, hidden}`.
- Порядок колонки — сохранённый порядок записей, которые сервер показывает сейчас, плюс новые записи в естественном порядке реестра. Новые модели добавляются в конец, дубликатов нет.
- Записи, которых сейчас нет, остаются в файле и не показываются (`hidden`). Когда запись возвращается, она снова видна. Её избранное сохраняется, даже если пользователь правил избранное, пока записи не было (тест m20, мутант V01).
- `POST /ultra/model-cards/view` `{base_revision, section, order}`.
  - Для колонки `order` должен быть полной перестановкой показанных сейчас записей этого вида.
  - Для избранного — любые показанные сейчас записи.
  - Иначе ответ 409 `settings_revision_conflict` («список изменился»). Неверные ID, повторы, чужой вид и лишние поля — 400.
- Повреждённый файл — `state: CORRUPT`, естественный порядок, без избранного. Следующее сохранение (`base_revision: null`) откладывает его рядом (`*.corrupt-<id>`).
- Сохранение порядка не меняет `model_registry`, назначения ролей, настройки API и `connections.json`. Тест m18 проверяет это побайтно.

## 4. Найденные и исправленные дефекты

1. **«Сильные стороны модели» не редактируются — дефекта сохранения нет.** Проверено до изменений на опубликованном коде: ввод, сохранение, повторное открытие, перезагрузка страницы (`evidence/description_check.json`); перезапуск сервера покрыт тестом m13. Причина — обнаруживаемость: поле в карточке выглядело полем ввода, а «Настройки» открывались на вкладке «Подключение». Исправлено командой и щелчком по полю (E28).
2. **Перетаскивание могло начаться со звёздочки.** В браузере `dragstart` приходит на саму карточку, поэтому проверка цели ничего не защищала. Теперь решает нажатие на звёздочку (`mousedown`). E24, мутант U14.
3. **После «Выше» / «Ниже» фокус клавиатуры терялся** на устаревшей отключённой кнопке. Теперь фокус остаётся на той же команде, а на краю — на соседней. E23.
4. **Вложенные интерактивные элементы.** Компактная карточка была `role=button` со звёздочкой внутри — нарушение ARIA. Теперь в `article` две соседние кнопки, «открыть» и звёздочка. Ручка вынесена из кнопки: некоторые браузеры не перетаскивают от `<button>`. E2, мутант U22.
5. **Полная карточка выходила за нижний край окна** (390 px: низ 872 при окне 844). Положение считалось, пока панель была скрыта и её высота равнялась 0. Теперь панель сначала показывается, затем измеряется. E30, мутант U17.
6. **Полная карточка заходила под закреплённую шапку страницы** (150 %). Теперь верхняя граница — низ шапки, высота ограничена окном. E30, мутант U18.
7. **Сетка ролей 3 × 3** в карточке шириной 520 px — ширина 560 px даёт 4 × 2, как в образце.

## 6. Совместимость со Stage1 и перенос выбора модели в чат

Решение: **перенос выполнен**, BLOCKED не понадобился. Контракт Stage1 (исходная постановка §1, 5, 6) запрещает отправку сообщений, создание и удаление чатов, изменение Workspace, запись в хранилище истории и смешивание токенов. Сохранение предпочтения модели через прежний маршрут EVM ни одно из этих правил не нарушает:

- кнопка у поля ввода сохраняет **только** выбор модели через прежний `POST /ultra/connections/selection`. Токен Ultra Chat с этим запросом не уходит (E3, мутант U21);
- маршруты `/ultra/chat/*`, токен чата, чтение истории, RAW, Turn не затронуты. Отправки, создания чатов и записи в Workspace нет. Поле ввода и «Отправить» по-прежнему неактивны;
- при загрузке экран чата читает то же, что и раньше: возможность, Workspace, историю, сохранённый выбор. Список моделей (`/ultra/connections`) читается только при открытии меню выбора (E3, мутант U20). Тест Stage1 U1 («the EVM catalog is not read by the chat screen») проходит без изменений;
- значок модели в шапке чата остался. Его подсказки сменились с «откройте EVM» на «выберите у поля ввода»; тесты Stage1 U12 проходят без изменений;
- все тесты Stage1 (JS 12, HTTP 22) проходят, файлы Stage1 не менялись.

**Рассмотренные альтернативы:**

- хранить порядок в `model_settings.json` — отвергнуто: одна ревизия для описания и порядка дала бы ложные конфликты между окнами;

- выбор модели как `<select>` в композере — отвергнут: для списка пришлось бы читать каталог при загрузке чата, а это меняет поведение Stage1 при загрузке.

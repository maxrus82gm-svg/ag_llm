## 3. Как устроено

### 3.1. `Start_WebAlarm.bat` — один и постоянный

- Только ASCII (cmd читает BAT в OEM-кодировке), окончания строк CRLF, никаких абсолютных путей и номеров портов.
- `pushd "%~dp0"` — работает из ярлыка и из любой текущей папки, в том числе с сетевого пути.
- **Python:** `.venv\Scripts\python.exe` рядом с файлом. Если его нет — `py -3`, затем `python` с сообщением `[INFO] Project .venv not found …`. Если нет никакого — понятная ошибка и пауза.
- Запускает `python -B -X utf8 -m web_alarm.launcher %*`. При ненулевом коде показывает его и ждёт нажатия клавиши, чтобы сообщение не исчезло.

### 3.2. Стандартный запуск — встроен в код и не переопределяется

`web_alarm/launcher.py`:

- основное приложение `web_alarm.server`;
- штатное хранилище;
- `127.0.0.1:8765` (или машинная `WEB_ALARM_PORT`);
- folder picker и Ultra Chat включены.

Окно:

- зелёное «СТАНДАРТНЫЙ ЗАПУСК — WEB ALARM ULTRA»;
- адрес, путь хранилища (только локально в этом окне), версия интерфейса (хеш страницы);
- заголовок окна консоли «Web Alarm Ultra — СТАНДАРТНЫЙ ЗАПУСК…».

Браузер открывается сразу. Страница отдаётся **без изменений** (проверено байтами).

### 3.3. Тестовые конфигурации — тот же BAT

`web_alarm/launch_config.json` (`schema_version 1`, поставляется с `"active": "standard"`). Внутри пояснения на русском. Профили:

| Профиль | Что запускает |
|---|---|
| `isolated-empty` (`web_alarm`) | То же основное приложение на пустом временном хранилище, порт 8766 |
| `ultra-chat-demo` (`python_script`) | Демо этапа 1 на синтетических данных: `reports/…S1…/tools/demo_ultra_chat.py --port 8767` |
| `wa4o-review` (`python_script`) | Прежнее одноразовое демо операторской панели `wa4o_ui_launcher.py` |

Правила, проверяемые до запуска (иначе красный отказ):

- профиль `web_alarm` — только `storage: "temp"` и порт, отличный от стандартного;
- `python_script` — только `.py` внутри проекта, путь через «/»;
- неизвестные поля, повтор ключей, другая версия схемы, неизвестный `active` запрещены;
- профиль с именем `standard` запрещён.

В тестовом режиме:
- красное предупреждение с именем и названием профиля и подсказкой, как вернуться;
- заголовок окна «[ТЕСТ] …»;
- 5-секундный отсчёт перед браузером (или перед скриптом);
- для профиля `web_alarm` — пометка каждой страницы (рамка, плашка, `[ТЕСТ: …]` в заголовке вкладки);
- временное хранилище удаляется при остановке.

Профиль `python_script` браузер пометить не может — окно консоли прямо об этом сообщает.

**Возврат:** `"active": "standard"`. Тест `l1` нарочно краснеет, пока в поставляемой конфигурации активен тестовый профиль — чтобы тестовый режим не ушёл в публикацию незамеченным.

### 3.4. Повторный запуск и занятый порт

- **Найдено первым прогоном тестов и подтверждено пробой.** На Windows два `HTTPServer` (оба с `SO_REUSEADDR`) могут одновременно слушать один порт. Без защиты второй двойной щелчок поднял бы второй сервер на 8765, и запросы распределялись бы между ними непредсказуемо (`evidence/first_run_hang.json`).
- **Защита.**
  - Перед запуском — проверка соединением, не слушает ли кто-то порт.
  - Плюс межпроцессная блокировка запускателя на этот порт: существующий `web_alarm.store_lock.InterProcessLock`, файл блокировки во TEMP пользователя, освобождается при смерти процесса.
- **Если порт занят.**
  - Стандартный запуск переиспользует работающий сервер только при совпадении страницы и `storage_root` из `/status`: «Этот запуск уже работает…», открывается браузер.
  - Иначе — красное «Порт … занят другой программой, другой версией или другим режимом Web Alarm…», код 3.
  - Тестовый запуск и самопроверка чужой сервер никогда не переиспользуют.

### 3.5. Завершение

- Закрыть окно, Ctrl+C или Ctrl+Break: сервер закрывается, блокировка порта освобождается, временное хранилище теста удаляется, печатается «Сервер остановлен.».
- После Ctrl+C сам `cmd.exe` по своему обыкновению спрашивает «Завершить выполнение пакетного файла [Y/N]?» — это поведение Windows, данные не затрагивает.

## 4. Как пользоваться

1. **Обычная работа:** двойной щелчок по `Start_WebAlarm.bat` в папке проекта. Должно появиться зелёное «СТАНДАРТНЫЙ ЗАПУСК — WEB ALARM ULTRA», затем откроется браузер. Окно не закрывать, пока работаете.
2. **Ярлык на рабочем столе:** правый щелчок по `Start_WebAlarm.bat` → «Отправить» → «Рабочий стол (создать ярлык)». Ярлык работает из любой папки.
3. **Тестовый режим** (разработчикам и проверяющим): в `web_alarm/launch_config.json` указать `"active": "<имя профиля>"` и запустить тот же BAT. Появится красное «ВНИМАНИЕ! НЕСТАНДАРТНЫЙ ТЕСТОВЫЙ ЗАПУСК».
4. **Вернуть обычный режим:** `"active": "standard"`.
5. **Другой порт на этом компьютере:** переменная среды Windows `WEB_ALARM_PORT` (1024–65535).
6. **Самопроверка без браузера:** `Start_WebAlarm.bat --self-test <файл.json>` запускает, проверяет страницу по HTTP, останавливает и пишет результат.

## 6. MANUAL ENGINEERING REVIEW (TEST-ENG-01)

**Просмотренные ветви:**
- загрузка конфигурации (нет файла → стандартный; строгий разбор; запреты);
- запуск основного приложения: блокировка порта → проверка соединением → `create_server`, далее
  - ветка «занято» (переиспользование или отказ),
  - самопроверка,
  - обычная работа (пауза теста → браузер → `serve_forever` → остановка в `finally`);
- запуск скрипта;
- `main`;
- BAT: выбор интерпретатора, код возврата, пауза.

**Найдено и исправлено до сдачи:**

1. **Второй сервер на занятом порту** (Windows `SO_REUSEADDR`) — §3.4. Найдено зависанием первого прогона, причина доказана пробой, исправлено, тесты r4 и r9.
2. **Переиспользование сравнивало только страницу.** Сервер той же версии с другим хранилищем был бы выдан за стандартный запуск. Теперь сравнивается и `storage_root`; тест r4.
3. **Рамка тестового режима, нарисованная тенью `html`, не была видна** за фоном шапки и панелей (визуальная проверка). Заменена прозрачным для щелчков слоем поверх страницы.
4. **Временные хранилища тестовых профилей накапливались во TEMP.** Теперь удаляются при остановке; удаление возможно только внутри TEMP и никогда не касается штатного хранилища; тесты r2, r3, r6 и общая проверка каждого запуска (§5.1).
5. **Ctrl+C во время 5-секундной паузы обходил закрытие сервера.** Пауза перенесена внутрь того же `try/finally`.
6. **Тесты проверяли удаление временного хранилища только на пути самопроверки.** Обычная остановка и отказ не проверялись. Добавлена общая проверка для каждого запуска и для r6, мутанты M12–M14 (§5.2). Код запускателя не менялся.

**Рассмотренные альтернативы:**

- **Выбор режима в `%LOCALAPPDATA%`.** Отвергнут: координатор и агенты переключают режим через файлы проекта, а файл в репозитории виден в истории и проверяется тестом l1.
- **Правка `server.py` для пометки страницы.** Отвергнута: этап 1 ещё на проверке, и его байты должны остаться прежними. Пометка сделана подклассом обработчика в самом запускателе.
- **Встраивание демо этапа 1 в код запускателя.** Отвергнуто: демо запускается как тестовый скрипт.

**Пограничные случаи:**
- путь с пробелом и кириллицей;
- отсутствие `.venv`;
- нет `LOCALAPPDATA` (штатный запасной путь хранилища);
- `WEB_ALARM_PORT` неверный или совпадает с портом теста;
- сломанный JSON;
- скрипт вне проекта;
- одновременный второй запуск;
- остановка во время паузы.

**Открытые риски:** §7.

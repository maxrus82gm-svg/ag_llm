## 2. Как устроены маркеры и слоты

```
# БЛОК 1 — ТЕКУЩАЯ ЗАДАЧА
---
###### ▼ НАЧАЛО ЗАДАЧИ — строку-маркер не удалять · <служебный ключ BLOCK-1:BEGIN>
**ОЖИДАНИЕ НОВОЙ ЗАДАЧИ.**              ← сюда пользователь вставляет новую задачу
###### ▲ КОНЕЦ ЗАДАЧИ — строку-маркер не удалять · <служебный ключ BLOCK-1:END>
---
# БЛОК 1.1 — ПОСЛЕДНЯЯ СДАННАЯ ЗАДАЧА
###### ▼ НАЧАЛО КОПИИ СДАННОЙ ЗАДАЧИ — заполняет только скрипт · <ключ BLOCK-1.1:BEGIN>
**SUBMITTED / REVIEW PENDING** · TASK ID `…` · перенесено … · SHA-256 копии `…` · CHAT-ONLY AMENDMENT: … · снимок `…` · отчёт `…`
(пустая строка)
<побайтовая копия прежнего БЛОКА 1>
###### ▲ КОНЕЦ КОПИИ СДАННОЙ ЗАДАЧИ — заполняет только скрипт · <ключ BLOCK-1.1:END>
# БЛОК 2 — …
```

- Маркеры сделаны видимыми заголовками шестого уровня, а не HTML-комментариями. Они видны во всех режимах Obsidian, а Markdown-заголовок не склеивается с соседним абзацем. Заголовки БЛОКОВ, на которые ссылается №18, не менялись.
- Строку маркера скрипт узнаёт только при полном совпадении. Любая другая строка, содержащая служебный ключ, считается повреждённым маркером. Поэтому в инструкциях карточек ключ описан словами, без полного имени.
- Строка статуса 1.1 хранит SHA-256 копии. `check` в любой момент сверяет его с текстом копии и обнаруживает ручную правку 1.1.
- Снимок `reports/<TASK-ID>/handoff_task.md` скрипт пишет сам: таблица полей и копия между `<!-- TASK-SNAPSHOT:BEGIN/END -->` (LF). Для каждой принятой чат-поправки отдельный раздел со своим SHA-256.

## 8. Ограничения, NOT RUN / OPEN

- Блокировка — файл во временной папке пользователя. Агент с другой TEMP ею не исключается. От изменений, сделанных до записи, защищает повторное чтение карточки, но короткое окно между последним чтением и атомарной заменой остаётся.
- Если в Obsidian открыта карточка с несохранённой правкой, Obsidian может перезаписать результат. Перед переносом правки в Obsidian нужно сохранить.
- Маркеры видны как маленькие заголовки и попадают в оглавление (outline) Obsidian. Вид в самом Obsidian исполнитель не проверял: NOT RUN.
- Задача, текст которой содержит полное служебное имя маркера, будет отклонена как повреждённый маркер. Это осознанно безопасная сторона.
- Карточка Ultra Desktop маркеров не получила (поручение касалось Claude и Codex). Скрипт её поддерживает: имя №001 этой карточки распознаётся.
- Скрипт и тесты не входят в набор `all` Web Alarm и запускаются отдельно. На Linux/macOS не проверялись.
- Git не использовался: опубликованные хэши карточек и HEAD — `GIT_DATA_REQUIRED` у координатора.
- Карточка Claude на диске в LF, остальные карточки в CRLF. Снимок состояния Git в начале сессии показывал её изменённой, скорее всего Obsidian пересохранил файл после синхронизации. Работа велась от байтов на диске; исходный LF-хэш приведён в разделе 6 для сверки.

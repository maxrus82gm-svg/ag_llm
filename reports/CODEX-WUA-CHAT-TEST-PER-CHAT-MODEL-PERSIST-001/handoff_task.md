# CODEX-WUA-CHAT-TEST-PER-CHAT-MODEL-PERSIST-001

**TASK ID:** `CODEX-WUA-CHAT-TEST-PER-CHAT-MODEL-PERSIST-001`

**Название:** Web Alarm Ultra — исправление сохранения выбора LLM отдельно для каждого чата в TEST

**Приоритет:** P1 — подтверждённый пользователем GUI-дефект.

**Исполнитель:** Codex 007.

**Репозиторий:** `maxrus82gm-svg/ag_llm`.

**Режим:** STRICT OFFLINE. Никаких реальных вызовов GigaChat, OAuth, оплачиваемых API или изменения production-данных.

## 1. Основание

14.11.2026 владелец выполнил ручную проверку `Start_WebAlarm_Test.cmd`.

Подтверждено:

- TEST Workspace и диалоги создаются.
- Отправка по Enter работает.
- Локальный имитатор возвращает синтетический ответ.
- После F5 история сообщений сохраняется.
- Истории двух разных чатов не смешиваются.

**Обнаружен FAIL:**

1. Пользователь выбирает GigaChat Pro, Lightning или Ultra.
2. Выбранная модель отображается в интерфейсе.
3. После F5 выбор возвращается к первой модели — GigaChat 2 Pro.
4. Независимое сохранение выбора модели в отдельных чатах отсутствует.

Предварительная проверка исходника `web_alarm/ui.py` выявила, что ветка TEST функции `openPicker()` изменяет `chatTurn.model` только в памяти страницы. В отличие от STANDARD, TEST не сохраняет выбранный `model_ref` в метаданных чата и не восстанавливает его при открытии.

Причину необходимо самостоятельно подтвердить тестом, а не считать окончательной только на основании анализа.

## 2. Главная цель

**Реализовать долговременное сохранение выбора LLM отдельно для каждого TEST-диалога.**

Пользователь должен иметь возможность выбрать разные модели в разных чатах и получать тот же выбор после переключения между диалогами и F5.

Никаких реальных LLM-вызовов для этого не требуется.

## 3. Требования к реализации

### P0 — исправить подтверждённый дефект

1. Исследовать существующие TEST-маршруты, метаданные чатов, модельный каталог и механизм хранения настроек.
2. Переиспользовать существующий механизм сохранения, если он подходит для изолированного TEST.
3. Сохранять выбор по устойчивой идентичности **Workspace ID + Chat ID**, а не глобально для страницы или по названию чата.
4. При открытии чата восстанавливать его собственную модель.
5. После F5 восстанавливать модель без необходимости повторного ручного выбора.
6. Смена модели в чате A не должна менять модель чата B.
7. При отсутствии сохранённого выбора разрешается начальная модель по умолчанию.
8. При повреждённой либо отсутствующей в каталоге сохранённой модели не выдавать молчаливую подмену за восстановленный выбор. Нужны безопасный fallback или явное предупреждение согласно существующему контракту.
9. Не сохранять пользовательский выбор в общем глобальном EVM-selection вместо per-chat state.
10. Не нарушать привязку незавершённого Turn к исходной модели, idempotency key и тексту.

### P1 — гарантировать изоляцию и сохранность

- TEST и STANDARD не должны использовать конфликтующие ключи или данные.
- Новый изолированный TEST с новым временным хранилищем не должен наследовать чужие настройки.
- Не изменять RAW-историю, usage и результат уже завершённых Turn.
- Не добавлять второй Chat Core или альтернативную систему хранения без технической необходимости.
- Не расширять список разрешённых моделей STANDARD.
- Не открывать REAL factory и не ослаблять safety-gates.

Сначала создать воспроизводимый отрицательный тест существующей ошибки (**RED**), затем выполнить исправление (**GREEN**).
